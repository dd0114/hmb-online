## 1. TL;DR

1. **결론 = (b) config-only 로는 불가능.** 볼륨 밴드(팀당 슛 7.2–8.4)를 **금지 노브 없이** 밟는 조합은 네 개 찾았고, 그중 하나는 축 A(박스 편중)까지 **개선**한다(박스 안 슛 41.2% → **24.4%**). 그러나 **볼륨 ✔ + 축 A ✔ + 축 B 비악화**를 동시에 만족하는 점은 **없다**. 축 B 를 실제로 여는 조합은 예외 없이 박스 안 슛을 71~77% 로 밀어 올리고 팀 폭·스로인·패스·파울 밴드를 부순다.
2. **축 B baseline 이 축 A 보다 훨씬 나쁘다.** 팀-경기당 슛 17.27개를 **1.57명**이 나눠 갖는다(슛 HHI **0.910** — 이론 최대 1.0). ST 가 슛 95.3% · 골 95.9% · **박스 안 수신 90.2%**. 수비수 슛은 60시드에서 **0건**.
3. **⚠️ 비중형 지표만 보면 속는다 — 크기 인지 지표를 새로 만들었다.** `forwardRunReach` 를 내리면 박스ST% 가 90.2→62.1 로 "개선"되지만 **박스 안 수신 총량이 5.47 → 1.63** 이다(박스가 빈 것). **비ST 슛/팀-경기**(base 0.81) · **비ST 박스수신/팀-경기**(base 0.54)로 보면 볼륨 밴드 후보 두 개(0.52 · 0.59)는 base 보다 **나쁘다**.
4. **Phase 2-A 의 권장안(안 C = `chain.discount` 0.99)은 축 B 를 악화시킨다** — HHI 0.910→**0.972** · 슈터 수 1.57→**1.18** · ST 골 점유 95.9→**99.1%**. `discount`·`goalValue`·`threatWeight`·`turnoverWeight` 등 **EV 로 볼륨을 누르는 모든 레버**가 같은 방향이다(남는 슛이 언제나 ST 의 슛이라서).
5. **막는 것의 정체는 세 벽이다(전부 `file:line` 확정).** ⓐ `decision.ts:1319-1322` 오프더볼 폭 항이 **바깥으로만** 민다(전역 부호 반전 외 우회 없음) ⓑ `chain.ts:344` + `pitch.ts:75-78` 슛 게이트가 **골 중앙까지 유클리드 하드 컷**이라 `shootRange`(19) < 와이드 문턱(20.4) ⇒ **와이드 슛 0% 는 산수** ⓒ `chain.ts:586` 슛 EV 가 xG 단조라 **EV 로 누르면 먼 슛부터 죽는다**.
6. **최소 구조 변경 4건**(§8-2): **N1** 슛 하드 게이트 → **결정단 전용 거리 감쇠**(S, `xgAtPoint` 무수정이 핵심 — 2-A 가 그걸 건드려 기각당했다) · **N4** hold EV 의 1대1 예외(S) · **N2** *조건부* 박스 도착런(M — 전역이면 폭 37.1·스로인 1.09 로 부서진다는 것을 실측) · **N3** 와이드 레인 슛 기하 봉인 해제(S). ⑨ 옵션 B(크로스·컷백·캐리 방향)와 중복 없이 정합한다. 권장 순서 **N1 → N4 → N2 → N3**.

## 2. 현상 / hero 원문 — 왜 다시 하나

Phase 2-A 의 3안(C 템포 / B 기하 / A 결정)은 **전부 `contest.shootRange` 19→15.5/12.8 을 포함**했다. 그런데

```ts
// packages/engine/src/chain.ts:344  (생성기 shoot)
if (g.distToGoalM > c.contest.shootRange || g.xgHere < c.contest.shootXgThreshold) return;
```

는 **하드 게이트**다. 사거리를 내리면 "먼 슛을 덜 고른다"가 아니라 **"박스 밖에서 슛이라는 선택지가 아예 없어진다"**. 박스 안 슛 비중 41.6% → 89.9~100% 는 발견이 아니라 그 산수의 귀결이다. **hero 판정: 기각.**

새 제약(hero 원문, 2026-08-02):

> "**다양성이 중요해.**"
> "**박스 안에서 한 선수만 집중되지 않게도 해봐. 물론 최전방 FW 가 기회를 많이 받겠지만 지금은 그 기회비율이 너무 획일적이고 1명 중심적인 게 문제야.**"

따라서 이 리포트의 과제는 셋이다.
1. **다양성 지표를 정의하고 baseline 을 재는 것**(§4) — 이게 토대다.
2. **거리 게이트(`shootRange`)·질 게이트(`shootXgThreshold`) 없이** 팀당 슛 7.2–8.4 를 밟는 조합을 찾는 것(§5).
3. **축 B(박스 기회의 ST 독점)를 config 로 움직일 수 있는지**를 볼륨과 무관하게 따로 확인하는 것(§6).

**금지 노브(후보 제외)**: `contest.shootRange` · `contest.shootXgThreshold`(#370 라이브 붕괴 원인값, 봉인).

### 5-3. 스크리닝에서 나온 **네 개의 새 사실**

**① `chain.holdPenalty` 를 음수로 두면 거리 게이트 없이 밴드를 밟는다 — 유일한 단독 노브.**
`holdPenalty` 는 `chain.ts:670` 에서 `stay = V(here) − holdPenaltyEv` 로만 쓰인다. 음수면 "제자리에서 공을 지키는 것"에 **보너스**가 붙는다. −2.0 에서 팀당 슛 **7.50**(밴드 7.2–8.4), 팀골 1.60 · 유효 2.95 · xG/슛 0.183 · 전환 20.0 · **코너 2.90 · 스로인 8.63 · 주행 5.59 · 패스 81.3 · 폭 47.6 전부 밴드 안**이다.
- **박스 안 슛 41.6% → 44.3%**(+2.7%p — Phase 2-A 3안의 +48~58%p 와 비교하라). **거리 p50 17.5m 그대로.**
- **축 B 가 개선된다**: 슛 HHI 0.920→**0.862** · top1 95.8→92.7 · **박스ST% 95.5→82.8**.
- ✗ **파울 4.47 → 16.18**(길이보정 밴드 5.5–6.0 의 2.7배). 이게 이 노브의 대가다(§6-3).
- ✗ 1대1 비중 7.17% → 2.67%(기준의 37%) — Phase 2-A 안 B(45%)보다 나쁘고 안 C(89%)보다 훨씬 나쁘다.

**② hold 계열 3종이 축 B 의 (약한) 레버다.** `hold.minKeep` 0.25→0.6 · `hold.pressPenalty` 0.22→0.10 · `hold.keepBase` 0.98→1.0 은 전부 **슈터 수를 늘리고**(1.50→1.70~1.88) **박스ST% 를 내린다**(95.5→79.5~91.6). 볼륨 효과는 −1.5~−0.2 로 약하다. 기제는 같다 — 볼을 지키는 것이 쉬워지면 ST 아닌 선수가 공을 더 오래 들고 있고, 그 사이 박스에 다른 사람이 들어온다.

**③ ⚠️ Phase 2-A 의 권장안(안 C = `discount 0.99`)은 축 B 를 *악화*시킨다.** 슛 HHI 0.920→**0.972** · top1 95.8→**98.6** · **슈터 수 1.50→1.18** · 골top1 95.5→**99.1**. `discount` 계열은 전부 같은 방향이다(0.92→0.938 · 0.96→0.966 · 0.99→0.972). 즉 "사슬을 길게 만들어 서두르지 않게" 하면 남는 슛이 **더욱더 ST 것**이 된다. `threatWeight`↑ · `goalValue`↓ · `turnoverWeight`↑ · `spaceWeight`↑ 도 같다. **볼륨을 EV 로 누르는 모든 레버가 축 B 를 악화시킨다** — 남는 슛이 "가장 좋은 슛"이고 그건 항상 ST 의 슛이기 때문이다.

**④ ⑨ 리포트의 "config 로는 축 B 를 못 움직인다"는 결론에 반례가 있다 — `movement.attackWidthReach` 를 *음수*로.**
⑨ 는 이 노브를 **올리는**(0.10→0.25) 팔만 쟀다. **내리면**(0.10→**−0.10**) 인포제션 폭확장이 **역방향**이 되어 윙어가 안쪽으로 접힌다(윙어 base 20.4m → 약 14.7m ≈ 박스 반폭 20.16m 안).
- **박스 안 수신 5.58 → 18.68 (3.3배)** · **박스ST% 95.5 → 58.9%**
- **슛 HHI 0.920 → 0.780** · top1 95.8 → **88.0** · 골top1 95.5 → **91.4** · **슈터 수 1.50 → 2.67**
- ✗ 볼륨 폭증(23.30) · 박스 안 슛 61.4%(축 A 악화) · **팀 폭 37.1(밴드 40–50 이탈)** · 스로인 1.00(붕괴) · 패스 85.9(초과)
`variety.defenderOverlapProb` 0.4 + `overlapBaseLine` 0.8(= 미드필더/윙어까지 오버랩)도 같은 방향이다: 박스수신 12.90 · 박스ST 80.8 · HHI 0.882 · 슈터 2.05 · **팀 폭 48.0(밴드 안)**. 대신 1대1 15.49(2배)·박스슛 62.7·스로인 12.18.

> **정리**: 볼륨 레버(EV 계열)와 축 B 레버(기하 계열)가 **서로 반대 방향으로 축 A 를 민다.** EV 로 누르면 슛이 줄되 ST 독점이 강해지고, 기하로 벌리면 독점이 풀리되 슛이 폭증하고 박스로 몰린다. 남은 질문은 **둘을 겹쳐서 상쇄되는 지점이 있는가**다 → §6.

### 6-3. 읽는 법 — **두 축이 서로를 배제한다**

**① 볼륨 밴드를 밟는 조합은 넷 찾았다. `shootRange` 없이 가능하다는 것 자체는 참이다.**
`chain.holdPenalty` −2.0 단독(7.50) · `forwardRunReach .12 + attackWidthReach .05`(7.91) · `holdPenalty −3.2 + overlap`(8.52) · `holdPenalty −3.2 + attackWidthReach −0.10`(8.07). **금지 노브를 하나도 안 썼다.**

**② 축 A(박스 편중)는 오히려 개선할 수 있다 — Phase 2-A 의 결론을 뒤집는다.**
`forwardRun .12 + aw .05` 는 박스 안 슛을 **41.2% → 24.4%** 로 **내린다**(Phase 2-A 3안은 전부 89.9~100% 로 올렸다). 슛 거리 p50 은 17.5 → 17.8 로 오히려 멀어진다. 기제: 전진 런을 줄이면 아무도 박스에 못 들어가고, 남은 슛은 전부 **박스 앞 17~18m** 에서 난다.

**③ 그러나 그 조합들은 축 B 를 *실제로는* 개선하지 못한다 — 비중이 좋아진 건 분모가 무너져서다.**
`fwdRun .12 + aw .05` 의 박스ST% 62.1% 는 좋아 보이지만 **박스 안 수신 총량이 5.47 → 1.63(30%)** 이다. LW/RW 의 **절대** 박스 수신은 base 0.10/0.07 → 0.03/0.03 으로 **오히려 줄었다**(20시드 역할 덤프). 즉 "윙어가 박스에 들어오게 됐다"가 아니라 **"ST 도 안 들어가게 됐다"**. 크기 인지 지표로 보면 결론이 뒤집힌다:
- 비ST 슛/tm: base **0.81** → hp−2.0 **0.52** · fwdRun **0.59** — **둘 다 base 보다 나쁘다.**
- 비ST 박스수신/tm: base **0.54** → hp−2.0 **0.41**(나쁨) · fwdRun **0.62**(+0.08, 사실상 무신호).

**④ 축 B 를 진짜로 움직이는 두 조합은 축 A 를 부순다.**
`hp−3.2 + overlap`(비ST슛 **1.12** · 비ST박스수신 **2.35** · HHI **0.758** · 슈터 1.98 · **1대1 90% 보존**)와 `hp−3.2 + aw−0.10`(비ST박스수신 **4.38** · 박스ST **52.8%**)은 축 B 를 실제로 개선한다. 대신 **박스 안 슛이 76.6% / 71.1%** 로 폭발한다(제약 51.2%). 그리고 각각 패스 76.6(하한 이탈) · 폭 37.0 + 스로인 0.56(붕괴)를 동반한다.

**⑤ 파울은 "부작용"이 아니라 볼륨 감소의 *기제* 였다 — 그래서 못 고친다.**
`holdPenalty` 음수 계열은 전부 파울 16~17(밴드 5.5–6.0 의 3배)이다. `rules.foul.base` .135→.035 로 파울을 밴드로 되돌리면(5.58 ✅) **볼륨은 유지되는데(7.57) 축 B 가 base 아래로 무너진다**(HHI 0.870→**0.938** · ST 93.1→**96.8%** · 비ST슛 0.52→**0.24**). 즉 hp−2.0 의 그 미미한 축 B 개선은 **개방 플레이가 아니라 파울→세트피스 재시작이 만든 것**이었다. 파울을 정상화하면 개선분이 통째로 사라진다. (확정 — 60시드 대조)

**⑥ 1대1(#316)은 hold 계열 레버에 구조적으로 취약하다.**
`chain.ts:668-671` 의 hold EV = `p_keep × (V(here) − holdPenalty) + (1−p_keep) × V(턴오버)`. `holdPenalty` 가 음수면 **자유로운 선수**(`p_keep`≈0.98)의 hold EV 가 가장 크게 올라간다 — 그건 정확히 1대1 상황의 선수다. 실측 1대1 비중 6.08% → **3.33%(hp−2.0)** · 2.21%(fwdRun) · **1.65%(hp−3.2 aw−0.10)**. `config.ts:2009` 가 기록한 #353 실패 모드(*"자유로운 선수가 가장 강하게 hold"*)를 **부호만 바꿔 재도입**하는 것이다.

### 7-2. 왜 그 천장이 있는가 — `file:line` 로 확정된 세 개의 벽

**벽 1 — 오프더볼 목표의 y 항은 *바깥쪽으로만* 민다. 안쪽으로 미는 항이 없다.**
```ts
// packages/engine/src/decision.ts:1319-1322  (공격 시 오프더볼 목표)
tx += Math.round((g.x - player.baseFx.x) * runFrac);            // ← x 전용(골 방향)
const widthDir = player.baseFx.y < center ? -1 : ... ;           // ← base 오프셋의 부호
ty += widthDir * Math.round(pitch.hFx * mv.attackWidthReach * widthTendency * (0.5 + team.width));
```
`widthDir` 는 **자기 base 가 중앙에서 어느 쪽인가**의 부호다. 그래서 이 항은 언제나 **자기 자리에서 더 바깥으로** 민다. `attackWidthReach` 를 음수로 두는 것이 유일한 config 우회인데, 그건 **전원에게 전역으로** 걸린다(풀백·센터백까지 안으로 접혀 팀 폭 37.1 · 공이 터치라인에 안 가서 스로인 1.09). **"파이널서드의 윙어만 안으로 들어온다"를 표현할 수 있는 config 가 없다.** (확정)

**벽 2 — 와이드 슛은 *기하학적으로* 불가능하다(0.0% 는 행동이 아니라 산수).**
```ts
// chain.ts:344   if (g.distToGoalM > c.contest.shootRange || ...) return;
// pitch.ts:75-78 distToAttackGoal = 골 중앙까지 **유클리드** 거리
```
와이드 레인 문턱 = 피치폭 68 ÷ 5 × 1.5 = **20.4m**(횡오프셋). 유클리드 거리는 횡오프셋보다 **항상 크거나 같으므로**, 와이드에서의 슛은 `distToGoal ≥ 20.4 > shootRange 19` 를 반드시 만족한다 ⇒ **오픈플레이 와이드 슛의 확률은 정확히 0이다. 다른 어떤 노브와도 무관하다.** 38개 팔 전부에서 와이드 0.0% 였고, 유일한 예외 두 건(0.1% / 0.3%)은 세트피스 재시작이 많은 팔에서만 나왔다 — 데드볼 슛은 사슬 게이트를 타지 않으므로 정합한다(**유력**).
→ Phase 2-A 의 3안은 `shootRange` 를 15.5/12.8 로 내렸다. 그건 이 벽을 **더 두껍게** 만드는 방향이었다.

**벽 3 — 슛 EV 는 거리가 멀수록 낮으므로, EV 로 볼륨을 누르면 *먼 슛부터* 죽는다.**
```ts
// chain.ts:586  ev = goalValue×xg + turnover×(1−xg)   (xg 는 거리에 단조 감소)
```
`discount`·`goalValue`·`threatWeight`·`turnoverWeight`·`spaceWeight` 계열 전부 이 성질을 공유한다 — 그래서 §5 표에서 볼륨이 내려갈수록 박스 안 슛 비중이 **예외 없이** 올라간다. 이 성질을 **피한** 유일한 두 레버가 `holdPenalty`(모든 슛의 대안을 균일하게 올림 → 박스슛 +8.4%p 에 그침)와 `forwardRunReach`(선수를 아예 박스 밖에 둠 → **−16.8%p**)다. **즉 축 A 를 지키려면 EV 축이 아니라 기하/배치 축을 써야 한다** — 그런데 기하 축은 벽 1 때문에 전역으로만 걸린다.

### 7-3. 결론 (과제 3)

**"config 로 축 B 를 못 움직인다"는 거짓, "config 로 축 B 를 *쓸 만하게* 움직인다"도 거짓이다.**
움직이긴 한다(ST 95.3→86.8%, 비ST 박스수신 0.54→4.38). 그러나 그 유일한 경로가 **전역 폭 부호 반전**이라 팀 폭·스로인·패스 밴드를 같이 부수고, 축 A 를 76% 박스 편중으로 밀어 넣는다. **hero 의 요구를 만족하는 config 점은 없다.**

1. **`chain.discount` 상향(Phase 2-A 권장안 C)을 축 B 개선으로 오해하지 말 것.** 실측 정반대다 — HHI 0.910→**0.972** · 슈터 수 1.57→**1.18** · ST 골 점유 95.9→**99.1%**(§5-1). 2-A 가 안 C 를 고른 이유는 "1대1 보존"이었고 그건 여전히 맞지만, **선수 다양성 축에서는 최악의 선택**이다.
2. **비중형 축 B 지표만 보고 판정하지 말 것.** `forwardRunReach` 를 내리면 박스ST% 가 90.2→62.1 로 좋아 보이지만 박스 자체가 빈다(수신 5.47→1.63, LW/RW 절대치는 오히려 감소). **반드시 크기 인지 지표(비ST 슛/tm · 비ST 박스수신/tm)를 같이 볼 것.**
3. **`rules.foul.base` 로 파울을 되돌려 hold 계열을 살리려 하지 말 것.** 되돌리면 축 B 개선분이 통째로 사라진다(§6-3 ⑤, 60시드 대조).

## 10. 미해결 / hero 결정 필요 (게임 내용·재미에 관한 것만)

1. **⚠️ 최우선 — "박스 안 다양성"과 "박스 밖 슛"은 지금 트리에서 서로를 배제한다.** 축 B 를 실제로 여는 두 조합(`overlap` · `attackWidthReach` 음수)은 박스에 사람을 넣는 방식이라 **슛의 71~77% 가 박스 안**이 된다. 반대로 축 A 를 지키는 조합(`forwardRunReach` ↓)은 **박스를 비워서** 지킨다. 어느 그림을 원하나?
   - (i) **박스가 붐비는 축구** — 여러 명이 박스에 들어가고 마무리도 박스 안(현대 축구 그림). 축 A 는 포기.
   - (ii) **박스 밖에서도 때리는 축구** — 중거리 슛이 살아 있고 박스는 ST 중심. 축 B 는 포기.
   - (iii) **둘 다** — N1+N2 구조 변경이 필요하다(§8-2). 규모 S+M, 밸런스 재보정 2회.
2. **"몸싸움"의 양.** `holdPenalty` 음수 계열은 파울을 4.67 → **16.15**(경기당 32회, 45분에 84초마다 1회)로 만든다. 명백히 과하지만, 현 출하값 4.67 은 밴드(5.5–6.0) **아래**다. 45분 경기에서 파울 몇 번이 재미있나 — 이 답이 hold 계열 레버의 사용 가능 여부를 정한다.
3. **1대1 을 몇 번 보고 싶은가.** 출하 6.08%(팀-경기당 1.05회)를 계약으로 지킬 것인가, 아니면 "1대1 은 드문 하이라이트"로 재정의할 것인가. N4(§8-2)를 하면 지키면서 볼륨 레버를 얻는다.
4. **수비수 골 0건을 받아들일 것인가.** 59개 지점 전부에서 DF 슛이 0.3% 이하다(⑨ 와 동일). 이건 config 문제가 아니라 **공중볼·세트피스 루틴(⑨ 옵션 C)** 이 없어서다. "CB 가 코너에서 헤더골"을 원하면 별도 트랙이 필요하다.
5. **`bench.ts` 45분 재도출**(Phase 2-A §6-2 다음액션 5)이 아직 안 됐다 — 이 리포트의 코너·스로인·파울·주행 판정은 전부 **잠정 길이보정치**(BENCH×0.5)다. 구조 변경 웨이브 전에 계약으로 승격해야 후보 비교가 안정된다. (엔지니어링 항목이라 hero 결정 사항은 아님 — 기록만)
