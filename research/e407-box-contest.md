## 1. TL;DR

1. **Q1 = 확정(반증 아님), 단 "안 움직인다"는 비중 축에서만 참이다.** overlap 팔(`variety.defenderOverlapProb .4` + `overlapBaseLine .8`)은 n60 에서 박스 유입을 **5.17 → 12.68/팀-경기(×2.45)** 로 열지만 **박스ST 86.1→81.6% · 슛top1 95.0→93.9% · 골top1 96.3→95.3%** 로 점유는 4.5pp/1.1pp/1.0pp 밖에 안 움직인다(n20 관측 전부 재현).
2. **크기 인지 지표로 보면 절대량은 움직인다** — 비ST 박스수신 0.72 → **2.33**(×3.2), 비ST 슛 0.85 → **1.23**(×1.44), 비ST 골 0.117 → **0.175**. 그러나 **늘어난 유입 7.51 중 79%(5.90)를 ST 가 먹고**, 추가 비ST 박스수신 1건이 비ST 슛으로 바뀌는 비율은 **0.23~0.30건**뿐이다. → 다음 웨이브 본체는 **"박스로 보내기"가 아니라 "박스 안 경합(도착지 xG 경쟁·마무리 EV)"** 이 맞다.
3. **Q2 = 부분 상쇄.** 파울은 `rules.foul.base` 하나로 **밴드 복귀 확정**(A4 팔 + 0.22 → **5.72**, 밴드 5.5–6.0). 박스슛 편중은 **A3 위에서는 상쇄 불가**(64.9%, `chain.shootDistance` 는 61.9 로 찔끔 내리고 대신 다양성을 부순다). 1대1(12.62)은 **어떤 노브로도 상쇄 실패**.
4. **Q3 = 넘겨받은 팔의 라벨이 기제를 잘못 가리킨다.** `overlapBaseLine` 은 **base 슬롯 x 문턱**이라 `.8` 은 "수비수 오버랩"이 아니라 **ST 포함 전원 오버랩**이다(`config.ts:1950` 4-3-3 ST x=.78). 분해하면 **유입은 MF·W 자격 확장에서, 1대1 붕괴는 DF 확률 상향에서** 온다 — 부작용과 효능이 **다른 노브에 실려 있어 분리 가능**하다.
5. **그래서 실용 팔이 존재한다(넘겨받은 팔이 아니다).** `.4/.75`(ST 제외) + `foul.base .22`: 유입 **10.13**(×1.96) · 박스ST **71.6%**(−14.5pp) · 슛top1 92.6 · 슈터 2.13 · 1대1 7.09 · 박스슛 51.3 · 파울 5.72 · 폭 48.0 · 패스 80.3. overlap 계열은 **"열리지만 쓸 수 없다"가 아니라 "쓸 수 있는 변종이 있다"**.
6. **DF 득점 경로는 overlap 으로 안 열린다(확정).** n60 11개 팔 + DF 전용 극단 팔(확률 1.0·전진 0.95)까지 **DF 슛 0 · DF 골 0 · DF 박스수신 0.00~0.03**. 오버랩 항이 전진과 **동시에 바깥으로 벌리기** 때문에 오버랩한 수비수는 박스가 아니라 **와이드**로 간다(기제=유력).

## 5. Q1 / Q2 / Q3 결론

### Q1 — 유입만 늘리면 "누가 받고 누가 쏘는가"는 안 바뀌는가 → **확정(비중 축). 단, 문장을 정확히 써야 한다.**

- **확정된 것**: 유입 ×2.45 에서 박스ST **86.1→81.6%** · 슛top1 **95.0→93.9%** · 골top1 **96.3→95.3%** · 슛HHI 0.904→0.883. 유입을 2.5배 열어도 **점유 구조는 사실상 그대로**다(n60, `e407-diversity`, SHA 51f0b35).
- **그러나 절대량은 움직인다**(크기 인지 지표): 비ST 박스수신 0.72→**2.33**(×3.2) · 비ST 슛 0.85→**1.23** · 비ST 골 0.117→**0.175** · 슈터 수 1.68→1.98. "안 움직인다"를 **절대량까지 안 움직인다**로 읽으면 그건 오독이다.
- **왜 비중이 안 움직이나(수치로 귀속)**: ① 늘어난 유입 7.51 중 **ST 가 5.90 = 79%** 를 흡수한다. ② 비ST 로 간 나머지 1.61 도 슛이 안 된다 — **추가 비ST 박스수신 1건당 비ST 슛 0.23건**(A3 기울기) · **0.30건**(D4 기울기). ST 는 같은 기간 박스수신 4.45건에 슛 16.2건을 쏜다.
- **함의**: 병목은 **박스에 도달하는 공의 양이 아니라, 박스 안에서 그 공이 누구에게 가고 누가 쏘는가**다. 즉 다음 웨이브 본체 = **박스 안 경합**(도착지 xG 경쟁 · 마무리 EV) 이 맞다. **Q1 은 반증되지 않았다.**

### Q3 — 무엇을 하는 기제인가 → **`file:line` 확정 + 라벨 오독 정정**

**코드 사실(확정)** — `packages/engine/src/decision.ts:1342-1354`, `decideOffBall` 의 **공격 국면 분기 안**:
```ts

if (vr.defenderOverlapProb > 0 && baseProg < vr.overlapBaseLine) {          // 1345  ← 자격
  const obucket = Math.floor(state.tick / vr.overlapPeriodTicks);           // 1346  ← 40틱 버킷
```

## 7. hero 결정 필요 항목 (릴리스 리뷰 안건 — 처음 보는 사람 기준으로 씀)

### ① 박스 편중 밴드의 **부호를 먼저 확정해 달라** (다른 두 항목의 결론이 여기에 걸린다)
지시문에는 "**박스 밖 슛 35–50%**"라고 적혀 있는데, 같은 문장이 "overlap 팔 **박스슛 64.7% 는 밴드 초과**"라고 한다.
이 둘은 서로 반대다. 이 리포트는 **"박스 *안* 슛 35–50%"** 로 읽고 판정했다(선행 문서 `e407-volume-diversity.md` §5 의 "축 A 제약 51.2% 초과"와도 그렇게 해야 맞는다).
- 실측(n60): **BASE = 박스 안 39.6% / 박스 밖 60.4%**.
- (a) **박스 안 35–50%** 로 읽으면: BASE ✔ · A3 `.4/.8` ✘(64.9) · A4 계열 ≈경계(49.7~51.3) · A2 계열 ✔(47.8~48.9). → §6-2 권장 유지.
- (b) **박스 밖 35–50%** 로 읽으면: **BASE 자체가 이탈**(60.4)이고 **A3 가 정확히 밴드**(35.1). → 결론이 뒤집혀 A3 가 되레 유력 후보가 된다.
- **트레이드오프**: (a)는 "먼 슛도 봐야 축구 같다"는 축, (b)는 "찬스는 박스에서 나야 한다"는 축. **게임을 보고 결정할 문제**라 여기서 정하지 않았다.

### ② 파울(목표 5.5–6.0) — overlap 이 파울 밴드를 **원천 배제하지 않는다**
- 실측: overlap 은 파울을 5.09 → **3.07** 로 떨어뜨린다. 원인은 판정이 아니라 **분모** — 파이널서드 소유 틱이 312→267(−14%)로 줄어 태클 시도 자체가 준다(`e407-boxpop` n60).
- 그러나 `rules.foul.base` 하나로 **복원된다**(확정): A4 팔 +0.22 → **5.72 ✔** · A5 +0.24 → 5.57 ✔ · A2 +0.22 → 5.86 ✔. 다양성 부작용도 거의 없다(대조 F1: HHI 0.904→0.892).
- **선후 관계 — 선택지**:
  - **(권장) 유입 웨이브 먼저 → P-FOUL 을 마지막에 한 번**: `foul.base` 의 적정 용량이 **팔마다 다르다**(BASE 0.20 · A4 0.22 · A5 0.24 · A3 ≥0.30). 파울을 먼저 맞춰 놓으면 유입 팔을 넣을 때마다 다시 맞춰야 한다.
  - (대안) **P-FOUL 먼저**: 지금 당장 밴드가 초록이 되는 대신, 이후 유입/경합 웨이브마다 재보정 비용이 붙는다. 릴리스 일정상 "지금 밴드를 채워야" 하면 이쪽.
- ⚠️ 이 실험은 파울 **총량**만 봤다. PK/옐로/퇴장 분포는 안 쟀다(과거에 `base` 단독 상향이 PK→골 폭증을 만든 이력이 있어 P-FOUL 웨이브에서 `boxFoulMult` 와 함께 봐야 한다).

### ③ DF 골 ≥5% — **overlap 으로는 안 열린다(확정). 목표를 어떻게 할지 결정 필요**
- 실측(n60, 11개 팔 전부 + DF 전용 극단 팔): **DF 슛 0건 · DF 골 0건 · DF 박스수신 0.00~0.03/tm**. 확률을 **1.0**, 전진량을 **0.95** 까지 밀어도 그대로다.
- 기제(**유력**): 오버랩 항이 전진과 **동시에 바깥으로 벌린다**(`decision.ts:1352`) → 올라간 수비수는 **박스가 아니라 와이드**에 선다. 게다가 극단 팔은 다양성을 **악화**시킨다(슛top1 95.1→**98.0** · 슈터 1.65→**1.35** · 1대1 6.11→**15.4**).
- **선택지**:
  - (a) **목표를 다음 웨이브(박스 안 경합)로 이관** — DF 골은 "수비수를 앞으로 보내기"가 아니라 **세트피스 타깃·크로스 도착지 선택**에서 나온다. 실축도 그렇다. **권장**.
  - (b) **지금 별도 소규모 작업으로** — 오버랩 시 벌리기 항을 끄고 박스로 넣는 변종(`decision.ts:1352` 조건화). 구조 변경 S 규모이고, 이 실험 범위 밖이라 미측정.
  - (c) **목표 유예** — DF 골 0% 를 당분간 수용. 관전 체감상 "수비수가 절대 못 넣는다"가 눈에 띄는지 hero 판단 필요.
