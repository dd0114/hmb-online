## 2. 교차 인사이트 (상호 연결)

### 연결 1. "AI 인풋 → 결정론 시뮬" 은 A와 B가 맞물려 성립
B(전술→자연어 프롬프트)가 만들어내는 산출물은 결국 A(매치엔진)가 소비할 **인풋**이다. A의 결론인 "ESMS식 곱셈 계수/가중치"는 B의 자연어 프롬프트를 수치 파라미터로 환산할 착지점을 제공한다. 즉 **AI 가 자연어 프롬프트를 해석 → 팀/선수별 전술 가중치(계수) 세트로 변환 → 시드와 함께 결정론 시뮬에 주입**. 이 접합이 방식1(사전 인풋 생성)의 기술적 근거다.

### 연결 2. 결정론(A)이 라이브 개입 상태머신(D)의 전제
D의 상태머신은 "OPEN(경기전/하프타임)에서 커밋 → freeze → 엔진 주입 → LOCKED 관전"을 계약으로 둔다. 이 "freeze 후 결과 고정"은 A의 결정론(시드+인풋 로그) 없이는 성립하지 않는다. 하프타임 re-freeze 는 **전반 시드·상태에 후반 인풋을 이어 붙여 재개**하는 것. 관전 구간이 "결과가 이미 정해진 재생"이라는 점은 C(좌표 보간 재생)와도 정확히 일치한다.

### 연결 3. C의 "좌표 재생"은 A의 출력 계약을 요구
C는 "시뮬 엔진이 뱉는 시계열 좌표를 보간 재생"한다고 전제한다. 그러나 A의 ESMS식은 팀 총합→확률 이벤트라 물리 좌표를 직접 내지 않는다. → **A와 C의 접합점**: 확률 이벤트 로그(찬스/슛/인터셉트/카드)를 만들고, 렌더링용 좌표는 이벤트를 시각화하는 경량 보간 레이어로 별도 생성. PoC 에서는 텍스트 커멘터리 + 최소 도트 이동으로 충분(C §1-3, D 관전 UI).

### 연결 4. B의 팀톡/프리셋 = D의 UI 이원화로 착지
B가 정리한 "정형 지시 vs 심리(팀톡)" 구분은 D의 "무거운 개입(하프타임 자유 프롬프트) vs 가벼운 개입(상시 프리셋 칩/샤우트)" UI 분리로 그대로 구현된다. B의 8종 프리셋은 D의 "프리셋 칩(가로 스크롤/그리드)"의 콘텐츠가 된다.

### 연결 5. PvP-ready 경계는 A의 결정론에서 파생
A의 락스텝/서버권위/state hash/headless replay 원리는 D의 "커밋→freeze→엔진주입" 계약과 결합해 **PvP-ready 경계**를 정의한다. PoC(싱글)에서도 시뮬을 서버권위·결정론·입력로그 재생 가능하게 만들어 두면, Phase 2 는 네트워킹(입력 동기화)만 얹으면 된다.

## 3. PRD 로 이어질 핵심 결정 (근거 요약)

1. **AI 아키텍처 = 방식1 채택**: 프롬프트→AI가 시뮬 인풋(전술 가중치/시드) 사전 생성→결정론 시뮬. 근거 = A(결정론·시드·서버권위) + 비용/지연. 방식2(매 틱 AI 개입)는 정합성·비용·지연·PvP 부적합.
2. **AI 주입 지점 = 경기전 1회 + 하프타임 1회** (D의 두 OPEN 창과 정확히 대응). 관전 중에는 AI 호출 없음(초안만).
3. **엔진 = ESMS식 확률 이벤트 + 시드 고정** (A), **렌더 = 2D 도트/텍스트 PoC** (C), **UX = 5-상태 상태머신 + 폼팩터 분기** (D).
4. **Phase 1 = 싱글 PoC (vs AI 감독)**, PvP-ready 경계 유지. Phase 2 = 실시간 PvP(서버 시뮬 권위 + 입력 동기화).
