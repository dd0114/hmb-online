# HMB 온라인 — 라이브 개입 UX 조사/설계

> **범위**: AI 프롬프트 기반 축구 시뮬 게임 HMB 온라인의 "라이브 개입" 타이밍·UI 설계.
> **핵심 질문**: 자연어 프롬프트를 *언제*(경기전/하프타임) *어떻게*(프리셋+자유입력) 받고, 폰/데스크탑에서 각각 어떤 UI로 구현할 것인가.

## 1. HMB 라이브 개입 플로우

HMB 의 한 경기는 "개입 가능 구간"과 "관전(잠금) 구간"이 번갈아 나오는 구조다. 유저가 인풋을 넣을 수 있는 창(window)은 **경기 시작 전**과 **하프타임** 두 번뿐이며, 그 사이 전·후반은 시뮬을 지켜보며 다음 개입을 *준비*하는 구간이다.

```
 ┌─────────────────────────────────────────────────────────────────────────┐
 │  [경기전 셋업]  ── 프롬프트 입력 창 (OPEN) ───────────────────────────── │
 │  · 상대 팀 분석 리포트 제시                                              │
 │  · 선수별 AI 프롬프트 입력 (프리셋 선택 + 자유 자연어)                   │
 │  · 팀 전술 프리셋 선택 (하이프레스 / 라인로우 / 역습 …)                  │
 │  · 입력 마감 타이머(예: 90~120초) → [킥오프] 확정                        │
 └───────────────┬─────────────────────────────────────────────────────────┘
                 │ 인풋 확정(freeze) → 시뮬 엔진에 프롬프트 주입
                 ▼
 ┌─────────────────────────────────────────────────────────────────────────┐
 │  [전반 진행]  ── 프롬프트 입력 창 (LOCKED / 관전) ─────────────────────  │
 │  · 시뮬 관전 (2D/텍스트 커멘터리)                                        │
 │  · 실시간 이벤트 로그 (슛/인터셉트/카드/부상)                            │
 │  · ✎ "다음 개입 초안" 트레이 — 교체·추가 프롬프트를 *미리* 작성만 가능   │
 │    (아직 적용 X, 하프타임에 커밋)                                        │
 └───────────────┬─────────────────────────────────────────────────────────┘
                 │ 전반 종료 휘슬
                 ▼
 ┌─────────────────────────────────────────────────────────────────────────┐
 │  [하프타임]  ── 프롬프트 입력 창 (OPEN) ─────────────────────────────── │
 │  · 전반 요약(핵심 이벤트 3~5개) + 히트맵/스탯                            │
 │  · 선수 교체 UI (아웃 → 인, 최대 N명)                                    │
 │  · 팀 톡 / 추가 프롬프트 (프리셋 + 자유 입력, 초안 트레이 승격)          │
 │  · 개별 선수 지시 갱신                                                   │
 │  · 입력 마감 타이머 → [후반 시작] 확정                                   │
 └───────────────┬─────────────────────────────────────────────────────────┘
                 │ 갱신 인풋 확정(freeze) → 엔진 재주입
                 ▼
 ┌─────────────────────────────────────────────────────────────────────────┐
 │  [후반 진행]  ── 프롬프트 입력 창 (LOCKED / 관전) ─────────────────────  │
 │  · 시뮬 관전 · 이벤트 로그                                               │
 │  · (선택) 초안 트레이는 계속 작성 가능하나 이번 경기엔 커밋 창 없음      │
 └───────────────┬─────────────────────────────────────────────────────────┘
                 │ 종료 휘슬
                 ▼
 ┌─────────────────────────────────────────────────────────────────────────┐
 │  [경기 종료]  · 결과/스탯 · 프롬프트→결과 인과 리뷰 · 다음 경기 학습     │
 └─────────────────────────────────────────────────────────────────────────┘
```

**설계 원칙 (사례에서 도출):**
- **개입 창은 "명시적 커밋"으로 닫힌다.** FM 은 하프타임 팀 톡/교체를 마치고 화면을 닫을 때 인풋이 확정된다. HMB 도 타이머 만료 또는 [후반 시작] 버튼으로 freeze → 엔진 재주입.
- **관전 구간에는 "준비만" 시킨다.** 전반 동안 다음 개입을 지켜보며 미리 초안을 짜두는 흐름은 실제 FM 유저의 하프타임 준비 습관과 일치한다. 잠금 구간에서 초안 트레이를 열어두면, 하프타임 창이 짧아도 승격(commit)만 하면 된다.
- **경기전과 하프타임은 같은 입력 컴포넌트를 재사용**하되, 하프타임에는 "전반 요약 + 교체"가 추가된 확장 폼으로 제시.

## 2. 기존 게임 라이브 개입 사례

> 목표: 축구 매니저/시뮬 게임이 "경기 중" 유저 개입을 어떻게 타이밍·UI로 풀었는지 3+ 사례 벤치마크.

### 사례 A — Football Manager: 터치라인 지시(Touchline Shouts)
경기 진행 중 언제든 감독이 벤치에서 외치는 동기부여 지시. **전술 자체를 바꾸지 않고** 선수 멘탈/사기만 상황에 맞게 조정한다("Encourage", "Demand More", "Praise", "Berate" 등). 팀 전체 또는 특정 선수/유닛 단위로 발동 가능하며, 코치에게 위임할 수도 있다. FM26 에서 한 번 빠졌다가 Update 4(26.1.0)로 다시 복원될 만큼 "실시간 개입"의 핵심 UX 로 평가된다.
- https://www.passion4fm.com/how-to-use-touchline-shouts-in-football-manager/
- https://www.thesixthaxis.com/2025/12/09/football-manager-26-update-26-1-0-brings-back-shouts/
- https://www.passion4fm.com/fm26-update-4-changelist-the-return-of-shouts/

**HMB 시사점**: "전술 변경(무거운 개입)"과 "동기부여 한 마디(가벼운 개입)"를 UI 레벨에서 분리. HMB 의 하프타임 자유 프롬프트가 전술 변경이라면, 관전 중 가벼운 "샤우트형 프리셋 태그"를 별도로 둘 수 있다.

### 사례 B — Football Manager: 하프타임 팀 톡(Team Talk) & 튜널/전술 화면 교체
FM 은 경기 전·하프타임·경기 후 세 시점에 팀 톡을 준다. 하프타임 팀 톡은 팀 전체 또는 개별 선수 대상으로 톤(격려/비판/침착 등)을 골라 사기를 조정한다. 하프타임에는 같은 화면 흐름에서 **교체(substitution)**도 처리되는데, FM26 은 "하프타임에 전술 화면에서 교체가 적용 안 되던 버그"를 여러 차례 핫픽스할 만큼 *"하프타임 = 팀 톡 + 교체 + 전술 조정이 한 창에 몰리는 고밀도 순간"*이다. FM26 UI 개편은 이 순간을 'Tile & Card' 시스템으로 재구성했다.
- https://www.footballmanagerblog.org/2023/05/mastering-team-talks-in-football-manager.html
- https://www.footballmanager.com/fm26/features/fm26s-reimagined-user-interface
- https://www.footballmanagerblog.org/2025/10/fm26-bug-fixes-hotfix-patch-notes.html

**HMB 시사점**: 하프타임 창은 **정보(전반 요약) → 결정(교체) → 지시(프롬프트)** 순서로 시선을 유도해야 인지부하가 낮다. 교체와 프롬프트가 한 창에 섞이면 실수가 잦으므로(FM 버그 이력) 탭/스텝으로 분리.

### 사례 C — EA Sports FC 25: FC IQ / Smart Tactics (실시간 D-패드 게임플랜 전환)
경기 도중 D-패드로 커스텀 전술·게임플랜(공격/기본/수비 등 5종)을 **즉석 전환**한다. D-패드 위로 "Quick Tactics"(get in box, deep press, offside trap 등)를 원터치로 지시. 매치 흐름에 맞춰 시스템이 전술을 *제안*하는 "Smart Tactics"도 도입 — 실시간 개입을 "프리셋 원터치 + AI 제안"으로 접근성 있게 만든 사례.
- https://www.ea.com/games/ea-sports-fc/fc-25/news/pitch-notes-fc-25-fc-iq-deep-dive
- https://fifauteam.com/fc-25-quick-tactics/

**HMB 시사점**: 관전(잠금) 중에도 "원터치 프리셋 태그"를 초안에 쌓아두는 UX 는 FC 의 D-패드 게임플랜 전환과 개념이 같다. 자유 자연어는 하프타임에, 원터치 프리셋은 상시.

### 사례 D — AgentPitch: LLM 이 전술 코드를 쓰는 축구 시뮬 (프롬프트 구조 참고)
LLM 이 매 라운드 전술 `decide()` 함수를 생성하고, **경기 종료 후** "지난 전략 + 무슨 일이 있었는지 → 개선하라"는 진화 프롬프트로 자동 개선하는 폐루프. 프롬프트는 필드 지오메트리·선수 속성·액션 스페이스(Move/Pass/Shoot/Tackle/Hold)·포메이션 규칙 등 15개 섹션으로 구조화된다. OpenAI/Anthropic/Gemini/DeepSeek/Ollama 지원.
- https://taogang.medium.com/agentpitch-when-the-llm-writes-the-tactics-1bf07ace1b2a
- https://blogarchive.statsbomb.com/uploads/2023/10/TacticalGPT-Uncovering-the-Potential-of-LLMs-for-Predicting-Tactical-Decisions-in-Professional-Football.pdf

**HMB 시사점**: HMB 는 AgentPitch 의 "라운드 종료 후 개선"을 **하프타임 개선**으로 앞당긴 형태다. 즉 하프타임 프롬프트 입력 시 "전반에 무슨 일이 있었는지" 요약을 함께 보여주면, 유저의 자연어 수정이 훨씬 근거 있게 이뤄진다(AgentPitch 의 evolution prompt 를 사람이 대신 쓰는 셈).

## 3. 폰 / 데스크탑 입력 UI 초안

같은 상태머신(§4)을 두 폼팩터에 공통 적용하되, **입력 창(OPEN 상태)의 레이아웃**만 폼팩터별로 다르게 구성한다. 핵심 컴포넌트는 세 가지: ① 정보 패널(상대분석/전반요약) ② 교체 보드 ③ 프롬프트 컴포저(프리셋 칩 + 자유 입력 + 타이머).

### 3-1. 폰(모바일) 모드 — "세로 스텝 위저드"
좁은 세로 화면이므로 한 창에 다 담지 않고 **스텝(단계)으로 분할**한다. 하프타임을 예로:

```
┌───────────── 폰 (하프타임) ─────────────┐
│  ⏱ 0:48   HALF-TIME  [1/3 요약]         │  ← 상단 고정: 타이머 + 스텝 인디케이터
│─────────────────────────────────────────│
│  스텝1 요약: 점유율 58% · 유효슛 2       │
│   핵심: 43' 실점(측면 침투)              │
│           [ 다음 → ]                     │
│                                         │
│  스텝2 교체: [OUT ▾][IN ▾]  (남은 3)    │  ← 드롭다운/드래그, 큰 탭 타깃
│  스텝3 프롬프트:                         │
│   프리셋 칩(가로 스크롤):               │
│    [하이프레스][측면봉쇄][시간끌기]…    │  ← 원터치 칩 = FC 퀵택틱 차용
│   ┌─ 선수별 자유 입력 ───────────────┐  │
│   │ 7번 손흥민: "왼쪽으로 넓게…"     │  │  ← 탭하면 전체화면 키보드 + 음성입력🎤
│   └──────────────────────────────────┘  │
│        [ 후반 시작 ▶ (확정) ]            │  ← 하단 고정 CTA
└─────────────────────────────────────────┘
```
- **원터치 우선**: 좁은 화면·짧은 타이머 → 프리셋 칩으로 대부분 처리, 자유 입력은 "필요한 선수만" 펼침.
- **관전 중(LOCKED)**: 화면 하단에 접힌 "✎ 초안" 시트(bottom sheet). 위로 스와이프하면 다음 개입 초안을 미리 작성, 하프타임에 그대로 승격.
- **음성 입력** 지원: 모바일에서 긴 자연어 프롬프트 타이핑은 부담 → STT 로 구술 → 텍스트 편집.
- 타이머는 상단 고정, 확정 CTA 는 하단 고정(엄지 도달 범위).

### 3-2. 데스크탑 모드 — "3분할 대시보드"
넓은 가로 화면 → 스텝을 나누지 않고 **한 화면에 정보/교체/프롬프트를 동시 노출**(FM26 Tile & Card 처럼).

```
┌──────────────────────────── 데스크탑 (하프타임) ───────────── ⏱ 1:30 ──┐
│  ┌ 좌: 전반 요약/히트맵 ┐ ┌ 중: 교체 보드 ────┐ ┌ 우: 프롬프트 컴포저 ┐ │
│  │ 점유 58% · xG 0.9    │ │ 라인업(피치뷰)    │ │ 프리셋 칩 그리드    │ │
│  │ 이벤트 타임라인:      │ │ 드래그로 선수↔벤치│ │ [하이프레스][역습]…│ │
│  │  12' 슛              │ │ OUT: 4번          │ │ ───────────────    │ │
│  │  43' 실점 ▶클립      │ │ IN : 15번         │ │ 선수별 자유 입력    │ │
│  │  히트맵(측면 과부하) │ │                   │ │ 7 손흥민: [       ]│ │
│  └──────────────────────┘ └───────────────────┘ │ 9 케인 : [       ]│ │
│                                                  │ 팀 톡: [        ] │ │
│                                                  └────────────────────┘ │
│                                   [ 후반 시작 ▶ 확정 (Enter) ]           │
└──────────────────────────────────────────────────────────────────────────┘
```
- **동시 참조**: 좌측 전반 요약을 보며 우측에서 바로 자연어 프롬프트 수정 → AgentPitch 의 "무슨 일이 있었는지 보고 전략 개선" 흐름을 사람이 수행.
- **키보드 지향**: 각 선수 입력 필드 간 Tab 이동, Enter 로 확정, 프리셋은 단축키. 데스크탑은 긴 자연어 프롬프트 타이핑에 유리하므로 자유 입력 비중을 폰보다 높게.
- **관전 중(LOCKED)**: 우측 프롬프트 패널이 "초안 모드"로 상시 열림(비활성 회색). 커밋 버튼만 하프타임에 활성화.
- 드래그&드롭 교체 보드 = FM 튜널/전술 화면의 데스크탑 상호작용 차용.

### 공통 규칙
| 항목 | 폰(모바일) | 데스크탑 |
|------|-----------|----------|
| 레이아웃 | 세로 스텝 위저드(3스텝) | 3분할 동시 노출 |
| 자유 입력 | 음성/원터치 칩 우선, 선택적 펼침 | 키보드 타이핑 + 칩 병행 |
| 교체 | 드롭다운/탭 | 드래그&드롭 피치뷰 |
| 확정 | 하단 고정 CTA | Enter / 하단 CTA |
| 관전 중 초안 | 하단 시트(스와이프) | 우측 패널 상시(비활성) |

## 4. 프롬프트 입력 타이밍 상태머신

경기 라이프사이클을 상태로 모델링. **프롬프트 입력 가능 여부는 상태에 종속**되며, 관전(진행) 상태에서는 "초안 작성"만 허용하고 실제 커밋은 개입 창(OPEN)에서만 일어난다.

| 상태 | 유저가 할 수 있는 것 | 프롬프트 입력 가능? | 전이 조건 |
|------|---------------------|---------------------|-----------|
| **경기전셋업** (PreMatchSetup) | 상대 분석 확인, 선수별 프롬프트 + 팀 프리셋 입력, 초기 라인업 확정 | ✅ 가능 (커밋 창 OPEN) | 입력 타이머 만료 또는 [킥오프] 클릭 → 인풋 freeze |
| **전반진행** (FirstHalf) | 관전, 이벤트 로그 확인, 다음 개입 *초안* 작성 | ⚠️ 초안만 (커밋 LOCKED) | 전반 종료 휘슬 |
| **하프타임** (HalfTime) | 전반 요약 확인, 선수 교체, 추가/수정 프롬프트 + 팀 톡, 초안 승격 | ✅ 가능 (커밋 창 OPEN) | 입력 타이머 만료 또는 [후반 시작] 클릭 → 인풋 re-freeze |
| **후반진행** (SecondHalf) | 관전, 이벤트 로그 확인, (초안 작성 가능하나 이번 경기 커밋 창 없음) | ⚠️ 초안만 (커밋 LOCKED) | 종료 휘슬 |
| **종료** (FullTime) | 결과/스탯 리뷰, 프롬프트→결과 인과 분석, 다음 경기 학습 저장 | ❌ 불가 | [다음 경기] → 새 라이프사이클 |

**상태 전이 다이어그램:**
```
PreMatchSetup ──(freeze)──▶ FirstHalf ──(휘슬)──▶ HalfTime
                                                     │
                                                (re-freeze)
                                                     ▼
   FullTime ◀──(휘슬)── SecondHalf ◀───────────────┘
```

**엔진 계약(contract):**
- OPEN 상태(경기전/하프타임)에서 커밋 시 → 프롬프트 페이로드(선수별 자연어 + 프리셋 태그 + 교체)를 시뮬 엔진에 주입, 이후 상태로 전이하며 입력 lock.
- LOCKED 상태(전·후반)의 초안은 로컬 버퍼에만 저장, 다음 OPEN 창에서만 커밋 가능.
- 타이머 만료와 명시적 확정 버튼은 **동등한 전이 트리거** — 둘 중 먼저 발생하는 것으로 freeze.

## 참고: HMB 적용 우선순위 (요약)
1. **하프타임 = 고밀도 순간** → 정보→교체→프롬프트 스텝 분리로 인지부하·오조작 방지(FM 하프타임 버그 이력 교훈).
2. **관전 중 초안 트레이** → 짧은 하프타임 창의 압박 완화(실제 FM 유저 준비 습관 반영).
3. **프리셋 칩(상시) + 자유 자연어(개입 창)** 이원화 → FC IQ 퀵택틱 + FM 팀 톡의 하이브리드.
4. **하프타임에 전반 요약 동반 제시** → AgentPitch evolution prompt 를 사람이 수행하도록 지원.
