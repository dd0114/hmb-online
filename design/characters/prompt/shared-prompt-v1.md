# 캐릭터 아트 공용 프롬프트 — v1 (외부 이미지 AI용, 2026-07-27)

> **무엇** — 카드 디자인·캐릭터 원화를 별도 이미지 AI 에서 뽑을 때, 어디서든 세션 시작에
> **레퍼런스 이미지와 함께 붙여넣는 공용 양식**. 세션별 테마(국가·시대·신화·종족 등)는
> **다음 메시지로 따로 전달**하는 구조를 그대로 유지한다.
>
> **초안 대비 무엇이 바뀌었나** = 부록 A. **왜 그 숫자인가(실측 근거)** = 부록 B.
> 이 문서는 **받는 쪽(`design/characters/pipeline/`) 실측**에 맞춰 초안 v0 을 교정한 결과다.
>
> 한 줄 요약: **아트만 그린다. 카드 프레임·이름·희귀도·포지션 뱃지·팀 링·선택 링·공 소유
> 마커는 전부 우리가(파이프라인/게임 런타임이) 그린다. 배경은 완전 투명.**

---

## 사용법

1. 레퍼런스 이미지 첨부 + 아래 `✂` 구간을 그대로 붙여넣는다.
2. 다음 메시지로 **이번 세션 테마 + 캐릭터 목록**을 준다.
3. 산출물을 `design/characters/incoming/` 에 드롭 → `node design/characters/pipeline/ingest.mjs`
   → `sheet.mjs` 로 대조 시트 → hero 게이트(#104).

첨부한 레퍼런스 이미지는 **시각 스타일(픽셀 밀도·색감·캐릭터 톤)만** 참고합니다.
레퍼런스에 보이는 **카드 테두리·이름표·별·설명판·배경 패널·원형 토큰은 재현하지 마세요.**
그것들은 우리 게임 엔진이 따로 합성합니다. 당신이 만드는 것은 **캐릭터 아트 그 자체**뿐입니다.

이번 세션의 테마와 캐릭터 목록은 **다음 메시지로 전달**합니다. 지금은 아래 규격만 숙지하세요.

# 0. 절대 규칙 (하나라도 어기면 파이프라인이 산출물을 만들 수 없습니다)

1. **배경은 완전 투명(알파 0) PNG.** 배경을 그리지 마세요.
   투명 출력이 불가능한 도구라면 **순수 마젠타 `#FF00FF` 단색** 배경 + **안티앨리어싱 없는
   하드 엣지**로 출력하세요. 마젠타는 캐릭터 어디에도 쓰면 안 됩니다.
   (반투명 그라디언트 배경·어두운 패널 배경은 자동 제거가 불가능합니다.)
2. **텍스트를 굽지 마세요.** 이름·이명·희귀도·별·포지션 약어·능력치·설명·워터마크·서명 전부 금지.
   모든 글자는 게임 UI 가 실제 폰트로 렌더합니다.
3. **프레임을 굽지 마세요.** 카드 테두리·금테·코너 세공·밴드·배경 패널 금지.
4. **UI 요소를 굽지 마세요.** 원형 토큰, 팀 컬러 링, 선택 링, 공 소유 마커, 등번호 뱃지,
   체력/상태 바 — 전부 게임 런타임이 매 프레임 그립니다. 아트에 있으면 **이중으로 겹칩니다.**
5. **바닥 그림자·외곽 글로우·오라·파티클·마법진 금지.** 실루엣 추출을 오염시킵니다.
6. **캐릭터 1명당 이미지 2장**(아래 §1). 여러 캐릭터를 한 장에 모은 시트는 기본 산출물이
   아닙니다(불가피할 때만 §7 의 엄격 규격).

# 1. 산출물 — 캐릭터 1명당 PNG 2장 + 메타 1개

| 파일 | 크기 | 내용 |
|---|---|---|
| `<charId>__portrait.png` | **정사각, 512×512 이상** (정확히 1:1) | 얼굴/가슴 위 |
| `<charId>__full.png` | **세로 1:2, 512×1024 이상** (허용 1:1.6~1:2.4) | 전신 액션 |

- `charId` = **소문자 ASCII kebab-case** (`ragna`, `penguin-king`). 대문자·공백·한글 금지.
- 구분자는 **언더스코어 2개(`__`)**.
- 같은 charId 의 두 장은 **같은 캐릭터·같은 의상·같은 색**이어야 합니다(둘을 대조해 주는 로직은 없습니다).
- 파일로 저장이 안 되는 환경이면, 이미지마다 어떤 charId 의 어떤 variant 인지 **명시**하세요.

두 장이 서로 다른 사다리로 내려갑니다(같은 이미지의 크롭이 아닙니다):
- `__portrait` → 얼굴 아바타 **64 / 32 / 16px** (경기 화면 선수 토큰)
- `__full` → 전신 스프라이트 **64 / 32 / 16 / 8px** + **카드 일러스트**

# 2. 메타 (기계가독 — 이미지와 함께 텍스트로 출력)

모든 캐릭터를 만든 뒤, 마지막에 **JSON 배열 하나**를 코드블록으로 출력하세요.
순서 = 캐릭터를 만든 순서. 누락 필드가 있으면 자동 폴백이 걸리고 색이 테마와 어긋납니다.

```json
[
  {
    "id": "ragna",
    "name": "라그나",
    "title": "불꽃의 스트라이커",
    "position": "FW",
    "stars": 5,
    "signature": "#f7a051",
    "frame": "#c82813",
    "desc": "차원을 가르는 강슛, 필드 전체에 볼을 지핀다."
  }
]
```

- `position` ∈ `FW` | `MF` | `DF` | `GK` (반드시 이 4개 중 하나, 대문자)
- `stars` = 1~6 정수
- `signature` = 캐릭터 대표색 1개(hex). **아트에서 실제로 눈에 띄는 색**을 고르세요 —
  카드 프레임·이펙트가 이 색으로 구워집니다. 미지정 시 "면적이 가장 넓은 채도색"이
  자동 선택되는데, 실측상 12종 중 다수가 테마색과 어긋났습니다(빙하 캐릭터 → 빨간 망토색).
- `frame` = 프레임 금속색(hex). 생략하면 `signature` 를 어둡게 깎아 씁니다.
- `desc` = 한 문장. 카드 하단에 게임 UI 가 렌더합니다(아트에 굽지 마세요).

# 3. 구도

## `__portrait` (정사각)
- **정면**, 시선 정면 또는 아주 약한 3/4. 목·머리 기울기 최소, 좌우 대칭에 가깝게.
- 크롭 = **머리 장식 맨 위 ~ 가슴 위**. 어깨는 살짝만.
- **얼굴+머리가 프레임의 55~70%**, 사방 5~10% 여백(장식이 잘리면 안 됩니다).
- **머리 장식(뿔·왕관·후광·귀·모자)이 캐릭터 식별자**입니다 — 절대 잘리지 않게.
- 모든 캐릭터의 **얼굴 크기·눈 높이·머리 중심**을 통일하세요(한 세트로 보여야 합니다).
- 축구공·전신·긴 무기·큰 날개 전체는 portrait 에 넣지 마세요.

## `__full` (세로 1:2)
- **정면 액션 포즈 1개** (달리기 / 슛 준비 / 드리블 / 태클 / 세이브).
- 머리끝~발끝 전부 포함, 캐릭터가 세로의 **85~90%**.
- **축구공 1개를 발 근처에**. 공이 캐릭터를 가리지 않게.
- 팔다리가 몸통에 붙어 뭉개지지 않게 — **8px 까지 줄여도 형태가 남아야** 합니다.
- 캐릭터마다 카메라 거리·비율을 바꾸지 마세요. 거대 종족도 다른 캐릭터와 **비슷한 시각적 부피**로,
  작은 종족도 지나치게 작게 만들지 마세요.

# 4. 스타일 — 픽셀 아트 직접 생성

- **고해상도 픽셀 아트**. 픽셀 모서리 선명, **안티앨리어싱 없음**, 부드러운 디지털 페인팅 금지.
- 업스케일이 필요하면 **최근접 보간(nearest-neighbor) 정수 배율**만. 흐린 확대는 규격 위반입니다.
- 미세 노이즈 픽셀 남발 금지. 면 단위 명암 + 굵은 실루엣.
- **제한 팔레트**: portrait 24색 이내, full 28색 이내 권장. 색 축소는 우리가 단계별로 합니다
  (아바타 64→24색 / 32→14색 / 16→8색, 스프라이트 64→28 / 32→18 / 16→10 / 8→5색) —
  당신이 미리 6~10색으로 줄이지 마세요. **원본은 풍부하게, 대신 실루엣과 대비를 확보**하세요.

## 저해상도 생존 규칙 (가장 자주 실패하는 지점)

실측: 12캐릭터를 16px 아바타로 내렸을 때 **명확히 읽힌 것은 4종뿐**이었고,
실패한 4종은 전부 **어두운 머리 + 어두운 복장** 조합이었습니다. 가른 변수는 해상도가 아니라
**실루엣의 굵기와 명도 대비**입니다.

- 머리 실루엣을 **굵고 독특하게**(갈기·뿔·왕관·후드 등). 얇고 산발적인 머리카락은 사라집니다.
- **머리와 몸통의 명도를 다르게**. 어두운 머리 + 어두운 옷 = 16px 에서 덩어리로 뭉개집니다.
- 얼굴은 배경과, 배경은 의상과 **명도 대비**를 확보하세요.
- 판정 기준: **눈을 가늘게 뜨고 봐도 누구인지 구별되는가.**

# 5. 축구 선수로 읽힐 것

모든 캐릭터는 판타지/역사 인물이기 **이전에 축구 선수**여야 합니다.

- 필수: 축구 유니폼(또는 유니폼으로 재해석한 의상), 축구화, 축구공(full 만), 축구 동작, 포지션 연상 자세.
- 판타지·신화·역사·실존 인물 모티프는 **머리 실루엣 / 표정 / 피부색 / 수염 / 헤어 / 종족 특징 /
  유니폼 문양 / 색상 / 절제된 장식**으로 표현합니다.
- 무기·갑옷이 축구공과 축구 동작보다 커 보이면 안 됩니다. **전사가 아니라 선수**로 읽혀야 합니다.
- **실존 선수의 이름·얼굴을 쓰지 마세요.**

# 6. 색상 제약 (게임 시스템과 충돌하는 색)

우리 런타임이 **아트 위에 겹쳐 그리는 색**들이 있습니다. 이 색을 캐릭터 주조색으로 쓰면
경기 화면에서 팀·상태 표시와 섞여 판독이 무너집니다.

| 예약된 용도 | 색 | 아트에서 |
|---|---|---|
| 팀 링 blue (아군) | `#3b82f6` / `#3da9f1` 계열 | **주조색 금지** (보조·악센트는 가능) |
| 팀 링 red (적팀) | `#ef4444` / `#ef4f44` 계열 | **주조색 금지** |
| 공 소유 하이라이트 | `#fde047` (형광 노랑) | 넓은 면적 금지 |
| 포지션 뱃지 FW/MF/DF/GK | `#f17869` / `#57b775` / `#0b90d8` / `#fce148` | **포지션을 색으로 표시하지 마세요** — 뱃지는 우리가 그립니다 |

또 하나: 일부 캐릭터는 **색상(hue) 회전으로 변형본**을 만듭니다. 이때 **피부톤 대역
(H 18~48°, S 0.18~0.8, L 0.35~0.92)은 보호되어 회전하지 않습니다.**
→ `signature` 와 유니폼 주조색을 **이 대역 밖**(예: 청록·보라·청색·자홍)으로 잡으면
변형본이 확실히 달라 보입니다. 주황·황토색 계열을 주조색으로 쓰면 변형해도 거의 안 변합니다.

# 7. (예외) 한 장 시트로만 출력 가능한 경우

도구가 파일 여러 장을 못 내면 시트 1장으로 받되, **자동 슬라이스가 가능한 형태**여야 합니다.
"빈 공간 없이 균형 있게 배치" 같은 유연한 레이아웃은 **슬라이스가 불가능**합니다(사람이 매번
좌표를 손으로 재야 합니다). 다음을 모두 지키세요.

- **정확히 균일한 격자**: 모든 셀 크기 동일, 모든 거터 동일, 바깥 마진 동일. 눈대중 정렬 금지.
- **셀 크기·거터·마진·열/행 수를 픽셀 정수로 텍스트에 명시**하세요.
  예: `cell 512×1024, gutter 32, margin 32, cols 6, rows 2, order = row-major`.
- 셀 개수 = 캐릭터 수. **빈 셀이 남더라도 격자를 무너뜨리지 마세요**(빈 셀은 비워 두면 됩니다).
- 배경은 **순수 마젠타 `#FF00FF` 단색**, 안티앨리어싱 없음. 격자선·라벨·제목·범례 금지.
- 캐릭터 순서 = §2 JSON 배열 순서.
- portrait 시트와 full 시트는 **분리**하세요(종횡비가 다릅니다).

# 8. 출력 전 체크리스트

- [ ] 배경이 완전 투명(또는 순수 `#FF00FF` + 하드 엣지)인가
- [ ] 이름·희귀도·포지션·설명 **글자가 하나도 없는가**
- [ ] 카드 테두리·프레임·배경 패널이 없는가
- [ ] 원형 토큰·팀 링·선택 링·공 마커·등번호가 없는가
- [ ] 바닥 그림자·글로우·오라·파티클이 없는가
- [ ] portrait 정사각 512+ / full 세로 1:2 512×1024+ 인가
- [ ] 머리 장식이 잘리지 않았는가, 사방 여백 5~10% 있는가
- [ ] full 에 축구공 1개, 정면 액션 포즈인가
- [ ] 모든 캐릭터의 얼굴 크기·눈 높이·카메라 거리가 통일됐는가
- [ ] 어두운 머리 + 어두운 복장 조합을 피했는가(16px 생존)
- [ ] 파일명이 `<charId>__portrait.png` / `<charId>__full.png`, 소문자 kebab-case 인가
- [ ] §2 JSON 배열을 이미지 순서대로 출력했는가

**이 작업의 최우선 목표 두 가지**
1. 모든 캐릭터가 **동일한 규격·카메라·얼굴 크기**로 한 세트처럼 보일 것
2. 각 캐릭터가 **64px 얼굴 아바타까지 줄여도 누구인지 구별**될 것

이제 다음 메시지의 테마와 캐릭터 조건을 이 규격대로 제작해 주세요.

# 부록 A. 초안 v0 대비 수정 diff 요약

의심 지점 6개는 **전부 실측으로 확인됐고 6건 모두 수정**했다. 추가로 초안에 없던
치명적 누락 1건(배경 투명)과 정정 2건을 더했다.

## A-1. 확인된 6건

### ① 카드 안에 이름·희귀도·포지션 텍스트를 굽게 함 → **삭제. 아트는 텍스트리스·프레임리스**
- 초안: "카드 내부 구조 — 상단 포지션 표시 / 하단 이름·이명·희귀도 / 가장 아래 설명 영역".
- 실측: `pipeline/lib/card.mjs` 가 **226×425 카드를 우리가 합성**한다(프레임 인셋 10px, 아트
  영역 `artBottom=331`, 네임플레이트 `nameY=330`, 별 밴드 `starsY=362`, 설명판 `descY=386`,
  포지션 뱃지는 내장 3×5 비트맵 폰트로 `POS_COLOR` 로 그린다).
  `card.mjs` 헤더 주석: *"한글 텍스트(이름/설명)는 파이프라인이 그리지 않는다 — 게임 UI(React)가
  실제 폰트로 오버레이한다."*
- `apps/web/src/common/full-art.ts` 는 카드를 **3층 합성**으로 그린다:
  `[층1] frame-<GRADE>.png` → `[층2] card-<char>.png 의 아트 영역만` → `[층3] React 텍스트 오버레이`.
- → 아트에 텍스트/프레임을 구우면 **글자가 두 번, 프레임이 두 번** 나온다. 초안 §3 "카드 내부
  구조" 전체와 §2 "상단 제목·포지션 범례"를 삭제하고 §0-2·§0-3 금지 규칙으로 대체했다.

### ② 원형 토큰·팀 링·상태 표시를 아트 AI 에게 시킴 → **삭제(런타임 소관)**
- 초안 §8·§10 전체가 24×24 원형 토큰, 팀 링 2px, 선택 시 금/흰 링, 공 소유 마커까지 지정.
- 실측: `packages/viewer-core/src/viewer.impl.mjs:218-233` 이 매 프레임 직접 그린다 —
  팀 디스크(`rgba(37,99,235,.55)` / `rgba(220,38,38,.55)`) → **아틀라스 타일을 그 위에 사각으로
  drawImage** → 팀 링(`#3b82f6`/`#ef4444`) → 공 소유 링(`#fde047`, lineWidth 3.2) → 등번호 뱃지.
- 발행 아틀라스(`dist/characters/avatars-*.png`)의 타일은 **링이 없는 상태**로 만들어진다
  (`make-characters.mjs` 는 `avatar-<size>.png` 를 쓰고, 링이 구워진 `avatar-<size>-blue.png` 는
  `out/` 프리뷰 전용).
- 결정적으로 **타일은 원형 클립 없이 정사각으로 그려진다** → 아트에 어두운 원형 배경을 구우면
  경기 화면에서 **팀 디스크 위에 사각 덩어리**로 얹힌다.
- → 토큰 규격 전체를 산출물 요구에서 제거. 초안이 원한 "확인용 프리뷰"는 필요하면 별도로
  받을 수 있으나 **입고 대상이 아니다**. §0-4 로 금지 명시.

### ③ "빈 공간 없이 균형 있게 정렬" 유연 그리드 → **고정 셀·정수 그리드·정수 배율**
- 초안: "카드 수가 달라지더라도 빈 공간 없이 균형 있게 정렬합니다."
- 실측: 운영 파이프라인에 **시트 슬라이서가 없다**. 유일한 슬라이서 `pilot-crop.mjs` 는
  *"파일럿 전용"* 이고, 레퍼 시트의 격자가 균일하지 않아
  *"세로 거터를 밝기 프로파일로 실측 → 격자가 균일하지 않아 공식 대신 경계 테이블을 쓴다"*
  며 12개 열 경계를 **손으로 박은 배열**(`R3_COL_X`)로 처리한다.
- → 유연 그리드 = **매 시트마다 사람이 좌표를 다시 재는 비용**. 근본 해결은 시트를 안 받는 것:
  기본 산출물을 **캐릭터별 개별 PNG 2장**(§1)으로 바꾸고, 시트는 §7 의 **정수 격자 계약**
  (셀·거터·마진·열/행 수를 텍스트로 명시, row-major, 빈 셀 허용)이 있을 때만 예외 허용.

### ④ 종횡비 1:1.65~1.75 vs 실제 → **둘 다 틀렸다. 애초에 카드 비율은 AI 소관이 아니다**
- 실측: 카드 = **226×425 = 1:1.881**(`dist/characters/card-*.png` 14장, `frame-*.png` 5장 전부).
  초안의 1:1.65~1.75 와 불일치.
- 더 중요한 건, **카드는 우리가 만든다**는 점이다. AI 가 맞춰야 할 비율은 카드가 아니라
  **아트 영역**이고, 그 실치수는 `w - inset*2 = 206`, `artBottom - inset = 321` → **206×321 = 1:1.558**.
  게다가 입고 이미지는 `fitCanvas(..., alignY:'bottom')` 로 **비율 보존 레터박싱**되므로
  아트 영역 비율에 정확히 맞출 필요조차 없다.
- → 카드 비율 요구를 삭제하고, `ingest.mjs` 가 실제로 **검증하는 값**으로 교체했다:
  portrait **정확히 1:1, 512×512+**, full **1:2, 512×1024+** (경고 임계 `ar < 1.6 || ar > 2.4`).

### ⑤ 슬러그·포지션·순서 매니페스트 누락 → **JSON 블록 필수 출력으로 추가**
- 초안에는 파일명 규칙도, 기계가독 메타도 없다. 그런데 `ingest.mjs` 는 파일명으로 charId 를
  파싱하고(**소문자 kebab-case 위반 시 건너뜀**), `incoming/<charId>.json` 에서
  `position`·`stars`·`signature`·`frame` 을 읽어 카드를 합성한다.
- `signature` 미지정 시 폴백은 `dominantColor` = "면적 최대 채도색"인데, 파일럿 실측에서
  **3종 중 2종이 테마색과 어긋났다**(펭킹킹 빙하 테마 → 빨간 망토 `#c03025`).
- → §1 네이밍 규칙 + §2 JSON 배열(필드 8개)을 신설. 순서 = 이미지 순서로 못 박아
  시트/개별 어느 경로든 매핑이 결정된다.

### ⑥ "최종 기준 16×16" → **경기 화면이 실제로 쓰는 건 64px 얼굴이다**
- 초안: "필요하면 32×32 보조 원본도 가능하지만 **최종 경기용 기준은 16×16px**".
- 실측 1 — 사다리는 4단이다: 아바타 **64/32/16**(색 24/14/8), 스프라이트 **64/32/16/8**(28/18/10/5).
  16 은 최종이 아니라 **가장 아래 칸**이다.
- 실측 2 — 경기 화면이 고르는 아틀라스는 `viewer-skins.ts:ARENA_ATLAS = "avatars-64"` 이고,
  주석에 A/B 실측 결론이 박혀 있다: *"전신 sprites 는 토큰 지름 16~22px 에서 판독 불가였고
  얼굴 avatars-64(축소 렌더)가 확대·축소 양쪽에서 읽혔다."* 즉 **16×16 타일은 경기장에서 안 쓴다.**
- 실측 3 — `PILOT-P2.md` §3: 16px 아바타 **명확 성공 4/12**, 스프라이트 ≤16px **0/12**.
  가른 변수는 해상도가 아니라 **실루엣 굵기와 명도 대비**.
- → "16×16 논리 해상도로 그려라"를 삭제하고, **512+ 원본을 풍부한 팔레트로 그리되
  64px 로 줄였을 때 읽히게** 라는 요구로 재정의(§4 저해상도 생존 규칙).
  색 축소(6~10색)는 AI 가 아니라 `quantize` 가 단계별로 한다 — 미리 줄이면 64/32 단계가 빈약해진다.
  (32×32 마스터안도 검토했으나 채택하지 않았다: 경기장이 소비하는 건 64px 이고, ≤16px 은
  `PILOT-P2` §6-2 의 **손보정 오버라이드 슬롯**(`__avatar16` 오버라이드, 미구현 P3)이 담당할 영역이다.)

## A-2. 초안에 아예 없던 것 (추가) — **배경 투명 요구**

초안 전체에 **배경 처리 언급이 없다.** 시트 1장 출력이라는 형식 자체가 불투명 배경을 전제한다.
이건 이 파이프라인에서 **가장 비싼 실패 모드**다:

- `PILOT-P2.md` 철회 이력: 배경 제거 파라미터 자동 선택을 **다섯 번 시도해 다섯 번 다 철회**했다.
  지표마다 반례가 있었고(`largestShare` 는 잔류를 못 잡고, `erodedPct` 는 캐릭터 99.77% 소실을
  0.000 으로 통과시켰다), 결국 **자동 선택 자체를 폐기**했다.
- 현재 설계: `bgTol` 을 **사람이 눈으로 골라 `incoming/<id>.json` 에 박는다.** 미지정이면
  정확색 제거로 물러나 **배경이 남는다**(캐릭터를 먹느니 배경을 남긴다).
  파일럿 12종의 실제 값은 `localTol 4~24 / globalTol 30~255` 로 **소스마다 제각각**이었다.
- 즉 불투명 배경으로 들어오면 캐릭터당 사람 손이 2회(값 선택 + 육안 확인) 들어간다.
- → §0-1 을 **절대 규칙 1번**으로 올리고, 불가 시 폴백을 `#FF00FF` 하드 엣지로 규정했다.
  글로우·그림자·오라 금지(§0-5)도 같은 이유다 — 반투명 경계는 자동 제거가 불가능하다.

## A-3. 정정 2건

- **포지션 색을 아트에 칠하지 말 것** — 초안 §11 은 FW 레드/MF 그린/DF 블루/GK 골드를 카드에
  칠하라고 지시한다. 실제로는 `card.mjs` 의 `POS_COLOR`(`#f17869`/`#57b775`/`#0b90d8`/`#fce148`)로
  **우리가 뱃지를 그린다**. 아트가 같은 색 규칙을 쓰면 등급 프레임·팀 링과 충돌한다.
  → 색 규칙은 유지하되 **"아트에서 쓰지 말 것"** 으로 방향을 뒤집어 §6 표에 넣었다.
- **hue 변형 대비 색 선택 가이드 추가** — LEGEND 부족분은 캐릭터 재사용 + **파이프라인 HSL 회전**
  으로 채운다(`make-characters.mjs`, web CSS 필터 아님). `img.mjs:388` 의 `isSkin` 이
  **H 18~48° / S 0.18~0.8 / L 0.35~0.92 를 회전에서 제외**한다.
  → 주조색이 이 대역에 있으면 변형본이 원본과 거의 같아진다. §6 말미에 명시했다.
