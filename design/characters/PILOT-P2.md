# P2 파일럿 결과 — 자동 변환 품질 상한 실측 (#104)

**일자** 2026-07-20 (v2 — 독립 검증 FAIL 후 재작성) · **대상** 라그나(FW) · 아우라(GK) · 펭킹킹(GK)
**증빙** `contact-sheet.png` · 산출 42개(`out/<id>/`) · **판정 주체 = hero**(아래는 측정 사실과 권고이며 확정은 #104 게이트)

> **v1 철회 이력(중요).** 초판은 "≤16px 은 3종 모두 붕괴 → 저해상 자동화는 원리적으로 불가"라고 결론냈다.
> 독립 검증 결과 **오귀속**이었다. 붕괴의 주원인은 도트화가 아니라 **배경 제거 단계의 손상**이었고,
> "3종 모두"도 사실이 아니었다(펭킹킹 16px 은 식별 가능). 해당 문장은 전부 철회하고 아래로 대체한다.
> 파이프라인도 함께 고쳤다(§4).

---

## 1. 파일럿 입력의 성격 — **SPEC 위반 입력이었다**

입력은 레퍼에서 크롭한 **이미 픽셀아트**인 소스다(ref-1 얼굴 90px, ref-3 전신 ~112×197 → nearest ×6).
그러나 배경이 **완전 불투명 다크 패널**이라, SPEC.md §2 가 필수로 요구하는 "투명 배경(불가 시 캐릭터에 없는 단색)"을 **정면으로 위반**한다.
즉 이 파일럿은 도트화의 best case 가 아니라 **배경 분리의 worst case**(어두운 배경 위 어두운 캐릭터)를 함께 측정했다.

→ 결과는 **두 단계로 분리해서** 읽어야 한다: ① 배경 분리 ② 도트화.

## 2. ① 배경 분리 — 어두운 배경 × 어두운 캐릭터는 **원리적으로 분리 불가**

전역 tolerance flood fill 을 지역 기울기 영역확장으로 교체해도 결론은 같다. 임계를 낮추면 배경이 안 지워지고, 높이면 캐릭터의 검은 머리·의상을 먹는다. 그 사이에 **안전한 값이 존재하지 않는다**.

| 캐릭터 | 결과 | 컷아웃 파편(조각/최대덩어리) |
|---|---|---|
| 아우라 | ✅ 분리 성공 (밝은 금발·흰 날개 = 배경과 대비 큼) | 통과 |
| 펭킹킹 | ✅ 분리 성공 (흰 얼굴·빨간 망토) | 통과 |
| **라그나** | ❌ **실패** — 검은 머리·검은 바지가 다크 패널과 융합, 다리·머리 소실 | portrait 36조각/40% · full 66조각/45% |

**이건 도트화 품질과 무관한 별개의 실패다.** 라그나의 저해상 산출이 뭉개진 1차 원인은 여기다.
→ **SPEC §2 의 투명 배경 요구는 권고가 아니라 필수 조건**임이 실증됐다.

## 3. ② 도트화 — 배경 분리에 성공한 2종 기준

라그나는 입력이 이미 손상됐으므로 도트화 판정에서 **제외**한다(오염된 표본).

| 단계 | 아우라 | 펭킹킹 | 판정 |
|---|---|---|---|
| **카드 (ref-2)** | ✅ | ✅ | **양호** — 프레임·별·뱃지·아트 배치 정상, 캐릭터 식별 명확 |
| 아바타 64px | ✅ | ✅ | **양호** |
| 아바타 32px | ✅ | ✅ | **양호** (v1 의 "경계" 판정은 배경 손상 탓이었음) |
| **아바타 16px** | ❌ 얼굴 뭉갬 | ✅ **식별 가능**(왕관·파란 몸통·흰 얼굴·주황 부리) | **소스에 따라 갈림** |
| 스프라이트 64/32px | ✅ | ✅ | 양호 |
| **스프라이트 16/8px** | ❌ | ❌ | **실패** — 전신은 정보량이 많아 이 크기에 안 들어간다 |

**결정 변수는 해상도가 아니라 소스의 실루엣 단순성과 색 대비다.**
펭킹킹(굵은 실루엣·고대비 블록)은 16px 에서 살아남고, 아우라(섬세한 얼굴·비슷한 명도의 금발/날개)는 무너진다.
전신 스프라이트는 ≤16px 에서 2종 모두 실패 — 얼굴 아바타보다 담아야 할 정보가 많기 때문.

## 4. 검증 지적으로 고친 것

| 발견 | 조치 |
|---|---|
| **배경 제거가 캐릭터를 조용히 파괴** | 전역 tolerance flood fill → **지역 기울기 영역확장**으로 교체. 더 중요하게 **컷아웃 품질 게이트 추가**(`cutoutQuality`: 연결요소 파편화·내부 구멍 검출) → 손상 시 `report.warnings` 로 경고. 이제 라그나는 "조각 36개, 최대 덩어리 40%" 로 **자동 검출된다** |
| 입고 검증 임계가 SPEC 의 절반(256/512) | SPEC 값(512×512 / 512×1024)으로 정정 + **정사각·1:2 비율 검증 추가** |
| 카드 프레임이 ref-2 대비 ~2배 두꺼움 | ref-2 **재실측**(카드 원점 x=22, y=300 스캔: local x1..x7 = 금 7px) → 인셋 17px → **10px** |
| 설명판이 너무 얕고 아이콘이 작음 | 설명판을 하단 프레임까지 꽉 채우고 아이콘을 패널 높이에 맞춰 자동 산출(지름 17 → 24px) |
| 반투명 밴드가 `fillRect`(덮어쓰기)로 그려져 알파가 산출물에 잔류 | `blendRect`(src-over) 추가·적용 → 카드가 완전 불투명 |
| 별 밴드 하단 구분선이 설명판에 덮여 안 보이는 죽은 코드 | 구분선을 설명판 상단(`descY-1`)으로 이동 |
| 잘린 IDAT 를 조용히 수용(빈 이미지 반환) | 압축해제 길이 검증 → 명시적 에러 |
| `circleWithRing` 이 소스 크기를 가정해 조용히 크롭 | 크기 불일치 시 리사이즈 |
| `Ragna__portrait.png` 가 별개 캐릭터로 등록됨 | charId 를 소문자 kebab-case 로 검증, 위반 시 건너뛰고 경고 |
| 대조 시트 설명문이 카드 프레임 밖으로 넘침 | 설명판 영역 안으로 클리핑 |
| 링 내부 배경색 `#0c1117` (팔레트는 `#0b1117`) | 정정 |

## 5. 남는 한계

- **시그니처 자동 추출은 "면적 최대 채도색"** 이라 테마색과 어긋난다. 3종 중 **2종 불일치**: 펭킹킹 `#c03025`(빨간 망토, 테마는 빙하 `#326e8a`), 라그나 `#c7331e`(레퍼 `#f7a051`). 아우라만 일치(`#f5bc47` vs `#eec830`).
  → **`incoming/<id>.json` 에 `signature`/`frame` 명시 권장**, 자동은 폴백.
- **저해상 단계는 소스 의존적**이라 자동화 결과를 신뢰할 수 없다 — 되는 캐릭터와 안 되는 캐릭터가 갈린다.
- **비-PNG 입력 경로는 macOS `sips` 의존**이라 결정론·이식성 미보증(PNG 경로만 검증됨).
- **레퍼 실측치 충돌**: `measurements.ref103.json` 의 `ref2_frame_scan_y300` 은 절대좌표에 카드 밖 글로우 5px 를 포함해 금테 두께가 과대 측정돼 있다. `row_y:105` 도 재실측값(y≈111)과 어긋난다. → **#103 에 이슈 레이즈 필요**(그쪽 소유 파일).

## 6. 권고 (hero 판정 대기)

1. **SPEC §2 의 투명 배경을 "필수"로 강제**한다 — 권고가 아니라 실패 조건임이 실증됐다. 파이프라인은 이제 위반을 경고한다.
2. **A안(픽셀아트 직접 생성) 권장 유지.** 다만 근거는 "도트화가 원리적으로 불가"가 아니라 **"32px 이상은 자동으로 충분하고, ≤16px 은 소스에 따라 갈려 신뢰할 수 없다"** 이다.
3. **≤16px 은 hero 직접 생성/손보정 슬롯을 두는 것을 권장** — `incoming/<id>__avatar16.png` 같은 오버라이드로 받고, 없으면 자동 산출로 폴백(미구현, 승인 시 P3).
4. **32px 이상 + 카드는 자동 파이프라인으로 충분** — 그대로 간다.
5. **재파일럿 필요**: 위 결론 중 도트화 부분은 표본 2종에 기반한다. hero 가 SPEC 준수(투명 배경) 이미지를 몇 장 주면 오염 없는 측정을 다시 낼 수 있다.
