## 1. 문제정의  <!-- Phase 4 hero gate -->

- **현상**: 페널티 유발 파울(t163)에서 파울러 A2와 피해자 H9가 뷰어상 4.7m 떨어져 보여 "접촉 없는데 왜 반칙?"(hero 육안). 다른 파울도 비슷하게 벌어져 보임.
- **근본 원인(재규정)**: **엔진 파울 로직은 정상** — 태클 순간 실거리(tackD) 계측 결과 t163 파울 = **0.51m 접촉**(전 파울 0.18~1.52m, 모두 tackleRange 2.0m 이내). 문제는 **뷰어**: `commitFoul`→`restartPenalty`가 **같은 틱에 피해자(taker)를 페널티 스팟으로 즉시 이동**시키고, 스냅샷은 그 이후 기록 → 파울 틱 화면엔 피해자가 이미 스팟에 있어 **접촉 순간이 안 보임**. 관객엔 "떨어진 채 파울"로 오인.
- **영향 범위**: 뷰어의 파울→세트피스 전환 표시(접촉 은폐). 엔진 파울 판정 자체는 정확. (엔진에서 reposition 을 1틱 늦추는 방향이면 결정론 골든.)

### Phase 2 — 분석 (사실)
- `contest.ts tryTackle`(456): 볼오너 반경 `config.contest.tackleRange`(=**2.0m**, showcase 도 상속) 내 상대만 태클러. `if (d <= range …)`(475). `commitFoul` 은 tryTackle 에서만 호출(유일 경로), 즉 **모든 파울은 tackD ≤ 2.0m 에서만**.
- 계측(tryTackle 에 tackD 로그 삽입, showcase): FOUL@163=**0.51m**, @828=0.64m, @938=1.52m, @1247=0.18m — 전부 접촉.
- `commitFoul`(409): foul 이벤트 → 카드 롤 → 박스 내면 `restartPenalty`(443)로 taker=피해자를 스팟에 즉시 배치. match.ts: tryTackle(428) 처리 → snapshot(447) **후** 기록 → 스냅샷엔 피해자가 스팟.
- 실측: t163 스냅샷 H9=(94,34)=페널티 스팟, A2=(96.3,38.1) → 4.7m(reposition 후). 직전 t162 는 5.2m(1틱 뒤 접촉으로 좁힘). **접촉 프레임(0.51m)은 어느 스냅샷에도 없음**(같은 틱 내 태클→reposition).
- 참고 한계: 1틱=1초 해상도라 태클러가 5m→접촉을 1틱에 좁히는 것도 스냅샷엔 급작스러움(Tier C 서브틱은 백로그).

### Phase 3 — 진단
- **채택**: 파울은 접촉(0.51m)에서 정상 발생. 뷰어가 **같은 틱 reposition 후**를 파울 틱으로 보여줘 접촉이 은폐됨 → "떨어진 파울" 오인. 엔진 버그 아님.
- 반증 검토: "tackleRange 가 큼?" → 아님(2.0m, 계측 0.51m). "엔진이 원거리 파울?" → 아님(tackD 게이트).
- 수정 방향(계획에서 확정): (V) 뷰어가 파울 틱에 접촉을 보여준 뒤 페널티 셋업, 또는 (E) 엔진이 피해자 reposition 을 1틱 늦춰 파울 틱 스냅샷에 접촉이 남게(결정론 골든). 접촉 프레임 데이터가 없으므로 (E) 가 더 정직할 수 있음 — hero 판단.
