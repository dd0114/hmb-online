## 1. 문제정의  <!-- Phase 4 hero gate -->

- **현상**:
  - **(A) 스퓨리어스 코너 버그**: home 키퍼가 away 슛을 **캐치**한 다음 틱에 반대편 **home 코너**가 생기고 공이 순간이동한다. hero 눈엔 "코너하다 상대 코너로 점프".
  - **(B) 코너 반복**: 같은 팀 코너가 짧은 간격으로 3연속 반복되며 양상이 거의 동일.
- **근본 원인**:
  - (A) = **엔진 이벤트 데이터 버그**(렌더 아님). 세이브(캐치)가 반대편 팀 코너를 생성 — 팀/원인 불일치. 코드 추적 필요(resolveShot 세이브 경로 / shot_out `setPiece.side`/deferred restart / **통합 3-way 머지 아티팩트 의심**: #91 세이브→코너 + α 엔진 결합).
  - (B) = **Tier-B 엔진 단순화 한계**(설계). 코너 = 단일 크로스→낙하점 최근접 경합, 수비 적응·코너 변주 미모델 → 반복.
- **영향 범위**: 엔진 `contest.ts`(resolveShot 세이브/shot_out) + `match.ts`(deferred restart). (A)는 결정론 골든 재검. (B)는 밸런스/리얼리즘(α 트랙 연계).

### Phase 2 — 분석 (데이터 실측, match-log engine@0.13.0)
- **(A) 버그 시퀀스** (원시 이벤트+공):

  - 기대: away 공격이 home 골(x=0)에서 세이브 → **away 코너(x=0)** 또는 home 캐치 후 인플레이. **home 코너(x=105)는 팀·골 둘 다 반대 = 스퓨리어스.** (세이브→코너 코드는 `side: scorerSide`=away, `attackGoal(away)`=x=0 이라 정상 경로로는 이 결과 불가 → 별도 상태 버그.)

### Phase 3 — 진단 (root cause + 방향)
- **(A) = 버그, 수정 대상**. 우선순위 높음(경기 흐름 오류·시각 점프). 방향: 세이브 경로에서 코너/캐치 후 상태(setPiece/deferred restart/side)가 반대편으로 새는 지점 추적 → 재현 테스트(E2E-TDD: 세이브 후 코너가 생기면 side=슛한 팀·골=슛한 골 이어야) → 수정 → 골든/결정론 재검. 통합 머지가 원인인지(#91∩α) 개별 브랜치 대조.
- **(B) = 한계, 인정 + 개선안 백로그**. Tier-B 코너가 단순 크로스-낙하점이라 반복. **개선 방향(config/behavior)**: ①코너 변주(숏코너·near/far 딜리버리 산포↑) ②수비 박스 세팅(코너 시 수비수 마킹/포스트 배치) ③재코너 시 미세 변화. α 엔진 리얼리즘 트랙(#99, `research/engine-realism-gap.md`) 연계. **결정론 유지 필수**.
- 반증: (A)가 렌더? → 이벤트 데이터(match-log) 자체가 home 코너라 엔진. (B)가 버그? → 규칙상 재코너는 정상(클리어 아웃), 다만 반복 양상 단조 = 설계 한계.
