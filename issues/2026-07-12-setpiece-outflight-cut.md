## 1. 문제정의

- **현상**: 코너킥/스로인 등 공이 라인 밖으로 나가는 세트피스에서, 공이 나가는 경로를 끝까지 안 보여주고 궤적이 끊긴 채(파킹지점 → 재시작 스팟 순간이동) 진행돼 납득이 안 됨. hero 육안 보고(2026-07-12, 뷰어).
- **근본 원인**: `synthOutFlight`(playback.mjs:132)는 직전 두 스냅샷의 **속도 외삽**으로 아웃 비행 레그를 합성하는데, null(합성 포기 → 기존 컷)로 빠지는 두 경로가 세트피스를 구조적으로 삼킴:
  - **코너 = 전량 CUT (정지공)**: 코너는 세이브/블록으로 공이 **골문 앞 정중앙(x=2.5/102.5, y=34)에 v=0으로 파킹**된 상태에서 발화(0.9.0 `saveCatchDepthM` 파킹). 외삽할 속도가 없어 `Math.hypot(vx,vy)<1e-6` → null → 컷. 실측 5/5 코너 전부 CUT. 게다가 파킹지점(중앙)은 실제 아웃 지점도 아니라 코너 깃발로의 순간이동이 큼.
  - **느린 스로인 = 일부 CUT (tHit>3)**: 공이 느리게 굴러 나가면(v≈3~5) 3틱 내 경계 도달 못 해(tHit 9~18) → null → 컷. 실측 throw_in@559(tHit 9.79)·@714(tHit 18.62) 등.
- **영향 범위**: 순수 뷰어 연출(index.html + playback.mjs). 엔진/결정론/골든 무관. showcase 기준 코너 5건 전부 + 스로인 ~2건. 관객 몰입(공이 어디로 왜 나갔는지 판독) 저하.

### Phase 2 — 분석 (발견 사실)
- `synthOutFlight`는 `st.setPiece`(= `corner`/`throw_in`, SETPIECE_STOP)일 때만 index.html:468~474에서 호출됨. 코너도 대상 범위엔 들어감.
- null 폴백 3분기: ① 정지공(v<1e-6) ② tHit<0 또는 >3틱 ③ exit-spot 이격 >8m.
- 실측(match-log showcase, `scratchpad/analyze-out.mjs`):
  - corner@148/644/765/978/1314 → 전부 `v=0.00`(정지공) → CUT.
  - throw_in 성공(v≈18, d=0m): @231/525/542/790/855/1106/1126.
  - throw_in CUT: @559(tHit 9.79)·@714(tHit 18.62) — 느린 롤아웃.
- 렌더: `hold.synth`가 있으면 draw()에서 freeze 도입 SYNTH_MS 동안 from→exit 를 lerp(index.html:209~211). 없으면 `spansReposition`이 재배치 틱에서 보간을 컷(index.html:205) → 순간이동 방지 위해 아예 안 그림 = "경로 끊김".

### Phase 3 — 진단 (root cause 가설)
- **채택 가설**: `synthOutFlight`의 "직전 2스냅 속도 외삽" 전제가 **코너의 파킹공(v=0)·느린 롤아웃**을 커버 못 함. #43은 스로인의 빠른 사이드라인 아웃만 해결했고, 코너는 발화 직전 공이 이미 정지 파킹돼 있어 원천적으로 빠짐.
- 반증 검토: "코너가 setPiece 대상이 아니라서?" → 아님(대상 맞음, 호출됨). "렌더 버그?" → 아님(synth가 null이라 애초에 안 만들어짐). 데이터로 null 분기 확정.

## 2. 계획

### 설계 판단 (코너 vs 스로인 = 다른 처리)
- **스로인**: 공이 진짜로 사이드라인 넘어 굴러 나감(느려도) → 되짚기+tHit 완화로 **진짜 아웃 크로싱** 합성 가능(truthful).
- **코너**: 파킹공(v=0)이고 되짚기 슛은 골 중앙 지향(외삽하면 골대 안) → **진짜 아웃 궤적이 데이터에 없음**. 코너 = 세이브/블록 → 키퍼가 골라인 밖으로 쳐냄의 추상화. → 파킹지점에서 **골라인(x=0/105) 밖으로 나가는 짧은 디플렉션 레그**를 합성(키퍼가 넘긴 것으로 묘사, 그 후 코너 깃발로). 날조된 '플레이'가 아니라 코너의 함의(키퍼 쳐냄)를 렌더 — 이 판단을 hero 승인받는다.

### 채택 방향 (뷰어 전용, 결정론 무관)
- `synthOutFlight` 를 일반화: (1) prev1-prev2 뿐 아니라 **뒤로 K틱 되짚어** 마지막 실움직임 구간을 속도원으로(파킹공 커버), (2) tHit 예산 완화(느린 롤아웃 커버), (3) 재시작 종류별 목표 경계 명시(스로인=사이드라인, 코너=골라인).
- 코너 전용: 되짚기 슛이 골문 안쪽을 향하면 **디플렉션 아웃 레그**(파킹→골라인 밖, 코너 깃발 쪽 y)로 대체.
- 순수 함수 유지(playback.mjs), 뷰어는 `hold.synth` 소비부만 확장. index.html:468~474 호출부 일반화.

### E2E Goal
뷰어 재생 중 코너(showcase 5건 전부)와 느린 스로인에서, 데드볼 freeze 도입부에 공이 **경계선(코너=골라인/스로인=사이드라인)을 실제로 넘는 레그가 렌더**되고(순간이동 아님) 그 뒤 재시작 스팟에 놓인다 — hero 가 뷰어를 열어 "공이 나가는 걸 끝까지 본다".

## 5. Learned
- **가설 정확도**: 코너 전량 CUT 원인(정지 파킹공 → 속도 외삽 불가)을 match-log 실측(코너 5/5 v=0.00)으로 즉시 확정. #43(빠른 스로인만 커버)의 미해결 잔여를 데이터로 규명.
- **설계 판단**: 코너는 '진짜 아웃 궤적'이 데이터에 없음(파킹공+슛은 골 지향) → 날조 대신 **키퍼 디플렉션**(코너의 물리적 함의)으로 묘사, hero 승인받고 진행. 인지 갭 연출은 "truthful vs 함의 표현"을 명시적으로 가르고 승인받는 게 안전.
- **연속성 규칙**: 합성 레그를 항상 **스팟에서 종료**(exit=spot)시키면 freeze 착지 프레임과 이중 순간이동이 원천 제거됨. via 2레그로 크로싱을 보여주면서도 스팟 종료 유지.
- **QA 에이전트 stall 대응**: 스크린샷 과다가 원인 → 재실행 시 "캡처 ≤4장, 수치 우선, 종료 시 정리" 규율 명시하면 안정적으로 완료(#48 QA 도 동일 규율로 성공).
- **다음 단축**: 세트피스 아웃 연출은 `synthAt` 훅으로 결정론 계약(애니 wall-clock 의존 회피) + 실화면 1~2장 육안이 효율적.
