# 트레이드 유저 플로우 재정의 — 튜토리얼 보장 트레이드 + 자동 리필 (hmb:trade)

- 세션: hmb:trade (owned = `server-java/**` 트레이드 상태머신 + `apps/web/src/trade/**`)

## 0. Hero 가 말한 유저 플로우 (원문 요지)

1. 처음 들어갔을 때는 **뽑기 다 가능**
2. **튜토리얼**이 준비되어 있고, 들어가면 **다이아 등급 1명 트레이드 성공**하게 함
3. 성공하면 **다음 선수가 랜덤 선택**되고, **등급별 대기시간**과 함께 "선수가 대기 중"이라고 표시
4. 대기시간 끝나면 그 선수 **트레이드 진행 가능**
5. 또는 **[pass] 버튼** — 신청하거나 pass 하고 나면 **또 랜덤으로 선수를 받음**
6. **슬롯 3개**

## 1. 문제정의

- **현상**: 현행 트레이드(#149 W2, release/next 통합 완료)는 `IDLE → [장 시작!] → WAITING(등급공개+카운트다운) → OPEN → 판정 → IDLE` 이다. 판정이 끝나면 슬롯이 **빈 채로 멈추고 유저가 [장 시작!]을 다시 눌러야** 다음 선수가 나온다. Hero 가 원하는 플로우에는 그 버튼이 없다 — **판정/pass 직후 다음 선수가 자동으로 배정**되고 대기가 시작된다. 또한 신규 유저의 **첫 경험(튜토리얼에서 다이아 1명 보장 성공)**이 존재하지 않는다: 현재 첫 진입 슬롯 3개는 전부 빈 IDLE 이고, 첫 오퍼의 등급·성공 여부는 전부 확률 롤이다.
- **근본 원인**: #149 는 "자동 대기가 수동적이다"는 문제를 **진입에 버튼을 다는 것**으로 풀었다(IDLE 상태 신설). 그런데 hero 가 실제로 원한 능동성은 **진입 버튼이 아니라 "공개 → 기다림 → 받거나 pass"라는 선택 리듬**이었다. 진입을 막은 것은 그 리듬을 만들지 못한 채 **빈 슬롯이라는 죽은 상태**만 추가했다. 더불어 신규 유저 온보딩이 확률에 맡겨져 있어 **첫 성공 경험이 보장되지 않는다**(현행 튜토리얼은 로비·덱 코치마크 오버레이일 뿐, 트레이드 결과에 개입하지 않는다).
- **영향 범위**:
  - `server-java/**` 트레이드 상태머신 — `IDLE` 상태와 `POST /{slot}/start` 의 존재 이유가 바뀐다(자동 리필로 대체). 신규 유저 **첫 오퍼 스크립팅**(다이아·성공 보장) 필요 = 유저별 "첫 트레이드 완료" 플래그 신설.
  - `apps/web/src/trade/**` — [장 시작!] 카드 제거/축소, [거래 안함] → **[pass]** 로 정리, "대기 중" 표현.
  - 계약 `docs/plan-v3/api/openapi-v2.yaml` — 상태 enum·엔드포인트 변경(additive 아님, **삭제/의미변경 포함**).
  - **경계 밖(이슈 레이즈 필요)**: 뽑기 포인트·확률은 `data/**`(economy) 소유, 튜토리얼 코치마크는 `apps/web/src/common/**`(web 에픽) 소유.

## 2. Phase 2 — 조사 결과 (사실만)

**현행 트레이드 (내가 이번 주에 만든 것, release/next `4611c42`)**
- 상태: `IDLE | WAITING | OPEN | RESOLVING`. 신규 유저 슬롯 3개는 전부 `IDLE`(오퍼 없음).
- `POST /api/trade/{slot}/start` = IDLE 에서 "장 시작", OPEN 에서 "거래 안함"(오퍼 폐기 + 새 오퍼·새 대기).
- WAITING = 등급만 공개(`targetGrade`), 선수 정체는 마스킹. 대기시간 = 등급별 config(`waitHours`, env 로 초 단위 오버라이드 가능).
- OPEN = 전면 공개, FA=제안 / TRADE=수락. 판정(FA성공·accept·decline) 후 → `IDLE`. FA 실패만 같은 오퍼로 쿨타임 재대기.
- 시드 결정론·원장 멱등 유지. `revealed` 플래그로 한 번 공개된 오퍼는 다시 가리지 않는다.

**튜토리얼 (현행)**
- `apps/web/src/common/tutorial-*` — **클라이언트 코치마크 오버레이**(localStorage `hmb.tutorial.done.{userId}`). 스텝 = 로비 5개 + 덱 2개. **트레이드 스텝 없음, 게임 결과에 개입하지 않음.**
- 서버에 튜토리얼/최초진입 플래그 **없음**(마이그레이션 V1~V7 에 컬럼 부재). `user.tutorialDone` 은 "발행 예정" 주석만 존재.

**뽑기·초기 자원 (현행)**
- `data/players/economy.v2.json`: `initialPoints: 3000`, 뽑기 `singleCost 300 / tenCost 3000(11장)`, 확률 BRONZE .45 / SILVER .30 / GOLD .15 / DIA .08 / LEGEND .02, 10연차 pity = GOLD 이상 보장.
- 즉 **신규 유저는 3000P = 10+1 뽑기를 정확히 1회 할 수 있다**(또는 단차 10회). 뽑기에 별도 잠금·해금 게이트는 없다.

## 3. Phase 3 — 가설과 판단

| 가설 | 근거 | 반증 가능성 |
|---|---|---|
| **H1 (채택)** hero 가 원한 건 "진입 버튼"이 아니라 **끊기지 않는 선택 리듬**이다. 슬롯은 항상 뭔가를 물고 있어야 하고, 유저의 능동성은 **받을지/pass 할지**에서 나온다. | 원문에 [장 시작!]이 한 번도 등장하지 않고, "신청하거나 pass 하고 나면 또 랜덤으로 선수를 받아"로 **자동 리필**을 명시 | hero 가 "첫 진입만 수동"을 의도했다면 반증 → **게이트에서 확인** |
| H2 튜토리얼 다이아 보장은 연출(코치마크)만으로 충분하다 | 현행 튜토리얼이 오버레이 기반 | "**성공하게 해**"는 결과 보장이라 클라이언트 연출로는 불가 — 서버가 첫 오퍼를 스크립팅해야 함. H2 기각 |
| H3 "뽑기 다 가능"은 이미 충족(3000P=10연차 1회) | economy 실측 | hero 가 "여러 번" 또는 "무료"를 의도했다면 반증 → **게이트에서 확인** |

## 4. 🛑 Hero 결정이 필요한 3가지

### D1. [장 시작!] 버튼을 없애는가 (핵심)
새 플로우대로면 **판정/pass 직후 다음 선수가 자동 배정**되므로 빈 슬롯(IDLE)과 [장 시작!]이 사라진다.
→ **이번 주에 만들어 release/next 에 합친 W2 진입 UX 를 되돌리는 것**이라 확인이 필요하다.

- **(a) 폐지 — 추천**: 슬롯은 늘 선수를 물고 있다. 유저 선택은 [트레이드 신청] / [pass] 둘. 원문 그대로.
- (b) 첫 슬롯 채울 때만 [장 시작!], 이후는 자동 리필.
- (c) 유지 — 판정 후엔 빈 슬롯, 다시 눌러야 함(현행 유지).

### D2. 튜토리얼 "다이아 1명 성공 보장"의 범위
- **(a) 서버가 첫 오퍼를 스크립팅 — 추천**: 신규 유저 1번 슬롯의 첫 오퍼 = **다이아 등급 고정 + 대기 짧게(또는 0) + 판정 100% 성공**. "첫 트레이드 완료" 플래그를 서버에 저장(재접속·재설치해도 1회만).
- (b) 그냥 다이아 선수 1명을 지급(트레이드 화면을 거치지 않음).
- 함께 정할 것: 보장 성공이 **FA 방식인지 TRADE 방식인지**(TRADE 면 내 선수 1명을 내줘야 함 → 온보딩엔 FA 가 자연스러움), 3슬롯 중 **1번 슬롯만** 적용하는지.

### D3. "처음 들어갔을 때 뽑기 다 가능"의 의미
현재도 신규 3000P 로 **10+1 뽑기 1회**가 가능하다(잠금 없음).
- (a) 지금 그대로 충분 — 별도 작업 없음.
- (b) 첫 진입에 뽑기를 **더 많이** 돌릴 수 있게(초기 포인트 상향 또는 무료 뽑기권) → **`data/**` 경제 수치 = 다른 세션 소유라 이슈 레이즈 후 협의 필요**.
