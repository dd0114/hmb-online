# apps/web 모듈 가이드 (도메인 세션용 CLAUDE.md)

이 디렉토리는 **웹 클라이언트(React SPA) 도메인**이다. 이 모듈 세션은 `apps/web/**`만 소유한다.

## 필독 (이 순서로)
1. `docs/plan-v2/PRD-v2.md` §2(유저 여정)·§3.7(AC-W1~W5)
2. `docs/plan-v2/LLD-web.md` (화면·구조·웨이브)
3. `docs/plan-v2/api/openapi.yaml` (서버 계약 SoT — 타입은 openapi-typescript 생성물 사용)
4. 에픽 이슈(web) STATE

## 도메인 경계 (위반 금지)
- 서버·엔진·뷰어 코드 수정 금지. API가 부족하면 server-java 에픽에 이슈 레이즈.
- **경기 캔버스 재생을 자체 구현하지 말 것** — QA 뷰어 소비(R1 이슈)만. R1 전에는 텍스트 타임라인까지만(LLD-web §3). 재발명 실패 사례 있음(#57).

## 캐릭터 아트 노출 정책 — **다이아 이상만 얼굴** (#285, hero 확정 2026-07-29)

> 이 절이 아래 두 절보다 **먼저** 걸린다. 어느 자리에 무슨 컴포넌트를 쓰느냐와 무관하게, 등급이
> 임계 아래면 **아트를 아예 그리지 않는다**.

- **판정은 `common/icon-policy.ts` 한 곳** — `CHAR_ART_MIN_GRADE` + `showsCharacterArt(grade)`.
  화면에 `grade === "GOLD"` 같은 비교를 적지 마라(계약이 아트 렌더 파일을 스캔해 금지한다).
  등급 미상은 **fail-closed**(안 그린다) — 못 그려도 화면은 성립하지만 정책이 뚫리면 회귀다.
- **`CharAvatar.grade` 는 필수 prop 이다.** 옵셔널이면 등급을 안 넘긴 호출부가 조용히 정책 밖으로
  새 나간다(실제로 `PromptFields` 가 그 상태였고 타입 게이트가 잡았다). 타입이 호출부를 강제하게 둔다.
- 임계 아래에서 보이는 것: 목록·슬롯 = **등급색 테두리 + 이니셜**(`data-art-policy="hidden"`) ·
  경기장 = **팀색 원 + 등번호** · 카드 = **등급 프레임·링·이름·별은 그대로, 아트 창만 아이콘**.
  ⚠️ **프레임은 아트가 아니다** — 같이 지우면 뽑기·도감에서 "무슨 등급을 얻었나"가 사라진다.
- **경기장 판정 근거가 바뀌었다**: 구 U-D8 은 "이 유닛이 등급 공용 디폴트냐"(`unitIsSharedDefault`)
  였는데, 지금 데이터에선 공용 디폴트 = 골드 이하 133명이라 **우연히** 답이 같았을 뿐이다. 발행측이
  골드에게 고유 아트를 주면 그 순간 뚫린다. 이제 `buildViewerSkins(assets, log, grades)` 가 **등급**으로
  자르고, 공용 디폴트 제외는 **백스톱**으로 남는다(등급표가 없는 QA 콘솔 경로용). 두 층 각각 계약이 있다.
  등급표는 **부모가 주입한다**(`MatchViewer` → `VisualPlayback.grades`) — 캔버스 부품은 API 를 모른다.
  ⚠️ `/api/players` 응답이 배열이 아닐 수 있다(구 서버·목의 `{}`) → `Array.isArray` 가드 필수.
  없으면 결과 화면이 통째로 흰 화면이 된다(`growth-mock` G4 가 실제로 잡았다).
- **예외 문은 하나뿐**: `artReviewExempt`(DEV `/design/cards` 아트 검수 도구). 제품 화면 금지 —
  계약이 사용처를 `src/design/**`·`src/common/**` 로 묶는다. "이 카드만 보이게" 하려고 쓰지 마라.
- 계약 = `common/icon-policy.test.ts`(정책·단일판정·예외 경계) + `CharAvatar.test.ts` ·
  `FullArtCard.test.ts` · `viewer-skins.test.ts`(**픽스처로 "고유 아트를 가진 골드"** 를 만들어
  구 근거가 뚫리는 조건을 태운다 + 변이체 킬) + `e2e/p285-icon-policy.spec.ts`(실화면·캔버스 픽셀).
- ⚠️ **열화 경로 표본은 다이아 이상으로 잡아라.** 골드 이하는 정책이 먼저 CSS 폴백으로 잘라서,
  아트 파이프라인이 통째로 죽어도 계약이 통과한다(구 표본 P050 이 정확히 그 자리였다).

## 캐릭터 아트 — 아이콘 / 풀아트 두 축 (#145 · #187)

| 자리 | 컴포넌트 | 언제 |
|---|---|---|
| 밀집 UI — 덱 리스트 행·전술보드 슬롯·매치 토큰·홈 팀 한 줄 | `common/CharAvatar` (얼굴 타일) | **기본** |
| **도감 그리드**(선수 탭) | `FullArtCard` (**아트만**) | `variant="art"` — #286 W3 에서 밀집 UI 규칙 **밖으로 나갔다** |
| 뽑기 결과 그리드 | `FullArtCard` (프레임 통짜 — 이름·별·등급이 카드 안 밴드에 앉는다) | `variant="card"` |
| **강화/카드 상세**(`CardGrowthDetail`) · 덱 지시 레일 헤드 · 트레이드 영입 대상 | `FullArtCard` (**아트만**) | `variant="art"` |

- ⚠️ **도감은 이제 전신이다 — 정책이 뒤집혔다(#286 W3, hero 확정).**
  옛 규칙은 *"도감은 어느 상태에서도 풀아트가 아니다"* 였고 근거는 **"잠긴 카드에 원색 전신을 띄우면
  잠금 표현과 어긋난다"** 였다. hero 판정(*"아이콘 아니라 전신 보여주자. 아이콘만 하면 모으는 재미가
  떨어질 것 같아"*)으로 뒤집으면서 그 근거는 **미보유 전신 실루엣**(원색이 아니다)으로 해소했다.
  즉 대가를 지불하고 바꾼 것이지 규칙을 잊은 게 아니다.
  - 도감 그리드 = `FullArtCard variant="art"` + `size="grid"`. 미보유는 `brightness(0)` + 이름 감춤.
    ⚠️ **이걸 "실루엣"이라고 부르지 마라 — 실화면은 통짜 검정 판이다.** `characters` 축 에셋은
    배경까지 구워진 완성 카드라 알파가 없어서, 밝기를 4배로 올려도 형체가 0이다(독립검증 MAJ-1
    실측). 그래서 "안 가진 것"을 읽히게 하는 실제 신호는 **자물쇠 오버레이**이지 형태가 아니다.
    형태까지 살리려면 발행측이 **알파 있는 아트**를 줘야 한다(#317).
  - **덱 리스트 행·전술보드 토큰·매치 토큰은 여전히 아이콘이다** — 경계가 사라진 게 아니라 도감만 나갔다.
  - 계약 = `e2e/p286-w3.spec.ts`(아트 창 비율·실루엣 필터·이름 감춤) + `e2e/p3-card-art.spec.ts`
    (도감엔 풀아트가 **있고** 아트 크롭이다 / 덱·토큰엔 **없다**).
  - ⚠️ **전신은 다이아 이상만이다 — AC 를 그렇게 좁혔다(hero 확정 Q6=B, 2026-07-30).**
    #285 노출 정책(`icon-policy.CHAR_ART_MIN_GRADE = "DIA"`)이 **이 절보다 먼저** 걸린다.
    골드 이하는 매핑이 있어도 아트를 안 그리므로 도감에서도 `frame-only`(=`<img>` 자체가 없다)다.
    - **실측**(도감 [전체], 미보유): DIA 이상 = `full-art` + 실루엣 / GOLD 이하 = `frame-only`.
    - 즉 "전신으로 모으는 재미"는 **로스터의 26%(39명)** 에만 성립한다. hero 는 이 상태를 알고
      **B(현행 유지 + 명시)** 를 택했다 — 하위 133명은 **공용 도트 하나**를 공유해서, 전신으로
      깔면 같은 그림이 133칸 반복돼 오히려 나빠지기 때문이다.
    - ⚠️ 한때 이 자리에 *"나머지는 **아트 발행**이 필요하다"* 라고 적혀 있었다. **틀린 말이다** —
      발행해도 #285 가 막는다. 진짜 해결은 **아트 발행 + 임계 조정**이 같이 가야 한다.
    - **미보유 잠금 표현은 등급과 무관하게 같다**(자물쇠 오버레이 = 아트 유무 무관). 같은 상태가
      등급에 따라 두 그림으로 갈리던 것은 결함이었다(독립검증 W3 BL-1).
    - 임계를 옮기면(`CHAR_ART_MIN_GRADE`) `e2e/p286-w3.spec.ts` 의 "전신은 다이아 이상만" 계약이
      **먼저 깨진다** — 그때 이 결정을 다시 보라는 뜻이다.
- **`variant="art"` 를 쓰는 기준**: 이름·등급·별을 카드 **밖**에서 이미 보여주는 자리. 프레임 통짜를 쓰면
  에셋이 그려둔 하단 밴드가 **빈 검은 띠**로 남는다(트레이드에서 카드 높이의 22%였다).
- **포지션 뱃지는 항상 선수 값으로 덮는다** — 아트에 구워진 건 **캐릭터의** 포지션이라 교차 매핑 선수
  (`player-chars.v1.json` 의 `crossPosition`, 현재 P012 1명)에서 틀린 값이 노출된다. 계약 표본에 그 선수를
  넣어야 검사가 성립한다.

### 아트 축이 **셋**이다 (#207 W3-D) — 매핑이 어느 manifest 를 볼지 정한다

`player-chars.v2.json` 의 값은 문자열이 아니라 **`{axis, id}`** 다. `charRefFor` 가 정규화하고
`char-manifest` 가 축별 접근자를 준다. 등급별 배정(U-D5·U-D8·U-D9):

| 대상 | 축 | 아트 |
|---|---|---|
| 활성 LEGEND 5 (P173·P175·P176·P177·P179) | `units` | 유닛별 고유 실아트 1:1 |
| **활성화 대기 LEGEND 1 (P180 경니시우스)** | `units` | 실아트 1:1 — **아트는 있고 시드는 아직 `active:false`** |
| 비활성 LEGEND 14 / DIA 25 | `characters` | 현행 원화(1:1 / 포지션 풀) |
| 아트 미입고 LEGEND 2 (P174·P178) | — | **미매핑 = 이니셜 폴백**(의도) |
| GOLD·SILVER·BRONZE 133 | `units` | `default-unit` 공용(도트, `pixelArt`) — ⚠️ **매핑은 있지만 화면엔 안 그린다**(#285 정책, 위 절) |

- ⚠️ **"활성"과 "아트 있음"은 별개 축이다**(3차 입고 2026-07-29). 운영 순서가 "아트 머지 → 배포 →
  어드민 API 로 활성화"(#207 파트 A)라서 **비활성인데 아트가 있는 중간상태가 정상**이다. web 은
  아트를 **매핑 유무로** 그린다(활성 여부로 분기하지 마라) — 활성화 토글이 켜지는 순간 아트가
  같이 떠야 하기 때문. 도감의 `off` 뱃지만 `active` 를 본다.
- 발행물에 `pendingCatalog:true` 인 유닛(현재 `seokdijk`)은 **대응 선수가 카탈로그에 없어** 매핑이
  없다 — web 에서 그려지는 자리가 아예 없다. 채번되면 매핑만 붙으면 된다.

- ⚠️ **`units[id].card.kind` 가 분기 권위다. 유닛명을 코드에 하드코딩하지 마라** — 에픽 초기
  인벤토리가 "완성 카드 3종"으로 잘못 적혔다가 2종으로 정정됐고, 그 뒤 재발행으로 **0종**이 됐다.
  이름을 박아 뒀다면 매번 깨졌을 자리다.
  `complete` = 프레임이 **이미 구워진** 통짜 → `frame-<GRADE>.png` 를 깔면 **프레임이 두 겹**이
  된다. `frameless-art` = 기존 합성 경로 그대로.
  **현재 발행 구성 = `frameless-art` 6종 / `complete` 0종**(#207 재발행: 보날두·욱링엄의 구워진
  숫자·별이 실데이터와 어긋나고 종횡비가 튀어서 프레임리스로 재발행). `complete` 분기는 **지우지
  않는다** — 발행측이 언제든 다시 실을 수 있고, 실물이 0종이라 실 manifest 기반 단언은 공허해지므로
  **픽스처 manifest 로 계약을 태운다**(`full-art.test.ts`·`FullArtCard.test.ts`·`char-manifest.test.ts`).
- ⚠️ **`fit:"fill"`(프레임리스 아트) 컨테이너는 아트 창이다, 카드 통짜가 아니다.** 통짜(`inset:0`)에
  `object-fit: contain` 을 걸면 2:3 아트가 226×425 카드 안에서 세로로 남아 **네임플레이트를 덮는다**
  (실측 침범 12~34px, #207 재발행 실화면에서 발·공이 이름을 가렸다). `variant="art"`·완성 카드만
  통짜가 맞다(그 박스 자체가 아트 박스라서). 계약 = `FullArtCard.test.ts` "아트 창 안에 갇힌다".
- **경기장(`viewer-skins`)은 두 축을 다 태운다(#218).** 페이로드가 `atlases:[{url,tile}]` + 셀의
  `atlas` 인덱스라 축마다 자기 시트를 싣는다(viewer-core 멀티 아틀라스). 그래서 활성 LEGEND
  실아트가 덱·도감뿐 아니라 **경기장에도** 뜬다.
  - ⚠️ **판정 근거는 #285 로 등급으로 옮겨갔다**(맨 위 노출 정책 절). `unitIsSharedDefault`(발행물
    `forGrades`)는 등급표가 없는 경로용 **백스톱**으로만 남는다. 셀이 없는 선수는 뷰어가 팀색 원으로
    그리므로 "빼는 것"이 곧 정책의 표현이다.
  - **등번호(`nums`)는 아트 유무와 무관하게 전원 싣는다.** 안 실으면 코어가 `playerId` 에서 번호를
    파생해 실경기 id("P173")가 토큰을 덮는다 — #218 제보("아이콘 안 보임")의 절반이 이거였다.
  - 계약 = `e2e/p218-legend-arena.spec.ts`(픽셀 판정: 폴백 가시성 · 얼굴 렌더 · bg 클립/부분 열화)
    + `viewer-skins.test.ts` + `packages/engine/dev-viewer/qa-skin.test.ts`.
  - ⚠️ **경계**: 이 배선의 절반은 `packages/viewer-core/**`(QA 도메인)에 있다. 위 "뷰어 코드 수정 금지"의
    예외는 **이슈로 승인된 스코프일 때만** 이다 — #218 이 owned-glob 에 `packages/viewer-core/**` 를
    명시해 코어 스킨 계약(`setSkin` 페이로드·토큰 렌더)을 여기서 고쳤다. 승인 없이 코어를 고치지 말고
    이슈를 레이즈해라(#57 원칙). 코어를 건드리면 루트 `npx playwright test`(뷰어 계약)도 같이 돌린다.
- 얼굴 아이콘은 `iconBackground` 를 존중한다. **해석은 자리마다 다르다 — 같은 플래그, 다른 결론**:
  - **정적 UI**(`CharAvatar`, 32~96px): `opaque-dark` = **원형 마스크 금지**, 라운드 사각(`.opaqueBg`).
    크게 보이는 자리라 원형으로 자르면 배경 전제로 번진 글로우 링·수염선이 잘린 게 눈에 띈다.
  - **경기장 토큰**(viewer-core, 지름 ~32px): `opaque-dark` = **원형 클립**(`cell.bg`). 여긴 팀색 링
    안에 앉는 자리라 안 자르면 불투명 배경이 **사각 덩어리**로 링을 뚫고 나온다. 글로우 손실보다
    토큰 형태가 우선(#218 실화면 판정 — 독립 QA PASS).
  - 새 소비자를 만들면 어느 쪽인지 **여기에 적어라**. 플래그만 보고 한쪽 규칙을 복사하면 반대쪽이 깨진다.

경계는 의견이 아니라 **계약**이다 — `e2e/p3-card-art.spec.ts` 가 밀집 UI 에 풀아트가 0개임을 강제하고,

## 덱 없는 유저의 게임 시작 (#286 W3.5)

**`GamePage` 는 덱을 조회조차 하지 않았다.** 그래서 덱 없는 유저가 [게임 시작]을 누르면 서버 404 가
**막다른 에러 토스트 한 줄**로 끝났다(hero 라이브 제보).

⚠️ **서버가 관용적이어서 생긴 문제가 아니다.** `MatchService` 의 매치 생성 3경로(연습·리그·원정)는
전부 `getActiveDeck` 으로 시작하고 덱이 없으면 던진다 — **거부는 이미 하고 있었다**. 없던 것은
**안내**다. 서버를 고치러 가기 전에 이 사실부터 확인해라.

### 근원은 온보딩 쪽이다 (둘)

1. **온보딩을 끝까지 안 본 유저.** 덱은 `POST /api/me/tutorial-complete` 가 지급하는데, 그 호출
   조건이 "모든 스텝 `seen`" 이고 마지막 두 스텝은 **덱 화면에 들어가야만** 보인다. 홈에서
   [다음]만 누르고 닫으면 완료 저장이 안 되고 → **덱 미지급**. `tutorial-steps.ts` 머리말에
   설계된 동작으로 적혀 있다 — 그 사이 유저가 [게임 시작]을 누를 수 있다는 걸 못 봤을 뿐이다.
2. **보유 11명 미만.** 서버가 이 상태를 **알고 통과시킨다**(`OnboardingService`: *"유저가 카드를
   모으면 직접 구성할 수 있다"*). 이 유저는 자동완성을 눌러도 저장이 안 되므로 **덱 화면으로
   보내면 안 된다** — 할 수 없는 일을 시키는 안내가 된다.

판정은 `common/deckless.ts`(순수): `deckMissing` · `decklessBranch` · `isDeckRequiredError`.

⚠️ **배선은 `useDecklessGuard()` 훅 하나로 한다** — 처음엔 게임 탭의 연습 경로에만 걸었다가
독립검증에 잡혔다(MAJ-2): `/league`·`/away` 는 북마크로 직접 들어올 수 있고 거기서도 매치를

버튼을 추가하면 `guard()` 를 앞에, `catchReject(err)` 를 `onError` 앞에, `dialog` 를 렌더한다.

- ⚠️ **404 를 전부 삼키지 않는다.** 전용 코드가 아니면 **문구까지** 본다 — 안 그러면 엉뚱한 실패까지
  "덱을 만드세요"로 덮어 진짜 원인을 가린다. W4 가 `DECK_REQUIRED` 를 붙이면 문구 의존은 사라지되
  **가지는 남긴다**(구 서버가 살아 있는 동안 web 이 먼저 나갈 수 있어야 한다).

## 재화 표기 — 서버 주도 (#232)

**화면에 재화 심볼·이름·아이콘·가격을 적지 마라.** 전부 `GET /api/config` 에서 온다.

| 쓸 것 | 자리 |
|---|---|
| `<Amount code={...} value={n} icon? />` (`common/Amount.tsx`) | 금액을 그리는 **모든** 자리 |
| `useCurrency(code)` → `{symbol,name,icon,...}` | 문장 안에 이름/심볼이 필요할 때 |
| `formatAmount` · `shortageMessage` · `withIga/withEulReul/withEunNeun` (`common/currency.ts`) | 순수 문자열이 필요할 때(원장·테스트) |
| `useAppConfigValue()` (`common/AppConfigContext.tsx`) | 가격·플래그(`shop.gacha`·`shop.dice`·`shop.gemTopup.enabled`) |

- **코드 상수는 `CURRENCY_POINT`/`CURRENCY_GEM` 둘뿐이고 그건 표기가 아니라 키다.** `"P"`·`"💎"`·
  `"포인트"`·`"젬"` 을 다시 적는 순간 서버 주도가 깨진다.
- **가격 미러를 만들지 마라.** `growth-config.ts` 에 `DICE_BUY_COST = 500` 이 있었고 서버가 5,000 으로
  바뀐 뒤에도 남아 화면이 "500 P 로 구매"를 그렸다 — 눌러 성공하면 지갑이 10배로 줄었다(#213).
  뽑기도 같은 방식으로 "300 P" 라고 쓰면서 다이아 300 을 뺐다.
- **금액과 재화는 항상 같이 온다**(`Price{currency,cost}` · `TradeSlot.speedupCurrency`). 클라가 단위를
  추측하는 자리를 만들면 위 사고가 재발한다.
- **잔액 게이팅은 결제 재화 기준.** 무료재화 잔액으로 유상재화 상품을 잠그면 유저가 살 수 있는데도 잠긴다.
- **순수 모듈은 표기를 주입받는다** — `seasonRewardView(reward, formatPoints)`(기본값 = **단위 없는
  숫자**라 주입을 잊어도 틀린 단위가 새 나가지 않는다) · `formatPoints(value, unit)`(unit **필수** —
  타입이 강제한다).
- **폴백**: config 를 못 받으면 `<Amount>` 는 **코드를 그대로** 노출한다(`POINT 300`). 흰 화면도, 하드코딩
  "P" 복귀도 아니다. provider 밖(단위 테스트)도 같은 경로를 탄다 — 그래서 컴포넌트가
  QueryClientProvider 를 요구하지 않는다.
- ⚠️ **`골드`/`다이아` 는 카드 등급 이름이기도 하다**(hero 확정 C1: 재화는 심볼 `G`/`Z` 우선, 등급 라벨은
  현행 유지). 재화 문자열을 지운다고 `GRADE_LABELS` 까지 건드리지 마라 — 계약이 그걸 잡는다.
- **`/api/config` 는 공개 엔드포인트다(인증 불필요).** 앱 부팅 시 **한 번** 부르는 값이라 로그인 전에
  401 을 맞으면 재조회 트리거가 없어 **그 세션 전체**가 코드 폴백으로 굴러갔다(독립검증 BL-1 —
  신규·세션만료 유저의 첫 진입이 전부 그 경로). 그래서 ① 서버에서 인증 제외 ② 이 경로의 401 은
  **세션을 파기하지 않는다**(`isSessionNeutralEndpoint` — 공개 응답 하나가 로그인 유저를 튕겨내면 안 된다)
  ③ 쿼리에 재시도·포커스 갱신을 열어 뒀다. 셋 다 계약이 있다.
- **가입 지급액도 서버에서 온다**(`grants.initialPoints/initialGems`). 클라 상수 3,000 이 박혀 있었고
  유상재화 지급은 **표기조차 없었다** — 운영이 무배포 override 로 지급액을 올린 뒤에도 화면은 그대로였다.
- 계약 = `e2e/currency-display.spec.ts`. **값이 아니라 "데이터를 따라오는가"를 본다** — config 를 `Ω/Ξ` 로
  목킹해 전 화면이 따라오지 않으면 실패한다(하드코딩을 되돌리면 실제로 7/10 이 깨진다). 목 헬퍼 =
  `e2e/app-config-mock.ts` — **새 목 스펙이 상점/지갑을 그린다면 이걸 실어라**(캐치올 `{}` 면 가격을
  모르는 폴백 화면을 보게 된다).
## 공지 팝업 본문 — 접힘과 그 신호 (#292)

**페이징은 #248 부터 있었다**(중첩 스택 · `1 / 2` 페이저 · 점 · `닫기`=다음 장). 그러니 "공지가 한 장에
다 들어 있다"는 제보가 오면 **web 이 아니라 활성 공지가 몇 건인지부터 봐라** — 실제로 그게 원인이었다
(라이브 활성 1건에 캐릭터 소개 + 패치 목록이 한 몸으로 들어 있었다).

- **본문 높이를 `vh` 로 박지 마라.** 예전 `max-height: 46vh` 는 화면이 남아도 본문을 묶어 **다 들어갈
  수 있는 공지까지 접었다**(390×844 에서 경니시우스 장 529px 중 141px 이 이유 없이 잘렸다). 지금은
  **카드가 쓰고 남은 만큼**을 본문이 가져간다(`.bodyArea`/`.body` 의 `flex:1 1 auto; min-height:0`).
- ⚠️ **그러려면 `.stack` 이 플렉스여야 한다.** 높이가 auto 인 부모에 걸린 `.card { max-height:100% }` 는
  퍼센트가 `none` 으로 풀려 **카드가 화면 밖으로 자란다**. 그동안 `46vh` 가 그 사실을 가려 주고 있었을
  뿐이라, 본문을 늘리는 순간 24시간 버튼이 화면 아래로 나간다.
- ⚠️ **"스크롤바를 넣었다"고 쓰지 마라 — 폰에서 보장되지 않는다.** iOS 사파리는 `::-webkit-scrollbar`
  를 아예 안 그리고, 모바일/헤드리스 크롬은 오버레이라 **폭이 0**이다(실측 `offsetWidth-clientWidth===0`).
  막대는 **데스크탑 보조**이고, 폰에서 실제로 일하는 신호는 **하단 페이드**(`data-more`)다.
  그래서 계약도 막대가 아니라 페이드·실측 높이를 본다 — 막대를 단언하면 **검사하는 척하며 항상 통과**한다.
- 페이드는 **끝에 닿으면 꺼진다**. 다 읽었는데 남아 있으면 그게 또 "아직 더 있다"는 거짓 신호다.
  판정은 스크롤 이벤트 + `ResizeObserver`(스크롤러 **와 그 내용** 둘 다) + 이미지 `load` — 마운트 때 한 번만
  재면 **늦게 오는 히어로 이미지**가 본문을 두 배로 늘려도 신호가 안 붙는다(라이브 공지가 정확히 그 모양).
- 계약 = `e2e/p292-notice-scroll.spec.ts`(변이체 4종 — `46vh` 복원 · `.stack` 플렉스 제거 ·
  `data-more` 상수화(양방향) · 1회 측정 — 전부 사망 확인). **픽스처 이미지는 실제 에셋을 써라** —
  더미 1×1 PNG 는 고유 크기가 1px 이라 `max-width:100%` 아래에서 1px 로 그려져 **넘치는 상황 자체가
  안 만들어진다**(그래서 계약 절반이 조용히 공허해진다).

### ⚠️ "스크롤이 안 된다" 제보의 두 번째 원인 — 팝업이 **보이는 화면**보다 크다 (#386)

`position: fixed; inset: 0` 의 높이는 **레이아웃 뷰포트**다 — 아이폰13이면 844px, 즉 브라우저 툴바가
덮고 있는 부분까지 포함한 값이다. 그래서 카드가 808px 로 자라고 본문 스크롤 여유는 **9px** 밖에 안
남는데(실측), 정작 보이는 높이는 660~745 라 **본문 꼬리와 [닫기]가 툴바 밑으로 들어간다**. 잘린 것이
스크롤러 **바깥**이므로 아무리 쓸어올려도 안 움직인다. 스크롤러는 멀쩡한데 제보는 "스크롤이 안 돼"다.

- 그래서 **딤은 `inset: 0` 그대로 두고, 아래 여백으로 툴바 몫만 비운다**(팝업·목록 둘 다):
  `padding-bottom: calc(18px + env(safe-area-inset-bottom, 0px) + (100lvh - 100svh))`.
  `100lvh − 100svh` = 접히는 브라우저 UI 가 차지할 수 있는 최대 높이이고, `env(safe-area-inset-bottom)`
  은 홈 인디케이터 몫이라 **축이 달라 이중계상이 아니다**. 카드(`.stack { max-height: 100% }`)는 그
  컨텐트 박스 안에 갇히고, 넘치는 몫은 전부 본문 스크롤러가 받는다. 데스크탑은 `lvh == svh` 라 0 —
  동작 변화가 없다(computed 실측: 390×844·1280×800 둘 다 `padding-bottom: 18px`).
  같은 함정을 관전 셸이 먼저 겪었다 — `match/stage/StageShell.module.css` 머리말이 SoT 다.
  ⚠️ `dvh` 금지: 툴바가 접힐 때마다 높이가 변해 **읽는 도중 본문이 리플로우**한다.
  ⚠️ `lvh`/`svh` 미지원 브라우저(iOS Safari &lt;15.4 · Chrome &lt;108)에서는 이 선언이 통째로 무효가 돼
  **수정 전 동작으로 폴백한다** — `@supports` 로 막을 수 있는 성질이 아니다(대안이 없다). 알고 남긴 것.
- ⚠️ **이 회귀는 브라우저 자동화로 재현되지 않는다** — 헤드리스에는 툴바가 없어 `lvh == svh` 다
  (CDP `Emulation.setVisibleSize` 는 no-op 임을 실측 확인). 그래서 계약이 **두 겹**이다:
  `src/lobby/notice-viewport.test.ts`(CSS 소스 스캔 — 약속을 지키고 있나) +
  `e2e/p386-notice-viewport.spec.ts`(390×664 실터치로 실제 읽히나). 한쪽만 두면 못 잡는다.
  ⚠️ 그 e2e 가 **폰 뷰포트에서 도는지**부터 확인해라 — `test.use` 에 `viewport:` 키를 빠뜨리면
  Playwright 는 조용히 데스크탑으로 돌리고 **그래도 전부 초록이다**(넓은 창에서는 본문이 알아서
  넘치니까). 실제로 그 상태로 4/4 통과했고 독립검증이 잡았다. 지금은 `beforeEach` 가 전제를 단언한다.
- 진단 순서: **본문 `scrollHeight - clientHeight` 를 먼저 재라.** 그 값이 한 자릿수인데 "안 내려간다"면
  스크롤러가 아니라 **카드 높이**가 범인이다(#292 로 달려가면 멀쩡한 코드를 뒤지게 된다).
- ⚠️ **오버레이 자체를 `height: 100svh` 로 줄이면 안 된다**(처음에 그렇게 썼다가 독립검증이 잡았다).
  툴바가 접히는 순간 그 아래 띠에 **딤이 안 깔려 뒤 화면이 노출되고**, `aria-modal` 다이얼로그인데
  그 자리를 탭하면 백드롭 닫기도 아닌 **뒤 홈 화면이 눌린다**. 딤은 `inset: 0` 그대로 두고,
  **아래 여백으로 툴바 몫(`100lvh − 100svh`)을 비운다**.

### ⚠️ 세로 플렉스 목록은 넘칠 때 **스크롤되지 않고 눌린다** (#386, 공지 다시 보기)

`NoticeCenter` 의 `.list` 는 `display:flex; flex-direction:column; overflow-y:auto` 인데, 자식 `li` 의
기본값이 `flex-shrink: 1` 이라 **내용이 넘치면 목록이 스크롤되는 대신 항목이 눌렸다**. 게다가
`.item { overflow: hidden }` 이라 눌린 만큼이 **소리 없이 잘렸다** — 오시야스 공지를 펼치면 항목이
**641 → 368**(clientHeight, 390×664·공지 4건 표본) 으로 눌려 히어로 이미지(321) 아래 글이 통째로
사라지고, `scrollHeight === clientHeight`(505/505) 라
**스크롤도 안 됐다**(= 다 읽을 방법이 없다).

- 고치는 곳은 `.item { flex: 0 0 auto }` 한 줄이다. 스크롤 컨테이너가 **세로 플렉스**면 자식에
  `flex-shrink` 를 명시하지 않는 한 이 함정이 항상 있다 — 새 목록을 만들 때 같이 확인해라.
- ⚠️ 계약은 "목록이 넘친다"만으로 부족하다 — 눌리면 **넘치지 않으므로** 그 단언은 오히려 통과한다.
  `펼친 항목의 scrollHeight ≤ clientHeight`(=안 잘렸다)를 같이 봐야 죽는다.
  ⚠️ 그리고 **활성 공지 1건으로는 목록이 안 넘친다**(실측 505/505) — 넘치는 표본을 만들어 재라.

## 공지 공유 딥링크 — `/share/notice/{id}` (#298 · 에픽 #293)

### 로비 팝업 큐에 **주입하지 않는다** — 전용 화면이다

로비 팝업은 **저절로 뜨는** 것이라 억제(닫기·24h)·튜토리얼 홀드·팝업 큐가 전부 걸려 있다.
딥링크는 성격이 정반대다 — **유저가 링크를 눌러 명시적으로 요청한** 공지이고 그게 방문 목적이다.
큐에 밀어 넣으면 그 규칙들을 하나씩 예외 처리해야 하고, **그 예외가 곧 로비 팝업의 회귀**가 된다.
그래서 표시 경로를 분리하고 억제 저장소는 **읽지도 쓰지도 않는다**(`NoticePopup suppressible={false}` —
[24시간 안 보기] 버튼도 그리지 않는다).

### 복귀 경로 — `src/auth/return-to.ts` 한 곳

- 붙이기 `loginPathWithReturn` · 풀기 `resolveReturnTo` · 검증 `safeReturnTo` 가 한 파일에 모여 있다.
  `RequireAuth` 가 `?returnTo=` 로 목적지를 들려 보내고, `LoginPage` 의 **착지점 두 곳**
  (일반 로그인 / 스타터팩 확인)이 그것을 쓴다. ⚠️ **한쪽만 고치면 신규 유저의 딥링크만 조용히
  로비로 샌다** — 두 경로가 갈라져 있다는 걸 기억해라.
- ⚠️ **`startsWith("/")` 로 판정하지 마라.** `//evil.test` 가 그 검사를 통과하고 브라우저는 그걸
  **외부 호스트**로 읽는다(`/\evil.test` 도 `//` 로 정규화된다). 그래서 **경로 화이트리스트** +
  `//`·`\`·`..`·제어문자 거절이다. 계약이 그 변이를 직접 죽인다(`return-to.test.ts`).
- 화이트리스트를 넓힐 땐 `PREFIX_ALLOWED` 에 접두사를 더한다 — 새 딥링크 화면을 만들면 여기도 같이.

### 상태는 서버가 정한다 — 화면은 문구만 고른다

LIVE 200 / EXPIRED·OFF **410** / SCHEDULED·DELETED·없는 id **404**(#297).
기간을 클라가 다시 계산하지 않는다 — 그러면 **기기 시계가 진실이 된다**(`notice-logic.ts` 머리말과 같은 규율).

- 판정은 순수 함수 `shareNoticeStateOf` 한 곳. **410 과 404 의 문구가 다른 것이 계약이다** —
  유저가 "기간이 끝났다"와 "링크가 잘못됐다"를 구분할 수 있어야 한다.
- ⚠️ **200 인데 모양이 아닌 응답**(구 서버·프록시의 `{}`)을 `notfound` 로 흡수하는 것이 핵심이다.
  흘리면 `notice.title` 접근이 던져 **흰 화면**이 된다(#274 부류). 정규화는 목록과 같은
  `normalizeNotice` 를 쓴다 — 단건만 따로 만들면 규칙이 갈라진다.
- 어느 분기에서도 화면이 비지 않는다: 로딩·만료·없음·손상·에러 전부 **문구 + 하단 네비 + [로비로 가기]**.
  500·네트워크 단절을 "없는 공지"라고 **거짓말하지 않는다**(별도 `error` 상태).
- 조회 훅은 `retry: false` 다 — 404/410 은 **정상 응답**(그 자체가 화면에 옮길 정보)이라 재시도가 무의미하다.

계약 = `e2e/p293-notice-deeplink.spec.ts` + `src/auth/return-to.test.ts`.

## 고레어 뽑기 이펙트 (#250)

**다이아 이상**이면 카드가 곧바로 뒤집히지 않는다 — 빛이 모인 뒤에 열린다. 레전드는 그 위에 한
단계가 더 붙는다:

```
DIA    : A(charge) ─────────────→ 개봉 → 잔광
LEGEND : A(charge) → B(surge) ──→ 개봉 → 잔광 → 확장 피날레(시트 전체)
```

- **레전드는 A 구간에서 다이아 색으로 위장한다**(실측: 800ms 프레임이 다이아와 픽셀상 동일).
  ⚠️ **같은 A 안에서 색만 바꾸면 안 된다** — 그러면 기대감 길이가 다이아와 같아져 반전이 성립하지
  않는다(hero 지적으로 구조를 다시 짰다). A 가 끝나야 B 로 가고, **B 가 끝나야 열린다**.
  위장은 별도 상태가 아니라 **단계에서 파생**된다(`isDisguised`) — 격상 시점을 튜닝할 값이 없다.
- **위장은 색 하나가 아니다.** 격상 전에는 레전드 전용 층(2중 링·2중 궤도)도 같이 숨는다 —
  스테이지가 자기를 `data-fx-tier="epic"` 으로 **선언**해서 CSS 전용 규칙이 통째로 안 걸린다.
- **전 튜닝값이 `FX_CONFIG`(`common/gacha-fx.ts`) 한 곳**: 임계·변주(A/B/C)·B 길이·격상색·스태거·
  파티클 수. `'에픽 이상'` 의 실체는 `threshold: "DIA"` **한 줄**이다 — 등급 비교를 컴포넌트에
  박지 마라(임계가 두 곳이 되면 조용히 어긋난다).
- 카드 1장 = `common/RevealFxCard`. **시안 프리뷰(`/design/gacha-fx`)와 제품이 같은 컴포넌트를 쓴다** —
  프리뷰가 자기 카드를 따로 그리면 hero 가 컨펌한 그림과 배선된 그림이 갈라진다(#209 와 같은 원칙).
- `GachaReveal` 이 소유하는 건 **언제 트리거하나**뿐. "트리거됨"(`reveal-logic`, 순수)과 "앞면이
  보임"(카드의 자기 시계)은 **다른 것**이다. 확인 버튼은 **모든 카드의 연출이 끝나야** 나온다.
- **조작은 현행 유지**(hero 확정 2026-07-29): 어느 카드를 눌러도 **다음 순서** 카드가 열린다.
  대신 **이펙트가 순서에 맞아야** 해서 순차 경로에 **개봉 게이트**가 있다(`startable` — 앞 카드가
  열린 뒤에 시작). ⚠️ 없으면 연타 시 순서가 실제로 뒤집힌다: 앞이 고레어라 2.2초 빛을 모으는 동안
  뒤의 비고레어는 지연 0 이라 먼저 열린다(실측 `1,2,4,0,3`). **일괄 공개에는 이 게이트를 걸지 마라** —
  거긴 일부러 인덱스 순이 아니다(등급 순 스태거, 클라이맥스가 마지막).

### 이 코드가 조용히 깨지는 자리 (전부 실제로 당했다)

- ⚠️ **단계 경계는 중복되면 안 된다**(`fxMarks`). `surgeOf("epic")=0` 이라 소박하게 적으면 경계가
  겹쳐 **단계 통지가 2회** 나가고, 소비자의 완료 집계가 부풀어 **확인 버튼이 피날레보다 먼저 뜬다**
  → 레전드 클라이맥스가 통째로 잘린다(실측 확인 2362ms vs 피날레 3373ms). 집계 쪽도 **집합**으로
  중복에 무감각하게 뒀지만, **두 층 각각 단독 계약**이 있다(한쪽만 남기고 "단순화" 하지 마라).
- ⚠️ **`key={phase}` 를 지우지 마라**(`GachaFx.tsx`). CSS 애니메이션은 `animation-name` 이 그대로면
  클래스가 바뀌어도 **재시작하지 않아서**, A 와 B 가 같은 키프레임을 쓰는 이 구조에서는 B 구간이
  **통째로 빈 화면**이 된다(속성은 멀쩡해서 단계·색만 보는 계약으로는 안 잡힌다).
- ⚠️ **모션 최소화는 끄는 게 아니라 축약이다.** 연출을 지우면 "고레어를 뽑았다"가 화면에서 사라진다.
  이 경로는 **두 번 깨졌다** — ①키프레임 이름만 갈아끼워 duration 을 물려받아 87ms 깜빡임이 됐고
  ②단계 추가 시 `.ph_surge` 를 빠뜨려 B 가 신호 0 + 카드만 흔들림이 됐다. **단계를 추가하면
  reduced 블록의 두 목록(모션 제거·정적 신호)에 둘 다 넣어라.** B 는 A 보다 **밝아야** 한다
  (움직임을 못 쓰니 밝기가 유일한 격상 신호다 — 계약이 `peak(B) ≥ peak(A)` 를 본다).
- ⚠️ **`test.use({ reducedMotion })` 는 이 설정에서 안 먹는다**(실측 `matchMedia === false`).
  `page.emulateMedia` 를 쓰고, **매치 여부 자체를 단언**해라 — 안 그러면 모션 최소화를 검사하는 척하며
  평상시 경로를 통과시킨다.
- **비고레어는 지연 0**을 유지한다(대조군이 느려지면 전체 체감이 나빠진다).
- 뽑기 결과를 단언하는 스펙은 **연출 종료를 기다려야** 한다 — 공용 `e2e/gacha-reveal-settle.ts`
  (확인 버튼 = 앞면이 전부 확정된 신호). 클릭 직후를 단언하면 고레어는 아직 뒷면이다.

계약 = `common/gacha-fx.test.ts` + `e2e/p250-gacha-fx.spec.ts`. **시간 임계를 스펙에 적지 마라** —
config 를 튜닝하는 순간 거짓 실패가 된다. 새 계약을 넣을 땐 **자기가 막으려는 결함을 실제로 죽이는지**
변이로 확인해라(여기 계약 여러 개가 처음엔 공허하게 통과했다).
## 리그 디비전 표시 (#262 · #268)

승급/강등 구조를 화면에 그리는 자리. **규칙과 이름은 전부 서버가 준다** — `GET /api/league` 의
`season.{division, divisionName, promoteRankMax, relegateRankMin}` 과 `GET /api/me` 의 `league`.

- **컷을 클라에 적지 마라.** 규칙은 서버 config, 사다리 표는 data 발행물이라 바뀐다. 복제하면
  "승급권"이라 칠해 놓고 실제로는 강등되는 화면이 된다. 계약이 이걸 직접 잡는다 — 응답 컷을
  1~4위/7위로 바꾸면 **구 규칙이면 유지였을 4위·7위가 승급·강등으로 따라 움직인다**.
- **디비전 이름을 level 로 만들지 마라**(없으면 `D5` 폴백). **다음 디비전 번호도 계산하지 마라** —
  사다리 양 끝 클램프가 서버 규칙이라 `level-1` 을 만들면 최상위에서 없는 디비전을 표시한다.
- **구 서버 폴백이 최우선**: 필드 부재 → 디비전 UI 통째로 소멸, 순위표는 그대로. `division` 은
  있는데 컷이 없으면 **뱃지만** 띄우고 구역은 **안 칠한다**(컷을 모르는데 칠하면 거짓말).

### ⚠️ 사다리 끝 — 화면이 서버와 반대 사실을 말한 적이 있다 (BL-1)

입문 디비전엔 강등이, 최상위엔 승급이 **없다**(서버가 컷을 null 로 잘라 보낸다). 그걸 무시하면
**신규 유저 전원**이 18라운드 내내 없는 강등 위협을 보고, 최상위 우승이 "한 단계 위로 갑니다"가 된다.
**재발 경로가 둘**이라 둘 다 계약이 있다:
1. 시즌 DTO 의 컷을 클라가 추측(`?? 2` / `?? 9`) — 하지 마라.
2. **`/api/me` 의 디비전으로 구역을 칠하기**(#268) — `/api/me` 는 시즌 밖 값이라 **컷 정보가 없다**.
   `pickMeDivision` 이 `hasRules=false` 로 만드는 이유이고, 뱃지만 띄우고 색칠은 하지 않는다.

## 경기 화면 정보 시트 · 후반 지시 미리작성 (#284)

**정보 패널에 토글은 없다.** 시트는 상시이고 **무엇이 탭인지는 매치 상태가 정한다**
(`stage-state.tabsFor(state, statePanel)`). 유저 설정이 아니다.

| 상태 | 탭 |
|---|---|
| `FIRST_HALF` | 통계 · 로그 · **후반 지시** |
| `HALFTIME`(`H1_BREAK`) | **감독** · 경기장면 · 통계 · 로그 |
| `SECOND_HALF` | 통계 · 로그 |
| `FINISHED` | **결과** · 통계 · 로그 |

- ⚠️ **`hmb.stage.toggles`·`stage-toggle-*` 를 되살리지 마라.** 하단 토글바와 시트 탭바가 똑같이 생겨
  화면에 같은 줄이 두 개로 떴다(hero 캡처). #169 AC-W1-1 의 "기본은 경기장면만"은 **뒤집힌 결정**이다 —
  `match-stage.spec.ts` 헤더에 무엇이 뒤집혔고 무엇이 그대로인지 적혀 있다(무대 생존·문서 스크롤 0은 그대로).
- **표시 순서와 기본 선택은 다른 축**이다. 순서 = 통계·로그·후반지시, 기본 = **로그**(`DEFAULT_INFO_TAB`).
  상태 패널(감독·결과)이 있으면 그게 이긴다. `resolveActiveTab` 이 그 우선순위를 소유한다.
- **`후반 지시` 탭은 전반에만**(`briefTabVisible`). 감독시간엔 `감독` 탭이 같은 입력을 **프리필된 채로**
  갖는다 — 둘을 같이 띄우면 같은 문장을 고치는 칸이 둘이 된다. 후반·종료는 서버가 409.

### 미리작성 → 감독시간 인계 (`halftime-draft.ts` · `useHalftimeDraft.ts`)

- **저장 버튼이 없다. 타이핑이 멎으면 자동 저장된다.** hero 의 "감독시간 만료 시 저장" 안은 기각됐다:
  만료는 **서버 이벤트**이고(`MatchClockSweeper` — *"아무도 보고 있지 않은 매치도 … 후반 시뮬로
  넘어간다"*, `sweep-interval-ms: 1000`), 탭이 닫혀 있으면 저장할 주체가 없다. 열려 있어도 전이 후
  도착한 저장은 **409**(허용 = FIRST_HALF·HALFTIME). ⇒ **유저가 확실히 화면에 있는 동안** 보낸다.
- 그 대가로 **실패도 조용해질 수 있다** → 상태 줄(`brief-save-status`)을 지우지 마라. 자동 저장이
  실패했는데 화면이 조용하면 유저는 적어둔 게 서버에 있다고 믿은 채 감독시간을 놓친다.
- **선수 칩 목록의 출처는 `match.userDeckSnapshot`** — 서버가 `POST /prompts{scope:player}` 의
  playerId 를 같은 스냅샷으로 검증한다(`snapshotPlayerIds`). 현재 덱으로 만들면 전반 중 덱을 고친
  유저에게 **400 나는 칩**을 보여준다. 스냅샷 없는 구 매치만 덱 폴백(#276 `boardUsable` 과 같은 규율).
- **프리필은 playerId 로 붙는다(슬롯 아님)** — #276 이 감독시간 자리 바꾸기를 열어서 슬롯 인덱스는
  움직인다. 사람에게 한 말이 자리를 따라가면 안 된다(`applyDraftPrompts` 계약이 그걸 잡는다).
- **초안은 셸(`StageShell`)이 소유한다.** 두 패널의 공통 조상이 거기뿐이고, FIRST_HALF → HALFTIME
  전이에서 그 컴포넌트는 언마운트되지 않아 초안이 끊기지 않는다.
- `sent` 를 따로 들고 **달라진 것만** 보낸다(`pendingSaves`) — 안 그러면 [후반 시작] 앞에 순차 POST
  12건이 붙는다(값이 같아 서버는 무해하지만 느린 건 무해하지 않다).

### 감독시간 화면의 두 층 — 실패 안내는 **스크롤 밖**이다 (#294 MAJOR)

`HalftimePanel` 은 `[스크롤 영역] + [고정 CTA]` 두 층이다. `POST /halftime` 실패 토스트가 스크롤
영역 **끝**에 있던 동안, CTA 가 그 위에 앉아 유저는 그것을 **볼 방법이 없었다**(실측 alert bottom
875.8 > 뷰포트 844). 화면이 클릭 전과 완전히 동일해서 "버튼 먹통"으로 읽혔다.

- 실패 안내는 `.ctaAlert`(CTA 와 **같은 층**, `flex:none`)에 둔다. 안내가 없으면 렌더 자체가 없다.
- ⚠️ CTA 를 스크롤 안으로 되돌리지 마라 — 그건 프롬프트를 안 덮으려는 #244 결정이다(BL-1).
- ⚠️ 로스터 조회 실패 토스트는 스크롤 **안**에 그대로 둔다(그 경우 CTA 자체가 비활성이고,
  더 건드리면 #284 시트 지오메트리 계약과 다툰다). 구멍은 **뮤테이션 실패 경로**뿐이었다.
- ⚠️ 계약은 `toBeVisible()` 로 쓰지 마라 — 뷰포트 밖도 통과한다. **좌표 + `elementFromPoint`** 로 잰다.

### 감독시간 보드에서 벤치의 뜻은 모드마다 다르다 (#294 MINOR-2)

| 모드 | 벤치 | 왜 |
|---|---|---|
| `say`(감독의 한마디) | **편다** | 벤치에게 쓴 지시를 **열람·수정**해야 한다. 교체가 일어나는 시점이 감독시간이라 들어올 선수에게 한 말을 그 자리에서 보는 게 자연스럽다 |
| `sub`(교체) | 편다 | 넣을 선수를 고른다 |
| `move`(자리) | **접는다** | 자리 바꾸기는 **선발끼리**다 — 넣을 선수를 고를 일이 없다 |

전반 `후반 지시` 탭은 원래 벤치에게도 쓸 수 있었고 서버도 그렇게 검증한다(로스터 = 선발+벤치).
빠져 있던 건 **동작이 아니라 열람 경로**였다.
- ⚠️ 벤치를 펴면 `DeckEditor` 의 **벤치↔선발 드래그 차단**이 도달 가능해진다(그 파일 주석이
  *"hideBench 가 바뀌는 순간 이 줄이 유일한 방벽"* 이라고 예고해 뒀다). 계약이 그걸 지킨다 —
  끌어올리는 것은 교체이고, 교체는 규칙(≤3·GK≥1)을 가진 `sub` 모드가 소유한다.

⚠️ **프리필 계약에는 선수가 2명 이상 있어야 한다**(#294 MINOR-1). 1명뿐이면 `applyDraftPrompts` 를
슬롯 인덱스 기준으로 되돌리는 변이가 **e2e 를 통과한다**(실측). 서로 **다른 문장** + `[자리]` 스왑을
태워야 "사람에게 한 말이 자리를 따라가는" 결함이 죽는다.

### 서버 계약의 구멍 두 개 (임시 처리 중 — #287)

1. **빈 문자열 400** → 저장한 지시를 **지울 수 없다**(덮어쓰기만). 감독시간이 안내로 덮는다
   (`clearedAfterSave` → `halftime-cleared-warning`). 삭제 수단이 생기면 그 안내를 걷어낸다.
2. **저장분 읽기 API 부재**(`MatchDetail` 에 프롬프트 필드 없음, #253 동류) → 화면 복원을 **로컬 초안**
   (`hmb.match.halftime-draft.<id>`)이 한다. ⇒ **기기 간 이어쓰기는 안 된다**(폰에서 적고 데스크탑에서
   열면 칸이 비어 보인다). **후반 반영은 된다** — 서버엔 저장돼 있다. 읽기가 열리면 `halftime-draft.ts`
   한 곳만 갈아끼운다.

### ⚠️ `min-width: 0` — 문서 스크롤 0 으로는 못 잡는 오버플로

`.sheet`·`.panel`(StageShell.module.css)에 **`min-width: 0` 이 필요하다.** 그리드/플렉스 아이템의 기본
`min-width: auto` 때문에, 안쪽에 `overflow-x: auto` 를 걸어도 넘치는 자식이 **스크롤하는 대신 부모를
늘린다**. 실제로 당했다 — 대상 칩 17개가 시트를 **989px** 로 밀어 탭바가 화면 밖으로 나가고 프롬프트
아래가 잘렸는데, 셸이 `overflow:hidden` 이라 **문서 스크롤은 0** 이어서 기존 계약이 전부 green 이었다.
**실화면 캡처로만 보였다.** 그래서 계약을 `시트 폭`·`칩 줄 clientWidth` 로 다시 세웠다
(`p284-info-tabs.spec.ts` g·h). 시트 안에 가로로 긴 줄을 새로 넣을 땐 이 두 계약을 같이 본다.

### ⚠️ 시트 높이 등급은 **넷**이다 — "보는 패널"·"쓰는 패널"·"읽는 패널"은 다른 축 (#348 · #355)

`sheetHeight(tab)` = `info` · **`input`** · `state` · **`result`**. 데스크탑(≥1024px)에서만 픽셀이 갈린다
(폰은 무대 크기를 **가로**가 정해 남는 세로를 시트가 다 가져간다 — 그래서 폰에선 이 결함이 없었다).

### ⚠️ 감독시간 2컬럼은 **1024px 아래에서도** 켠다 — 컨테이너를 켜는 곳이 둘이다 (#354)

`DeckEditor` 의 2컬럼(보드 | 지시 레일)은 컨테이너 쿼리(`@container teamsheet (min-width: 640px)`)가
켜는데, 그 컨테이너를 만드는 `container-type` 이 `DeckEditor.module.css` 의 `@media (min-width:1024px)`
**안에만** 있었다. 그래서 1023px 이하는 **폭이 아무리 넓어도 단일 컬럼**이고, 단일 컬럼에서 보드는
피치 비율을 지키므로 **가로가 넓을수록 세로로 자라** 그 아래 레일이 밀렸다 — `감독의 한마디`
입력칸이 통째로 화면 밖(1023×768 y955 · 1023×900 y1076 · 853×533 y798 · 768×900 y881, 히트테스트 0).

- **깨지는 조건은 "넓고 낮은 창"이지 모바일이 아니다.** 폰(390)은 보드가 262px 라 멀쩡했다.
  이 밴드에는 창을 조금 좁힌 데스크탑과 **브라우저 확대**(853×533 = 1280×800@150%)가 떨어진다.
- **값 조정으로는 안 된다**(#348 ③ 과 다른 점): 감독시간 시트는 이미 세로를 100% 쓴다.
  853×533 에서 입력칸을 넣으려면 보드가 ~150px 이어야 해 "보드를 없애는 것"에 가깝다.
  그래서 **입력칸을 보드 높이와 무관하게** 만든다 = 옆에 세운다(데스크탑이 이미 그렇게 동작한다 —
  새 레이아웃이 아니라 그 밴드를 넓힌 것이고, 임계도 기존 컨테이너 640px 그대로다).
- ⚠️ **켜는 곳이 `HalftimePanel.module.css` 인 것이 의도다.** `container-type: inline-size` 는 layout
  containment 를 걸어 `position: fixed` 자손의 컨테이닝 블록이 된다 — **덱 화면**에는 보유 선수
  시트(`.sheetBackdrop`)가 있어 그 밴드에서 백드롭이 뷰포트가 아니라 에디터 박스에 갇힌다.
  감독시간은 `placementLocked` 라 그 시트가 **구조적으로 열리지 않아** 안전하다.
  **이 규칙을 `DeckEditor.module.css` 로 옮기지 마라** — 옮기는 순간 덱 화면이 같이 걸린다.
- ⚠️ **폰은 단일 컬럼 그대로다**(컨테이너 366px < 640px). 390px 에서 보드 옆에 레일을 세우면 둘 다
  못 쓴다 — 계약 ④ 가 "폰에서는 입력칸이 보드 **아래**"를 직접 재니 임계를 잘못 내리면 거기서 죽는다.
- 데스크탑(1280×800)·폰(390×844) 지오메트리는 **한 픽셀도 안 움직였다**(before/after 실측 동일) —
  변경이 그 밴드에만 걸린다는 증거다.

## 공지 이미지 — 업로드·경로 해석 (#309 W1)

공지에 그림을 넣으려고 `public/notice/` 에 파일을 커밋하고 **웹을 재배포**하던 것이 끝났다.
운영자가 admin 패널에서 올리면 서버에 저장되고, 본문은 그 경로를 참조한다.

- **경로 해석은 `common/notice-asset-url.ts` 한 곳**(`resolveNoticeUrl`). 규칙은 한 줄이다 —
  **`/api/` 로 시작하는 것만** API base 를 붙인다.
  - 업로드 이미지(`/api/notices/assets/{id}`) → **백엔드 오리진**(web 은 CF Pages 정적이라 그
    오리진에 `/api` 를 받아 줄 서버가 없다).
  - ⚠️ **기존 정적 에셋(`/notice/hero-kyeongnicius.webp`)은 웹 오리진 그대로 둔다.** 전부 옮기면
    그 그림이 백엔드에서 404 다 — "공존"(#309 요구)이 이 한 줄이다. 계약이 양방향으로 걸려 있다.
  - dev·테스트·데모(8080)에서는 `apiBase()==""` 라 **항등**이다 → 기존 화면·계약 무영향.
- ⚠️ **본문에 절대 URL 을 적지 마라.** 백엔드는 quick tunnel 뒤라 주소가 바뀐다 — 절대 URL 을
  구우면 터널이 한 번 죽는 순간 과거 공지 이미지가 전부 깨지고 복구가 본문 일괄 수정뿐이다.
  마크업 조립은 `noticeAssetMarkup(id, alt)` 로만(경로 규칙을 화면이 복제하지 않는다).
- **업로드는 FormData** — `apiFetch` 가 감지해 `Content-Type` 을 **설정하지 않는다**(boundary 는
  브라우저가 붙인다). 손으로 `multipart/form-data` 를 넣으면 서버가 파트를 하나도 못 읽는다.
- ⚠️ **삭제 버튼을 만들지 마라. 내리기는 노출 ON/OFF 뿐**(hero 확정 2026-07-30). 되돌릴 수
  있어야 한다. 끌 때 `usedBy > 0` 이면 **몇 건이 영향받는지 먼저 말하고**(`assetToggleWarning`)
  확인을 받되 차단하지는 않는다 — 운영자가 아는 상태에서 내리는 결정이다.
- 업로드 성공 시 **본문 끝에 마크업을 자동 삽입**한다. 경로를 손으로 옮겨 적게 하면 오타 한 글자가
  깨진 이미지가 되고 그 오타는 게시 후에야 보인다. **실패 시에는 본문을 건드리지 않는다**(계약).
- `NoticeImage` 의 로드 실패 시 숨김은 **업로드 저장소가 생긴 뒤에도 필요하다** — 외부 URL 참조는
  계속 가능하고, 운영자가 노출을 끄면 그 그림이 **의도적으로** 404 가 된다.
- 계약 = `common/notice-asset-url.test.ts`(양방향) + `admin/notice-admin-logic.test.ts`(정규화·경고) +

## 아트 base — 구운 폴백 vs 서버 번들 (#309 W2)

운영자가 admin 에서 아트 번들을 켜면 **웹 재배포 없이** 그림이 바뀐다. 그 전환이 여기 한 곳에 있다.

- **`CHARS_BASE`("/chars") 는 구운 폴백의 이름이고, 지금 쓰는 값은 `charsBase()` 다.** URL 조립
  함수들이 `base = charsBase()` 를 **기본값**으로 쓰는 것이 전환의 전부다 — 기본값은 호출 시점에
  평가되므로 한 곳을 바꾸면 아바타·카드·프레임·경기장 스킨이 전부 따라온다. 호출부는 `base` 를
  넘기지 않으므로 바꿀 곳이 없다. **`CHARS_BASE` 를 지우지 마라**(폴백이 사라지면 요구 ③이 깨진다).
- 판정은 `char-assets-store.resolveCharsBase()` 가 부팅 시 **한 번** 한다:
  `GET /api/chars/index` → **유효한 형태**면 base = `<api>/api/chars`, 아니면 구운 `/chars`.
- ⚠️ **200 만으로 채택하지 않는다**(`isUsableBundleIndex`). 목·프록시·구 서버가 `{}` 를 주면
  "아트 0개"가 정상처럼 통과해 전 화면이 **조용히** 이니셜 폴백이 된다 — 깨진 화면이 아니라
  밋밋한 화면이라 아무도 버그로 신고하지 않는다. 서버가 자기 리비전과 필수 파일 목록을 말해 줄
  때만 그 base 를 쓴다.
- ⚠️ **매니페스트만 서버에서 읽고 이미지를 웹 오리진에서 찾으면 전부 404 다** — base 는 한 곳에서
  정하고 `fetchCharAssets` 가 그 값을 받는다. 두 곳에서 정하지 마라.
- **e2e 에는 백엔드가 없다** → index 조회가 실패하고 구운 폴백을 탄다. 그래서 기존 아트 계약
  (`p3-card-art`·`p285-icon-policy`·`p218-legend-arena`·`p3-char-skin`, 36건)이 **손대지 않고 그대로
  통과한다**. base 를 바꾸는 변경을 할 땐 그 4개를 같이 돌려라.
- 운영 화면 = `admin/CharBundlePanel`(탭 `admin-tab-chars`). **삭제 버튼이 없다** — 리비전은 쌓이고
  활성 포인터만 옮긴다. `[구운 기본 아트로 되돌리기]` = `revisionId: null`.
  **업로드가 활성화가 아니다**(요약 확인 후 켜는 흐름) — 그 순서가 계약이다.
- ⚠️ **URL 조립축에 계약을 걸어야 한다**(독립검증 MAJOR-1). `charsBase()` 반환값과 매니페스트 fetch
  URL 만 보면, 기본값을 `CHARS_BASE` 로 되돌리는 변이체가 **전 스위트 1334건을 통과한다**. 그 상태는
  "매니페스트만 서버에서 읽고 이미지는 웹 오리진에서 찾아 전부 404" — 아바타·카드·프레임·아틀라스·
  경기장 스킨이 조용히 죽는다. e2e 는 백엔드가 없어 **구조적으로** 이 축을 못 잡는다.
- ⚠️ **서버가 "번들 있다"고 해 놓고 파일을 못 주는 상태**가 실재한다(볼륨 유실 후 DB 만 복원).
  `loadCharAssets` 가 **매니페스트가 하나도 안 오면 구운 폴백으로 되돌린다** — 이게 없으면 화면이
  통째로 이니셜이 되고 되돌아갈 길이 없다(서버 `index()` 의 파일 확인과 **두 층**).

## 경기 화면 시계 — 축은 **하나**다: 로그가 구운 `minute` (#388)

**엔진은 45분(하프 1350틱)을 돌리고 표기만 0~90' 로 스케일한다**(`displayMinutes`, #365). 그 결과
`minute` 이 **스냅샷·이벤트에 구워져** 내려오고, 로그줄(`LogPanel` 의 `l.minute`)은 그 값을 읽는다.
그런데 헤더·장면 목록·핀 툴팁만 `floor(tick / 60)` 으로 **틱을 분으로 직독**하고 있었다 →
라이브에서 **헤더 25' 옆에 로그줄 48'** (정확히 2배). 한 화면이 두 시각을 말했다.

- **화면에서 스케일을 다시 유도하지 마라.** 규칙이 두 곳에 생기고, 엔진이 표기를 바꾸는 날
  **화면만 조용히 어긋난다** — 이 결함이 정확히 그렇게 생겼다(engine@0.23.0 까지는 하프 2700틱이라
  `tick/60` 이 **우연히** 맞았다). 축은 `minute` 하나다.
- 헤더: `stage-state.headerMinute` → `displayMinuteAt`(= `tick` 이하 마지막 스냅샷의 구운 분).
  실서버 로그는 **틱당 스냅샷 1개**라 정확하고, 트림된 리포 픽스처(성긴 스냅샷)에서도 성립한다.
- ⚠️ **감독시간만 휘슬 기준이다** — 전반 마지막 스냅샷은 tick 1349 → 구운 분 **44**, 로그줄은
  `45' 전반 종료`(`half_whistle minute 45`). 마지막 스냅샷을 쓰면 그 화면이 또 두 시각을 말한다
  (`halfEndMinuteOf` 가 휘슬 우선, 없으면 스냅샷 폴백).
- **헤더는 초까지, 장면 목록·핀은 분까지 — 공존이 정상이다** (#406 W2, 커밋 `f720a05`).
  ⚠️ 여기 원래 *"초 표기(`10'00"`)를 버린 것은 의도다"* 라고 못 박혀 있었다. 그 문장의 근거는
  **"초까지 쓰려면 표기 스케일을 화면에서 재유도해야 한다"** 였는데, **그 전제가 틀렸다** —
  스케일을 **로그에서 되유도**하면 상수 없이도 초를 만들 수 있다. hero 확정(안 A, 2026-08-02)으로
  헤더는 `48'32"` 통합 표기가 됐다. 규율(#388)은 그대로고 **해소 방법**이 생긴 것이다:
  - **분 = 구운 `minute`**(그대로) · **초 = 그 분이 로그에서 처음 나타난 틱부터의 경과**.
    분을 만드는 축이 여전히 하나뿐이라 **초가 틀려도 분은 구조적으로 어긋날 수 없다**.
  - **"1틱이 몇 표기분인가"도 상수로 적지 마라** — `displayTicksPerMinute` 가 앵커 간격에서
    되유도한다(분이 하나뿐인 짧은 트림은 휘슬 폴백, 둘 다 없으면 **null = 초를 안 붙인다**).
    ⚠️ `30` 이나 `2` 를 어디든 적는 순간 #388 이 이름만 바꿔 돌아온다.
  - **보간하지 않는다**(hero 확정). 현행 레짐은 1틱 = 표기 2초라 초가 **짝수로만 뛴다**. 1초씩
    흐르게 만드는 것은 "데이터에 없는 값을 화면이 지어내는 것"이라 같은 축의 잘못이다.
  - **감독시간엔 초가 없다**(`second: null` → `45'`). 그 값의 권위는 종료 휘슬이고 휘슬 분에는
    앵커가 없다 — 붙이면 없는 앵커에서 숫자를 지어내는 것이고, 애초에 그 시계는 흐르는 시각이
    아니라 **끝난 지점**을 말한다(#226).
  - **장면 목록·핀 툴팁은 계속 `mm'`**(`timeline-pins.pinClock`, 구운 `minute`). 목록은 훑는
    자리라 초까지 쓰면 폭만 먹고 스캔이 느려진다. `formatMatchClock`(틱 직독)은 여전히
    **`minute` 이 없는 구 로그 폴백 전용**이니 새 소비자를 붙이지 마라.
  - 계약 = `e2e/p406-header-clock-seconds.spec.ts`. ★ **핵심은 대조군**이다 — 같은 실엔진 로그의
    `minute` 만 **구 레짐(60틱/분)으로 다시 구워** 두 로그에서 시계가 갈리는지 본다. 이게 없으면
    `30` 을 어딘가 적어 둔 구현이 **전부 초록**이다.
- ⚠️ **기존 단위테스트가 결함을 통과시켰다** — 값이 90분 레짐(하프 2700틱)으로 고정돼 있어서
  `tick/60` 이 우연히 맞았다(`2700 → 45'`). 계약을 세울 땐 **지금 레짐(1350틱)** 픽스처로 세워라.
  e2e 픽스처는 `scripts/gen-p388-fixture.ts` 가 **실엔진**(`defaultEngineConfig`)으로 만든다 —
  매핑을 손으로 적으면 계약이 "내가 적은 규칙"을 검사하게 된다.
- ⚠️ 장면 목록은 **돌려보기(review) 화면에만 있다**(감독시간 `경기장면` 탭·다시보기). 관전 무대
  플레이 모드엔 컨트롤이 아예 없다(#148/#216) — 거기서 재면 계약이 `skip` 으로 조용히 비어 버린다.
- 계약 = `stage-state.test.ts`(1350틱 레짐) · `ScoreBar.test.ts`(받은 분을 그리는 규칙) ·
  `timeline-pins.test.ts` · `e2e/p388-header-clock.spec.ts`(실화면 헤더 == 로그줄).
  ⚠️ `p226-halftime-header.spec.ts` 의 기대값도 **구운 분에서** 가져온다 — 예전엔 `round(tick/60)`

## 선수명은 **초크포인트 한 곳**으로만 (#406 요구 6)

`playersById.get(id)?.name ?? id` 가 **8개 파일에 각자** 선언돼 있었다. 규칙(무엇을 우선하나 ·
못 찾으면 뭘 보여주나 · 짧은 이름을 어디에 쓰나)이 화면마다 살아 있으면 정책을 한 번 바꿀 때
여덟 곳을 같이 고쳐야 하고, 하나를 빠뜨리면 **그 화면만** 옛 규칙으로 남는다(#285 `icon-policy`
와 같은 축). SoT = `common/player-names.ts`, 상세 주석은 그 파일 머리말.

### 사다리 — **카탈로그 → given → `미상 선수`**

1. **카탈로그**(`GET /api/players`, playerId 조인) — 이름을 고치면 여기부터 바뀐다.
2. **호출부가 준 이름**(`given`) — 서버 응답·매치 스냅샷이 같이 실어 보낸 값.
3. `UNKNOWN_PLAYER_NAME`(= `미상 선수`) — **playerId 는 절대 화면에 안 나온다**.

- ⚠️ **2단이 1단을 이기게 하지 마라.** 라이브 `match_halves.select_data_json` **152/152 에 옛
  영어 이름이 박제**돼 있다. 저장은 고치지 않기로 했으므로(재현 번들 = 스냅샷 불변, W0 결정)
  web 쪽에서 그 결정이 뜻하는 바가 **이 우선순위**다. `TradePlayerCard` 가 정확히 반대로 돌고
  있었다(부모는 카탈로그를 조인해 넘기는데 카드는 서버 `PlayerRef.name` 을 읽었다).
- **id 를 given 으로 넘겨도 막힌다**(`looksLikePlayerId` 백스톱) — 옛 습관(`?? playerId`)이 남아
  있어도 화면엔 `P077` 이 안 뜬다.
- 창구는 셋, **사다리는 하나**다: `usePlayerNames()`(훅) · `buildPlayerNames(rows|Map)`(순수) ·
  `playerNameOf(row, axis, given?)`(행을 이미 손에 든 프레젠테이션 부품).
  ⚠️ 마지막 것이 없으면 프롭으로 행을 받는 부품이 `player?.name ?? playerId` 로 되돌아간다 —
  초크포인트가 **id 조회 경로만** 덮으면 절반만 막은 것이다.

판단 기준은 하나다: **이름 옆에 다른 조각이 같이 앉는가.** 앉으면 짧은 이름.

### AST 스캐너 — 초록은 "우회 0"이 아니라 "**이 형태의** 우회 0"이다

`common/player-names.test.ts` 의 "우회 금지" 블록이 `src/**` 전 파일을 TypeScript AST 로 훑어
①**컬렉션에서 찾은 행의 `name` 직접 추출** ②**이름 → id 폴백** 을 금지한다(정규식이 아니다 —
줄바꿈·구조분해·중첩 괄호·주석에 무감각해야 해서).

- **잡는 축**: 삼항(선언부·사용부) · 간접 경유 N1~N8(객체 리터럴 프로퍼티·배열 구조분해·`let`
  재대입·spread 사본·파라미터 기본값·`useMemo` 래핑·같은 파일 프롭 전달·별칭 n단) ·
  연산자 O1~O7(`&&` 가드의 오른쪽 · `??=`/`||=`/`&&=` 바인딩 · `??=`/`||=` id 폴백 · `satisfies` ·
  콤마 · **`??`/`||` 의 오른쪽** · **프로퍼티 대상 바인딩**(`s.p = m.get(id)`)).
- **미탐 경계는 그 파일 머리말에 적혀 있고, 음성 대조가 그걸 계약으로 고정한다** —
  인덱스 접근(**대입 대상이 인덱스인 경우 포함**) · `find`/`get` 밖의 조회 메서드 · 함수 경계 ·
  메서드 별칭 · `name` 필드 고정 · id 폴백 우변이 식인 경우 · 순회 렌더 · **파일을 넘는 프롭** ·
  `&&` 의 왼쪽.
  ⚠️ **그 목록이 완전하다고 읽지 마라 — 완전했던 적이 없다.** 4차가 O1~O5 를, 5차가 O6·O7 을
  **미기재 상태에서** 발견했다. 한때 머리말이 *"남은 미탐은 전부 아래에 적는다"* 고 단언했는데
  거짓이었고, 그 문장 때문에 다음 사람이 "목록에 없으니 잡히는 형태"로 읽는다. 지금은
  "지금까지 확인된 경계"로 다시 썼다.
  ⚠️ **경계의 근거를 '오탐이 쏟아진다'로 적을 거면 재고 적어라.** `&&` 왼쪽이 그 예였다 —
  *"왼쪽까지 보면 `if (row && …)` 류가 전부 오탐"* 은 재보지 않은 문장이었고, 실측하면
  (왼쪽까지 보는 변이 + `apps/web/src` 전수 재스캔) **새 offender 0건**이다. 진짜 근거는
  의미론이다: `a && b` 가 `a` 를 값으로 내는 건 `a` 가 falsy 일 때뿐이라 왼쪽 갈래는 행일 수 없다.
  (`??`/`||` 는 오른쪽이 truthy 한 행일 수 있어 **대칭**이다 — 그래서 O6 으로 넓혔다.)
  ⚠️ **새 형태를 발견하면 머리말 목록과 음성 대조를 같이 갱신해라** — 넓히면 음성 대조가
  **먼저 깨진다**(설계된 신호).
- ⚠️ **오탐은 버그가 아니라 설계다.** 선수 카탈로그가 아닌 컬렉션도 걸린다 → `EXEMPT` 에
  **사유와 함께** 적어 "의도된 예외"로 만든다. 조용한 예외를 허용하면 계약이 다시 거짓말한다.
- ⚠️ **`*.test.ts` 를 스캔에서 통째로 빼지 마라 (#406 W8 결정).** 테스트가 `meta.get(k)!.name` 으로
  기대값을 단언하는 것은 화면이 아니지만, **클래스 단위 면제는 지금 파일이 아니라 앞으로 생길 모든
  테스트 파일**에 적용돼 "이 자리는 왜 초크포인트를 안 쓰나"를 아무도 다시 묻지 않게 만든다 —

## 경기 화면의 사이드 — **홈은 내가 아니다** (#322)

리그 어웨이 라운드에서 화면이 통째로 뒤집혔던 자리. 라이브 제보 2계정(축구왕여르·별희),
리그 20경기 중 **7건(35%)**, **어웨이 라운드를 치른 유저 3명 전원**(리그 유저는 6명 — 나머지 3명은
아직 홈 라운드만 해서 안 걸렸을 뿐 면제가 아니다. 더블 라운드로빈이라 절반이 어웨이다).

- **엔진 home = 픽스처 `home_team`** 이다(`MatchOrchestrator.userIsHome`, 2026-07-19). 유저가
  어웨이인 라운드에는 `scoreHome` 이 **봇 득점**이고, 이벤트 `team:"home"` 이 봇이고,
  뷰어가 그 팀을 **왼쪽**에 그린다(`sx()` 는 미러링이 없다 — 엔진 x=0 이 항상 왼쪽).
  **서버·엔진·DB 는 전부 정합했다. 틀린 건 web 한 곳이었다.**
- **이름 배치는 `stage-state.teamNamesOf` 한 곳**이 한다. 서버가 `MatchDetail.homeName`/`awayName` 을
  **사이드 라벨 그대로** 주고, 없으면(구 서버) `ownerName`/`opponent.name` 으로 폴백한다.
  ⚠️ **`homeName = ownerName` 을 다시 쓰지 마라** — 그 한 줄이 이 버그의 전부였고, 흘러가는 곳이
  스코어바·로그·타임라인·결과카드·팀스탯 **전부**라 한 줄로 화면 다섯 개가 같이 거짓말한다.
- **`ownerName` 은 "홈"이 아니라 "누구 매치냐"** 다. 서버 javadoc 이 *"매치를 만든 유저(홈)"* 라고
  적어 둔 것을 web 이 계약으로 믿은 게 발단 — 문서 한 줄이 만든 버그다.
- **표시 관례 = 홈 먼저**(hero 확정 안 C, 2026-07-30). 유저 시점으로 뒤집지 **않는다** —
  그러면 피치도 미러링해야 하고(viewer-core = QA 도메인) 로그·이벤트 축까지 전부 반대 관점을
  하나 더 얹어야 한다. 데이터 전 층이 픽스처 관점으로 일관된 이상 화면을 진실에 맞추는 쪽이 맞다.
  대신 **내 팀 표식**(`myTeamSide` → 스코어바 `내 팀` 칩)으로 "어느 쪽이 나인지"를 따로 말한다.
  헤더 이름 색은 이미 뷰어 팀색과 같으므로(home 파랑 / away 빨강) 칩은 색이 아니라 **위치**를 말한다.
- ⚠️ **표식을 이름 슬롯의 줄임표에 태우지 마라.** 처음에 칩을 `.teamName`(=`text-overflow: ellipsis`)
  안에 넣었더니 긴 팀명 뒤에서 **통째로 잘렸는데** DOM 엔 있으니 `toBeVisible()` 이 그대로 통과했다
  — 화면엔 없었다(실화면 캡처로만 보였다, 루트 §2-2). 지금은 슬롯이 플렉스고 **이름만**
  줄어든다(`.teamLabel`). 계약도 **폭·클리핑 실측**으로 걸려 있다.
- ⚠️ **그 계약은 `FIRST_HALF` 에서 재야 한다.** `FINISHED` 로 쟀더니 **변이체가 살아남았다** —
  종료 화면은 헤더 우측이 비어 슬롯이 넓다. 실제로 잘리는 건 리그 뱃지 + 시계 + 상태 태그가
  폭을 먹는 **관전 중**이다. 계약은 **가장 좁은 상태**에서 재라.
- ⚠️ **표본이 계약의 절반이다.** 기존 web 목·계약은 전부 유저=홈이라 이 결함을 **구조적으로**
  못 잡았다(그래서 3개월 살았다). 새 매치 계약을 쓸 땐 **어웨이 픽스처 표본**을 같이 태워라.
- ⚠️ **"왼쪽 = 나"에 기대던 화면을 같이 찾아라.** 통계 탭이 그랬다 — `[왼쪽 값][항목][오른쪽 값]`
  좌우 대칭인데 **열 이름이 없었다**. 홈이 항상 유저였을 땐 위치가 곧 이름이라 읽혔지만, 이 변경
  뒤로는 어웨이 라운드에서 왼쪽이 봇이다. 그래서 통계에도 팀 이름 줄 + 내 팀 칩을 넣었다
  (`stats-team-home`/`stats-team-away`/`stats-my-team`). 결과 탭은 이미 팀명 헤더가 있었으니
  **비대칭 자체가 신호**였다 — 다음에도 그렇게 찾아라.
- **표식 자리 규칙 = 항상 자기 이름 바로 뒤**(스코어바·통계 동일). 통계에서 어웨이 쪽만 이름 앞에
  뒀더니 칩이 두 이름 **가운데**로 떨어져 어느 팀 것인지 모호했다(실화면으로 확인).
- 계약 = `stage-state.test.ts`(사이드 ↔ 팀 이름) + `e2e/p322-side-orientation.spec.ts`
  (라이브 실경기 로그 주입 · 헤더/로그/결과/표식 + 무회귀 + 구 서버 폴백)
  + `e2e/p322b-stats-team-header.spec.ts`(통계 열 이름 · 스코어바와 같은 순서 · 무회귀).

## 스포일러 규칙은 **폴백에도** 걸린다 (#238)

라이브 하프에서 "재생 위치를 넘는 점수를 보이지 않는다"(#233)는 **시각 재생에만** 걸려 있었다.
캔버스가 실패했을 때 뜨는 텍스트 폴백(`MatchViewer` 의 `TimelineView`)의 `끝까지 보기` 는
게이트가 없어서, 후반 진행 중에 누르면 그 하프 이벤트가 **전부** 열리고 스코어보드가
**경기 최종 스코어**를 그렸다(변이체 실측: `viewer-score-half2` 가 `1 : 5`).

- **상한 규칙은 `match-logic.visibleTimelineEvents` 한 곳**이 소유한다. 호출부에서 `slice`/`filter`
  를 다시 쓰지 마라 — #233 독립검증 minor-1 이 정확히 그 형태였다(인라인 계산이 변이체를 통과시켰다).
- 상한값은 **시각 재생과 같은 출처**(`liveGate` → `tickOfIndex`)에서 온다. 폴백만의 두 번째 규칙을
  만들면 둘이 조용히 갈라진다.
- ⚠️ **서버 시계는 인덱스로, 이벤트는 절대 틱으로 말한다.** 섞으면 후반에서 상한 비교가 늘 참이 된다.
- **라이브면 `finalScore` 를 쓰지 않는다** — 다 봤다고 그 하프의 최종을 그리면 상한을 걸어 놓고
  마지막 줄에서 스포일러를 내는 꼴이다.
- **상한을 모르면(손상 로그로 스냅샷을 못 읽으면) 건너뛰기 버튼을 아예 주지 않는다.** 그 상태에서
  버튼을 남기면 고치기 전과 똑같이 하프 전체가 열린다.
- ⚠️ **계약을 한 테스트에 묶지 마라.** 처음엔 a·b·c 를 한 개로 묶었는데 변이체가 **문구 단언에서
  먼저 죽어** 정작 스포일러 단언 두 개는 **실행조차 되지 않았다** — "죽었으니 계약이 있다"는 착각이
  나오는 모양이다. 셋을 갈라 각각 변이를 죽이는지 확인해라.
- 폴백을 e2e 로 띄울 땐 캔버스를 목으로 부수지 말고 **`finalScore` 를 뺀 로그**를 내려라 —
  viewer-core `loadLog` 가 throw 해서 **실제 손상 로그와 같은 경로**로 폴백이 뜬다(#65 신뢰경계 검증).
- 계약 = `match-logic.test.ts`(상한 순수함수) + `e2e/p238-fallback-live-gate.spec.ts`.

GEN1/GEN2 대기 화면(`GenWaitPanel`)의 서술 문구는 **축구장 정경 로테이션**이다(hero 확정).

## 폰 덱·선발 UX — auto·선수풀·드래그 (#439, hero 확정 2026-08-04)

세 요구가 **전부 `DeckEditor` 하나**에 모여 있다(덱셋팅 `/deck` · 경기전 `BriefingPanel` ·
감독시간 `HalftimePanel` 이 같은 컴포넌트를 props 만 바꿔 쓴다). 새 화면을 만들 일이 아니었다.

### auto = **빈 자리만 채운다** — 한 함수, 후보 풀만 주입

```
fillEmptySlots(draft, candidates)          ← 화면 무관 순수 함수 (deck/fill-empty.ts)
  덱셋팅  → candidates = 보유 선수 전체
  경기전  → candidates = 벤치 선수만        ← R2 제한이 후보 목록에서 자동으로 나온다
```

- **R2 를 auto 안에 `if` 로 넣지 마라 — 후보 목록이 곧 규칙이다.** 두 화면이 같은 코드를 타야
  한쪽만 고쳐지는 회귀가 구조적으로 안 생긴다. 계약 = `deck/auto-shared-logic.test.ts`(소스 스캔).
- ⛔ **`autoBuildLineup`(`deck/auto-lineup.ts`)을 다시 배선하지 마라.** 그건 전원 재구성 +
  **모든 선수의 `promptText` 덮어쓰기** + 팀 전술 초기화 + `teamPrompt` 삭제라, hero 가 경기전에서
  없애라고 한 **[초기화]와 같은 종류의 피해**다. 소비처 0 이 계약이고, 파일은 롤백 자산으로 남긴다
  (적합도 수학 `positionWeight`/`fitScore`/`assignSlots` 는 지금도 공유한다).
- **[초기화]는 경기전에서만 없앤다**(`hideReset`). 덱셋팅은 처음부터 다시 짜는 일이 정상이라 남긴다.
  `placementLocked`(감독시간)와 **다른 축**이다 — 경기전은 배치 자체가 열려 있다.
- **경기전 시트는 벤치만**(`poolScope="bench"`). 필터·비활성이 아니라 **목록 자체를 줄인다**
  (AC = DOM 부재). 선발끼리 자리 바꾸기는 계속 열려 있다 — 막는 것은 스쿼드 밖에서 데려오는 것뿐.
- **포메이션은 auto 가 바꾸지 않는다**(구 `autoBuildLineup` 은 최적 포메이션을 골랐다). 경기 직전에
  진형이 조용히 바뀌는 것 자체가 결정거리라 **의도된 귀결**이다 — 되살리지 마라.

#### ⚠️ auto 가 **자리를 준 선수의 빈 지시**를 채운다 (hero 결정 ⓐ 2R → "승격도" 3R)

1R 은 "프롬프트를 만들지 않는다"로 짰고, 그 결과 **빈 덱 + AUTO 의 지시가 11/11 → 0/11** 로 죽었다
(`POSITION_DEFAULT_PROMPTS` 를 넣던 유일한 소비처가 `autoBuildLineup` 이었다). 온보딩
(`common/tutorial-steps.ts` `setup-auto` → `setup-motto`)이 *"AUTO 로 선발을 채우고 감독 한마디만
직접 타이핑"* 을 전제하는데 지시칸이 전부 빈칸이 됐다.

**규칙은 두 조건의 곱이다** — ①auto 가 **이번에 자리를 준** 선수(새로 놓았거나 **벤치 → 선발 승격**)
② 그 지시가 **비어 있다**. 둘 다 참일 때만 그 자리의 포지션 기본 문구가 들어간다.

- ⚠️ **①의 "승격"은 3R 에 hero 가 넓힌 것이다**(*"승격되는 선수도 넣어줘"*). 2R 은 경계를
  *"원래 아무 데도 없던 선수"* 로 좁게 잡아서 **벤치에서 올라온 선수가 지시 없이 선발로 출전**할
  수 있었다. 한때 이 자리에 *"올라온 선수는 비어 있으면 빈 채로 남는다"* 라고 적혀 있었고 그건
  이제 **거짓**이다.
- ⚠️ **②는 안 움직인다.** 한 글자라도 있으면 절대 안 덮는다 — 유저가 지운 문장을 auto 가 되살리면
  그게 Q1=ⓑ 위반이다. 그리고 **auto 가 자리를 주지 않은 선수**(원래 그 자리에 있던 선수)는 지시가
  비어 있어도 안 건드린다 = 전수 채우기가 아니다. 계약이 세 갈래를 각각 변이로 죽인다.
- ⚠️ **이 회귀는 AC 7건에도 기존 e2e 36건에도 안 걸렸다** — 아무도 **지시 개수**를 안 쟀기 때문이다
  (선발 수·프롬프트 보존은 쟀다). 자동 배치를 건드리면 `directive-count` 를 같이 재라.

## 원정 데일리 미션 (#408) — **클라 계산 0** 이 이 화면의 전부다

하루(KST) 2개 · 티어별 다이아 · 미션당 1회 리롤. 설계 = `docs/plan-v5/away-daily-mission.md`
(**게임 수치·한글 미션 문구는 hero 산출물이라 임의 변경 금지**). 자리 셋 = 원정 페이지 섹션
(`mission/DailyMissionSection`) · 홈 알림 한 줄(`home-logic.homeNotice`) · 결과 화면
(`mission/MissionRewardSection`).

- **판정 로직은 `mission/mission-logic.ts` 하나**고, 거기 있는 규칙은 **정규화와 라벨 매핑뿐**이다.
  티어→금액 · 달성 여부 · 리롤 가능 여부를 화면이 다시 만들면 노브(economy `mission.reward`,
  `hmb.mission.daily.*`)를 돌린 순간 화면이 서버가 하지 않는 일을 단언한다(#262·#368 규율).
  - ⚠️ **`missionClaimable` 은 `state === "COMPLETED"` 다 — `progress >= target` 이 아니다.**
    달성은 경기 정산이 판정하고(`completed_at`) 진행도는 달성 후 **언다**. 두 값이 갈라지는 창이
    실재하고, 그때 클라 계산은 "받으세요"라고 말하면서 서버는 409 를 준다.
  - ⚠️ **리롤 문은 서버의 `rerollable` 하나**다. `state` 로 추론하지 마라 — 잠긴 **이유**를 고를
    때만 `state` 를 읽는다(문을 여는 판정이 아니라 안내 문구다).
  - ⚠️ **"자정에 초기화"를 문자열로 적지 마라.** 경계는 서버가 `resetAtKst` 로 말한다.
    `new Date(...)` 로 파싱하면 브라우저 타임존으로 **환산돼** KST 밖 기기에서 00:00 이 아닌 값이
    뜬다 — 그 값은 서버가 오프셋을 박아 보낸 벽시계라 환산 대상이 아니다(정규식으로 그대로 읽는다).
- **홈 한 줄은 `claimableCount` 를 쓴다 — 오늘 미션 배열을 세지 않는다.** 달성분은 기한 없이
  남아서(설계 §6.3) 서버가 **지난 날짜 미수령분까지** 합산해 준다. 배열로 만들면 어제 못 받은
  것이 홈에서 사라진다.

### 홈 숫자와 화면이 갈라졌던 자리 — `pendingClaims` (갭1, 서버 `6b38674`)

**W3 에서 실제로 터졌다**: `claimableCount` 는 전 기간을 세는데 `missions` 는 **오늘 행만** 와서,
어제 달성하고 안 받은 유저는 홈에서 "받을 보상 1건"을 보는데 원정 화면엔 **받을 카드가 없었다** =
§6.3(달성분은 기한 없이 남는다)이 **화면에서 도달 불가능**했다. 서버가 `pendingClaims[]` 를 얹어 닫았다.

- 원정 섹션은 **두 묶음**이다: `오늘의 미션`(missions) + `받지 않은 보상`(pendingClaims, 지난 날짜).
- ⚠️ **오늘 것은 `pendingClaims` 에 안 들어온다**(서버 보증 — 오늘 달성분은 `missions` 에
  `COMPLETED`). 두 목록을 이어 그려도 중복이 없으니 **클라가 중복 제거를 하지 마라**. 있지도 않은
  중복을 지우는 코드가 나중에 진짜 항목을 지운다.
- ⚠️ **`pendingClaims` 항목엔 `progress`/`target`/`rerollable` 이 없다**(끝난 미션). 진행 막대·
  [다시 뽑기]를 그리지 마라 — 없는 값을 0 으로 채우면 "0 / 0" 이 뜬다. 지난 미션 리롤은 410
  `MISSION_EXPIRED`. **수령은 오늘 것과 같은 엔드포인트**다(`claim` 은 날짜를 보지 않는다).
- ⚠️ **`claimableCount/Amount` 를 클라가 합산하지 마라.** 서버가 그 둘을 **화면에 그릴 수 있는
  것에서 파생**시킨다(missions 의 COMPLETED + pendingClaims) — 원본이 하나라 어긋날 수 없다.
  자체 합산을 넣는 순간 이 갭이 반대 방향으로 다시 열린다.
- ⚠️ **롤백 스위치(`missions: []`)에도 `pendingClaims` 가 있으면 섹션을 그린다.** 처음엔 "`missions`
  가 비면 무조건 섹션 없음"이었는데, 그러면 §9 가 *"끄기가 지갑을 뺏지 않는다"* 라고 약속한 자리에서
  같은 버그가 되살아난다. 판정은 `pickDailyMissions` 한 곳 — **둘 다 비어야** null 이다.

- **부재가 정상 상태다**: 구 서버(404) · 롤백 + 미수령 0 → **섹션을 통째로 안 그린다**(#286 W5).
  스켈레톤·에러를 띄우면 "아직 없는 기능"이 "고장 난 화면"이 된다.
- **결과 화면 섹션은 일부러 자립형**이다(#405 가 `ResultPanel`·`StageShell`·`GrowthReportSection`
  을 재작성 중) — `ResultPanel` 접촉면은 **import 1 + JSX 1줄**이고 CSS 도 자기 모듈이다. #405
  보상 탭이 랜딩하면 그 한 줄을 옮기기만 하면 된다.
  - **[받기]의 문은 서버 `state` 하나다**(갭2, 같은 커밋이 실어 줬다). 그 필드가 없던 동안은 버튼을
    아예 두지 못했다 — ⚠️ `progress >= target` 으로 열면 **수령한 뒤에도 버튼이 남는다**.
    `COMPLETED` → [받기] · `CLAIMED` → "✓ 받음" · `IN_PROGRESS` → 진행도만(누를 것이 없다).
  - ⚠️ 구 서버(필드 부재)는 `state:""` 로 떨어져 **문이 닫힌다**(fail-closed). 없는 값을 `COMPLETED`
    로 추측하면 이미 받은 보상에 버튼이 다시 뜬다.
  - `missionClaimable` 은 **원정 섹션과 결과 화면이 공유**한다(인자가 `{ state }` 하나인 이유) —
    두 곳에 적으면 한쪽만 규칙이 낡는다.
  - ⚠️ **수령은 `["matchResult"]` 도 무효화한다.** `useMatchResult` 는 `staleTime: Infinity` 라,
    안 하면 `missions[].state` 가 **영원히 `COMPLETED`** 로 남아 다이아를 받았는데 [받기]가 그대로
    보이고 다시 누르면 409 다 — **이 화면엔 지갑 배지가 없어서** 유저는 받았는지 확인할 방법조차
    없다(독립검증 blocker-1). **판정은 옳았고 입력 데이터가 낡은 것**이었다. 미션을 그리는 화면이
    둘이면 무효화도 둘이다.

#### ⚠️ 뮤테이션 계약은 **결과 화면의 최종 상태**로 단언해라 (blocker-1 의 진짜 교훈)

「헤더 지갑이 따라온다」가 아무 단언도 없던 것이 첫 번째다.
- 계약 = `mission/mission-logic.test.ts`(36) + `home/home-logic.test.ts`(5) +

제출 요건 1(GitHub Pages 에서 바로 플레이 + 목데이터)의 구현체. `src/static/**` 가 **브라우저 안의
목 백엔드**이고, 화면·훅·뷰어는 **한 줄도 바뀌지 않았다**.

- **주입 지점은 `apiFetch` 한 곳**(`api/client.ts`). `#129` 의 `apiBase()` 와 같은 규율 —
  호출부는 계속 `"/api/..."` 를 넘기고, 스태틱 모드면 네트워크 대신 `static/router.ts` 로 간다.
- **경기 흐름은 실서버와 같은 계약**이다: 같은 상태머신(BRIEFING→GEN1→…→FINISHED) + 같은
  `MatchClock`(`phaseStartAt`/`phaseEndsAt`/`halfRealMs`). 그래서 흐름 브릿지(#424)·라이브
  게이트(#238)·스킵(#421)이 손대지 않고 그대로 돈다. **여기서 규칙을 다시 만들지 마라.**
- **엔진은 브라우저에서 직접 돈다**(`static/sim.ts` → `runFirstHalf`/`resumeSecondHalf`,
  하프당 0.2~0.6초). 러너(`packages/server/runner/simulate.ts`)의 `resumeState` 직렬화는
  **가져오지 않는다** — 프로세스 경계가 없어 carry 를 메모리에 들고 있으면 되고, 새로고침 복구는
  저장해 둔 **입력으로 재시뮬**한다(결정론이라 같은 로그가 나온다).
- **AI 폴백은 재발명하지 않았다** — `packages/server` 의 `stubExecutor` 를 그대로 소비한다
  (`@hmb/server-stub` alias). AI 경로는 로컬 브리지(`scripts/ai-bridge.ts`)가 기존
  `claudeCodeExecutor` + `prompt/coach.ts` 를 부른다. **로그인 없으면 안내만 하고 폴백**(hero 지시)
  — 플레이를 막는 분기는 어디에도 없다.

### ⚠️ 라이브 번들이 커지지 않는 것은 **상수 하나**에 달려 있다

`STATIC_BUILD_ENABLED`(= vite `define` 이 꽂는 `__HMB_STATIC_BUILD__` 리터럴)가 목 백엔드
`import()` 를 감싼다. 이걸 `isStaticMode()`(런타임 함수)나 `import.meta.env` 를 읽는 형태로
바꾸면 **접힘이 깨져 라이브 프로덕션 빌드에 157 kB 가 실린다**(실측). 반대로
`import.meta.env.DEV` 를 직접 쓰면 **playwright e2e 의 Node import 가 TypeError** 로 죽는다
(`char-assets-store` → `client.ts` → `static/mode.ts` 경로가 실재한다). 두 조건을 **동시에**
만족하는 형태가 지금의 define 이고, `static/mode.test.ts` 가 그 형태를 계약으로 박제한다.

- 같은 이유로 `common/char-manifest.ts` 의 `CHARS_BASE` 도 `(import.meta as …).env?.BASE_URL ?? "/"`
  다 — 서브패스 배포(#444)를 살리면서 Node import 를 죽이지 않는 유일한 형태다. 값은 라이브
  기본(`BASE_URL="/"`)에서 정확히 `"/chars"` 로 접혀 **기존 계약·동작 무변경**이다.

## 규칙
- Playwright E2E(AC-W1 풀 시나리오)가 주 게이트. 시각/연출 판정은 **독립 QA 서브에이전트**로만(자기검수 금지, 루트 §2-2).
- ⚠️ **e2e 는 리포의 `evidence/**` 에 직접 쓰지 않는다**(#314). 증거 캡처는 `HMB_WRITE_EVIDENCE=1`
  뒤에 두고, 기본 목적지는 `test-results/`(gitignore)다 — 그 스펙을 게이트로 돌리는 **다른 세션의
  트리가 매번 dirty** 해지고 `git add -A` 가 그걸 조용히 쓸어 담는다(#286 이 커밋에 섞어 원복,
  #309 가 리베이스마다 수동 원복). 증거 갱신은 **부작용이 아니라 의도적 행위**여야 한다:
  `HMB_WRITE_EVIDENCE=1 CI=1 npx playwright test e2e/<spec>`. 참고 구현 = `p293-notice-deeplink`.
  캡처를 별도 스펙으로 떼지는 마라 — 계약이 본 것과 다른 화면을 찍게 된다(목적지만 가른다).
- **e2e 전체 실행 금지** — `league-season`·`match-flow`·`w3-viewer-smoke` 는 :8080 라이브 데모에 붙는다.
  목 기반 스펙만 지정하고 `CI=1` + 빈 포트(`WEB_E2E_PORT=…`)로 돌려라(`reuseExistingServer` 가
  다른 세션 dev 서버를 주워 쓴다).
- 모바일 우선 반응형. 상태는 TanStack Query, 전역 스토어 도입 금지(PoC).
- 커밋 `[Spider] type(web): ...`.
