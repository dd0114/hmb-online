## 0. 어떻게 보나 (재생법)

시연 경기는 **결정론적으로 재생성**된다 — 시드·config 가 고정이라 누가 언제 돌려도 같은 경기다.

```bash
# ① 로그 재생성(원하면. 이미 커밋돼 있다) — 아래 표의 틱은 이 경기의 좌표다
npx tsx evidence/377/gen-m1-pre.ts        # → evidence/377/m1-pre-match.json

# ② 뷰어로 재생
cd packages/engine/dev-viewer && node build-standalone.mjs && open viewer-standalone.html
#    뷰어 콘솔에서: __viewer.seek(<틱>)     ← 아래 표의 "틱"
#    또는 QA 콘솔(#191) 탭에 m1-pre-match.json 을 주입
```

- **시각** 열 = 뷰어 시계에 뜨는 표기 시각(0~90′ 스케일, `displayMinutes`).
- **틱** 열 = `__viewer.seek(틱)` 에 그대로 넣는 값.
- 시연 경기: `seed 34` · 데모 픽스처 · 리얼 config · 최종 **4:3**.

## 1. #349 — 프리킥을 **차서** 재개한다 (Law 13)

**무엇이 보여야 하나**: 프리킥 스팟의 taker 가 공을 몰고 나가지 않는다. 발로 **차서**(패스 또는 슛)
플레이를 재개하고, 그 순간 수비벽이 스팟 9.15m 앞에 **서 있다**.

| 틱 | 시각 | 재개 행동 | 벽 (매핑 요구 / 실제 서 있던 인원) | 한 줄 |
|---|---|---|---|---|
| **45** | 1:30 | pass | **4 / 3** | 골문 가까운 프리킥 — 4인 벽을 부르고 3명이 제자리에 서 있다 |
| 208 | 6:56 | pass | 2 / 2 | 먼 프리킥 — 위협거리 매핑대로 벽이 2명으로 줄었다 |
| 224 | 7:28 | pass | 3 / 3 | 벽 전원 도착 |
| 240 | 8:00 | pass | 3 / 3 | 〃 |
| **627** | 20:54 | **shoot** | **4 / 3** | 벽을 세운 위에서 **직접 슛** — 벽이 있는 채로 차는 그림 |
| 128 / 544 / 952 | 4:16 / 18:08 / 31:44 | pass | 0 / 0 | 사거리 밖(위협거리 > `wallRangeM`) — **벽을 안 세우는 것이 정상** |

프리킥 재개 295건 중 **드리블 221건 = 78.5%**, 스로인 25.3%. hero 제보 *"프리킥을 안 차고
선수가 드리블해. 그거 반칙 아니야?"* 가 그대로 재현된다.

## 2. #349 — 벽이 **실제로 선다** (그리고 우리 팀이 벽을 서지 않는다)

hero 관찰 3분해 중 ②③에 대한 답이다.

- **② "벽을 안 세운다"** — 벽 배정은 **되고 있었다**(0.25.0 #307). 안 서 있던 것은 **기하** 때문이다:
  파울 부근 수비수는 스팟 9.15m **안**에 있어 접근 금지(#176)가 먼저 자기 방위로 밀어내고,
  거기서 벽 자리로 가는 직선은 원을 가로지르므로 일방통행 벽이 매 틱 그 이동을 **취소**했다.
  → 링 위 엉뚱한 방위에 굳는다. 20시드 실측 **스팟거리 p50 9.2m / 슬롯거리 p50 11.4m**,
  **벽 도착률 12.3%**. 수정(경계를 따라 돌아가기) 후 **75.9%**.
- **③ "우리 팀이 이상하게 위치를 잡는다"** — 역할 배정의 팀 축은 **정상**이었다(20시드 오배정 0건).
  hero 가 벽으로 본 것은 공격팀 **백업 3인**(`backupRadiusM` 8m)일 가능성이 높다 — 벽 거리(9.5m)와
  1m 차이라 화면에서 겹쳐 보인다. ⚠️ 이건 판정이 아니라 **가설**이고, 일괄 리뷰에서 hero 확인 대상이다.
  (같은 1m 차이가 계측도 속였다: 좌표로 역할을 되추론했더니 백업 2/3 이 벽으로 오분류돼
  "9.15m 침범 566건"이라는 **가짜 위반**이 나왔다. 그래서 역할 라벨을 배정한 쪽이 달게 했다.)

## 3. #347 — 킥오프는 **전원 자기 진영**에서 시작한다 (Law 8)

**무엇이 보여야 하나**: 킥오프 휘슬 순간 화면 오른쪽/왼쪽 절반에 각 팀이 **완전히 갈려** 있다.
공격 3인방이 하프라인을 넘어 서 있지 않다. 그 순간 **"▶ KICK-OFF!"** 자막이 한 호흡 뜬다.

| 틱 | 시각 | 재개팀 | 상대 진영 침범 | 한 줄 |
|---|---|---|---|---|
| **0** | 0:00 | home | **0명** | 경기 개시 — 전원 자기 진영 |
| 73 | 2:26 | away | 0명 | 실점 후 재시작 |
| 1047 | 34:54 | home | 0명 | 〃 |
| **1350** | **45:00** | away | **0명** | **후반 시작** — 하프타임 경계 |
| 1752 / 2047 / 2147 / 2323 / 2429 | 58:24 / 68:14 / 71:34 / 77:26 / 80:58 | — | 0명 | 나머지 득점 후 재시작 |

**수정 전에는 무엇이 보였나** (`setPiece.kickoff.compress=false` 대조군): LW/RW 가 상대 진영

*"서로 상대 진영에 배치된 게 아니라 중앙부터 배치 시작해야 돼"* 가 그대로 재현된다.

⚠️ 골 세리머니 정지(25틱) 중에도 목표가 킥오프 배치다 — 안 그러면 세리머니 동안 앞선이 상대
진영으로 걸어 들어갔다가 재시작 틱에 도로 튕겨 나오는 "왔다 갔다"가 보인다.

## 4. 이 웨이브가 **의도적으로 남긴 것** (일괄 리뷰 안건)

1. **볼륨이 내려갔다.** 10시드 대조(스위치 3개 on/off): 팀당 슛 9.85 → **6.50** · 팀당 골 2.35 → **1.60**.
   프리킥을 드리블로 재개하던 것이 사라지면서(그게 골문 쪽 전진이었다) 공격 볼륨이 준 것이다.
   60시드 밴드는 **전부 통과**한다(슛 7.23 · 골/팀 1.54 · 전환 20.89% · 유효슛 2.95 · 슛당 xG 0.20).
   **계수는 안 건드렸다** — hero 방침대로 볼륨 재보정은 트랙 T 소관이다.
2. **롱패스 시도 비율 8.07%**(밴드 하한 11.5) — **#372, 기지 선행 RED**. 스위치 3개를 끈 대조군에서도
   9.1% 로 이미 빨갛다. 재시작이 전부 짧은 패스가 되며 분모가 커져 1.0%p 더 내려갔다.
   #372 가 지적한 대로 이 지표는 **분모 문제**라 값이 아니라 밴드 정의가 수리 대상이다.
3. **`shot-outcomes.spec.ts` one_on_one RED** — **기지 선행**. `origin/release/engine-v2` 의 쇼케이스
   데모도 `oneOnOne: 0` 이다(별도 워크트리에서 확인). 45분 레짐에서 #316 의 빈도 미달
   (0.517/경기)이 그대로 드러난 것이고 이 웨이브와 무관하다.
