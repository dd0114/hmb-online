# data 모듈 가이드 (도메인 세션용 CLAUDE.md)

이 디렉토리는 **선수·경제 시드 데이터 도메인**이다. 이 모듈 세션은 `data/**`만 소유한다.

## 필독
1. `docs/plan-v2/PRD-v2.md` §3.1 (AC-D1~D4) + `docs/plan-v2/LLD-data.md` (분포·밴드·스키마)
2. `docs/plan-v2/grade-mapping-v2.md` (v2 실선수 등급 매핑 기준, **§9 = v2.2 LEGEND 개편 델타**) + 에픽 이슈(data) STATE

## 규칙 (위반 금지)
- **실선수 이름·데이터 사용 허용 (v2~, 이슈 #84 hero 결정)** — 큐레이션 로스터(`roster.ts`)로 유명 실선수를 등급 매핑해 발행한다. 등급 배정 기준은 `docs/plan-v2/grade-mapping-v2.md`.
  - ⚠️ **백로그(상용화 차단 항목): 초상권/실명·데이터 라이선스 해결 필수.** PoC 한정 실명 사용이며, 상용 배포 전 반드시 라이선스를 확보하거나 가상화한다. (PRD-v2 §7 비범위 "실선수 라이선스 데이터"와 정합.)
  - (v1 이력: PoC 가상풀 전제로 '실선수 금지'였음 — v2에서 전량 교체 시점 도래하며 갱신.)
- 산출물은 **버전 파일로만 발행**(`players.v2.json` 등). 발행 후 수정 금지 — 바꾸려면 다음 버전 + 소비자(server-java) 조율.
  - 현행 발행 축: `players.v2.json`(172, 동결) → `v2.1`(+personality, 동결) → `v2.2`(+신규 8종 = 180, +`active` 필드, 동결) → `v2.3`(+유닛명 정정 2 · 신규 비활성 3, 동결) → `v2.4`(+신규 LEGEND 2종 = 182, 동결 — #256 석다이크·오시야스) → `v2.5`(능력치 9종 재롤 = 182, 동결 — #405 초기 스탯 하향) → **`v2.6`(선수명 한글화 + `shortName` = 최신 발행본 — #406 요구 6)**.
    - ⚠️ **번호가 두 트랙에서 동시에 올라갔다**(#405 ↔ #406). 두 축은 직교한다 — #405 = `attributes` 재롤 · #406 = `name`/`shortName`. #405 가 `v2.5` 를 먼저 발행했고 **발행 후 수정 금지**라 한글 층은 `v2.6` 으로 올라가 **v2.5 를 입력으로** 받는다(`buildPlayersV26`). 즉 v2.6 = 하향된 스탯 + 한글 이름. 병렬 트랙이 같은 발행 축을 쓸 때의 표준 처리다.
    - ⚠️ **현재 라이브 소비본은 `v2.5`** 다(#405 가 스위치). `v2.6` 으로의 스위치(`application.yml` 의 `hmb.data.players-file` · `server-java/Dockerfile` 의 `HMB_DATA_*`)는 **server-java 소관**이라 별도 이슈로 요청한다 — 스위치+배포 전까지 라이브 이름은 안 바뀐다.
    - ⚠️ **동결 경계가 셋이다**: `FROZEN_ROSTER_COUNT`(172 = v2/v2.1) · `FROZEN_ROSTER_COUNT_V22`(180 = v2.2/v2.3) · `FROZEN_ROSTER_COUNT_V24`(182 = v2.4). 로스터에 append 하면 **세 경계 모두** 슬라이스로 과거 발행물을 재현해야 한다 — v2.2 빌더가 전체 로스터를 받고 있었던 탓에 #256 이 두 번째 경계를 새로 만들었고, #405 가 v2.5 재롤을 얹으며 세 번째가 생겼다.
    - ⚠️ **밴드 축도 둘이 됐다**(#405): `GRADE_BANDS`(40-55…80-95, 폭 16, 바이어스 +5/+6 — v2~v2.4 발행물이 구워진 값, **절대 수정 금지**) · `GRADE_BANDS_V25`(32-42…68-78, 폭 11, 바이어스 **+3/+4** = `PRIMARY_BIAS_V25`/`TRAIT_BIAS_V25`, v2.5 전용). `rollAttributes` 의 `bands`·`bias` 인자 기본값이 구 값이라 과거 빌더는 인자 없이 그대로 돈다.
    - 🚨 **함정: 밴드 폭을 줄이면 바이어스도 같이 줄여야 한다.** #405 1차 발행에서 실제로 밟았다 — 폭만 16→11 로 줄이고 +5/+6 을 그대로 뒀더니 **주스탯이면서 trait 인 스탯은 가산 합 +11 = 폭 전체**라 `lo + roll(0..10) + 11 > hi(=lo+10)` 로 **예외 없이 상한 클램프**됐다(실측 클램프율 79.4% → **100.0%**, 170/170). 그 스탯들은 롤이 무의미한 **상수**가 되고, 같은 (포지션, trait) 조합 카드가 그 스탯에서 전부 동일해진다 = 수집 게임에서 카드 개성의 소실.
      - 성장 여백과는 **무관**하다 — 신규 설계에서 성장 천장은 시작밴드 hi 가 아니라 별도 `growCeil`(server)이라 시작 상한에 박혀도 천장까지 여백이 남는다. 즉 하향의 목적은 지키고 상수화만 없애면 된다.
      - 규칙: **바이어스를 폭에 비례 축소**한다(5/16·6/16 ≈ 3/11·4/11). 계약 = `data.test.ts` 의 `degenerate 가드 — 바이어스 합(주스탯+trait) < 밴드 폭` + 구조적 하한 2건(`lo+3`/`lo+4`). 변이체 킬 확인 완료(+5/+6 으로 되돌리면 가드가 발화).
    - ⚠️ **data 는 시작 밴드만 발행한다**(설계 §2.8.1 경계). 성장 천장(72/78/84/90/95)·감쇠·XP 곡선은 전부 **server 의 `GrowthTuning`** 소관이고 data 에는 없다. 여기 있는 밴드는 **발행 시점 롤 전용**이지 런타임 튜닝 노브가 아니다.
  - **아티팩트별 부분 버전업**이 가능하다: `PLAYERS_V21_VERSION`(성격 추가), `ECONOMY_V3_VERSION`(#209 `starterTop` 추가).
    구파일은 바이트 불변으로 두고 새 파일만 발행한 뒤, 소비자 경로(`hmb.data.*-file` + `server-java/Dockerfile` 의 `HMB_DATA_*`)를 스위치한다.
  - `economy.starterTop.pool` = 가입 시 지급하는 **최상위 후보**(#209, 현재 5종). **활성 유닛만 넣는다** —
    비활성은 신규 획득 차단이 정책이고 가입 지급은 신규 획득이다(#207 랜딩 때 구 pool 전원이 비활성이 돼 실제로 교체했다).
- 생성 결정론: 시드 고정, 재실행 바이트 동일(AC-D2). `data.test.ts`가 게이트. 이름·포지션·등급은 로스터에서, 능력치 9종만 시드 RNG로 밴드 내 파생.
  - ⚠️ **로스터에 항목을 추가할 땐 반드시 배열 맨 끝에 append 한다.** `generateAll()` 이 `createRng(SEED)` 한 스트림을 `ROSTER.forEach` 로 순차 소비하므로, 중간 삽입하면 그 뒤 **전원의 스탯이 shift 되어 기보유 유저 카드가 전부 바뀐다**. 근거·증빙 = `grade-mapping-v2.md` §9.5.
- 다른 패키지 수정 금지(예외: 소비자 경로 스위치 등 매니저 사전 승인된 최소 변경). shared 스키마가 안 맞으면 이슈 레이즈.

## 표시명 축 (#406 요구 6 — v2.6 부터 두 축이다)

- **로마자 축 = `roster.ts` 의 `name`** — 시드 RNG 스트림의 순서이자 동결 발행물(v2~v2.5)을 슬라이스로
  바이트 동일 재현하는 기준. **절대 한글로 덮지 않는다.** 덮으면 그 재현 계약이 통째로 깨진다.
  (#207 U-D6 이 ROSTER 대신 `V23_NAME_CORRECTIONS` 를 쓴 것과 같은 이유.)
- **한글 축 = `names-ko.ts` → v2.6 레이어** — hero 확정 **안 C 하이브리드**(2026-08-02, #406):
  실선수 172명은 한글 음역 · 패러디 10명(P173~P182)은 현행 유지. 표에 `ko` 가 없으면 개명하지
  않는다(= 패러디 불변이 구조적으로 보장된다). `from` 앵커가 v2.5 발행물 이름과 다르면 빌더가 throw
  (#405 재롤은 `attributes` 만 바꿨으므로 그 앵커는 v2.4 영문명 그대로 성립한다).
- **가드는 축별로 갈렸다**(약화가 아니라 정밀화 — `data.test.ts`):
  - 라틴 문자 단언 + 3음절 금지 → **로마자 축 전용**(ROSTER/v2~v2.5). 원래 목적인 "v1 절차생성
    가상명 재유입 차단"에 그대로 유효하다.
  - `PARODY_REAL_NAME_KO_DENYLIST` → **패러디 유닛(P173~P182) 전용**으로 범위 명시. 목적이
    "패러디명이 실명을 베끼지 않는다"이므로 실선수 음역 6건(야신·마라도나·호나우두·벨링엄·
    음바페·비니시우스)은 정상 통과해야 하고, 그 대비를 테스트가 직접 박제한다.
  - 한글 축 가드는 v2.6 describe 에 신설: 한글 전용·빈 문자열 금지·길이 상한·id 유일·표시명 유일·
    `shortName` 무결성(중복은 알려진 2쌍 오나나·루이스만 허용, 그 외 신규 중복은 실패).
- ⚠️ **기계가 못 잡는 잔여 리스크 = "올바른 행에 붙었나"**(독립검증 minor-2). `from` 앵커는 id 별이라
  **두 행의 `ko` 를 통째로 맞바꿔도** 앵커·무결성·유일성 가드가 전부 통과한다(엉뚱한 선수가 남의
  이름을 갖는다). 표기 자체는 hero 가 세션 재량으로 위임했고 정정 경로가 어드민 개명이라 실질
  위험은 낮지만, **표를 대량 편집할 땐 사람이 눈으로 대조해야 한다** — 계약이 지켜 주지 않는다.

### `shortName` 을 왜 시드에 넣었나(선택지 3안 비교)

밀집 UI(덱 행·전술보드 슬롯·경기 토큰·로그줄)는 풀네임(최대 12자)이 안 들어간다. 세 안 중 **ⓐ v2.6 시드
필드**를 골랐다.

- ⓐ **채택 — 발행물 필드**: 풀네임과 **같은 채널**(서버 카탈로그)로 흐른다. 이게 결정적이다 —
  한글 풀네임 자체가 서버의 v2.6 스위치+배포로만 도착하므로, 짧은 이름을 다른 채널로 보내면
  "짧은 건 한글인데 풀네임은 영어"인 **혼재 상태**가 생긴다. Jackson `FAIL_ON_UNKNOWN_PROPERTIES=false`
  (`server-java/.../common/Json.java`)라 서버가 DTO 를 노출하기 전에도 임포트는 안전하고, web 은
  값이 없으면 `name` 으로 폴백하면 된다.
- ⓑ 기각 — **별도 빌드타임 산출물**(`player-names.v1.json`, `player-chars.v2.json` 선례): 서버 무관하게
  즉시 쓸 수 있지만 위의 혼재 상태를 만든다. 아트 매핑(chars)은 런타임 상태가 아니라 정적 자산이라
  그 선례가 성립했던 것이고, 이름은 어드민이 잠그고(`admin_locked`) 바꿀 수 있는 **런타임 상태**다.
- ⓒ 기각 — **규칙 파생 + 예외표**: 한글 음역에 "성만 남기기"의 기계 규칙이 없다(전치사 성 "판 바스턴",
  단일 토큰 "손흥민", 1자 "텔"). 예외표가 곧 표 전체가 된다.
- **web 에 이름 표를 복제하는 안은 금지**(SoT 이중화) — web 은 카탈로그 응답만 소비한다.
