## 0. 목표

수집형 카드 시스템으로 **"좋은 호날두를 뽑으면 계속 뽑고 싶게"** 만든다. 세 기둥:
1. **여러 버전의 같은 선수** — 같은 호날두를 Base/이벤트/레전드 등 여러 버전으로 보유·추격.
2. **강화** — 뽑은 카드를 중복·재료로 더 강하게(중복이 죽지 않게).
3. **투트랙 뽑기** — ① 무작정 스카우트 + ② **오퍼(가오레식 일일 만남)**. 오퍼는 P2P 트레이드 없이 "거래" 재미를 준다.

**HMB 차별점 정합:** 버전마다 고유 프롬프트 프리셋을 얹어 "선수별 자연어 프롬프트" 컨셉과 시너지. (엔진/시뮬은 무변경 — 카드 시스템은 능력치·프롬프트 입력만 바꾼다.)

## 2. 시스템 상세

### D1. 버전축 — 여러 버전의 같은 선수

- **선수 identity = `baseId`**(예: 호날두), **카드 instance = `versionId`**(예: 호날두·BASE / 호날두·LEGEND).
- 한 baseId 아래 여러 버전 카드가 존재. **버전이 등급을 결정** — 예: 호날두 BASE=GOLD, 이벤트=DIA, 레전드=LEGEND. "더 높은 버전 = 같은 선수의 더 높은 등급 카드."
- **버전 종류(PoC 범위):**
  - `BASE` — 기본 카드(모든 선수 보유). #84 실선수 풀이 여기 매핑.
  - `SPECIAL`/`LEGEND` — 스타 선수 한정 상위 버전(전성기·레전드). PoC엔 마퀴 선수 소수만 시드.
  - `EVENT` — 이벤트 배너 한정(추후 발행). 데이터 스키마만 준비.
- **버전 고유 프롬프트 프리셋(선택):** 상위 버전은 시그니처 프롬프트 동봉 가능(예: 레전드 호날두 = "박스 안 킬러 본능"). HMB 고유 시너지.

### D2. 강화 (Enhancement)

- 보유 카드 instance마다 **강화 레벨** `level`(0 → 상한). 강화 시 주스탯 소폭↑(EngineConfig 계수, 결정론).
- **재료:** ① 동일 versionId 중복(1순위) ② 범용 강화 재료/타 카드 ③ 포인트.
- **한계돌파:** 기본 상한(예 +5)을 **동일 선수 중복**으로 단계 개방(예 → +10). 중복이 항구 수요를 갖게 하는 게이트.
- **최종 능력 = 등급 밴드 기본 + level 보너스**(밴드 상한 소폭 초과 허용). 전부 config.
- **결정론 불변:** 강화·돌파는 계수 + 시드로만. `Math.random`/`Date.now` 금지, 고정소수, 골든 스냅샷 유지.

### D3. 투트랙 뽑기

#### 트랙 1 — 스카우트 (무작정 뽑기)
- 기존 시드 뽑기 유지·계승. 단뽑/10연, 확률표(economy), GOLD↑ 보장, 시드 결정론.
- 순수 확률 랜덤 배출 — "많이 돌리면 좋은 카드" 트랙.

#### 트랙 2 — 오퍼 (일일 만남) 〔가오레 영감〕
> 포켓몬 가오레의 "하루 특별한 만남 + 확률적 확정"을 **축구 이적 오퍼**로 번안.

- **일일 3개 오퍼 동시 등장**(매일 리셋). "오늘은 누가 우리 팀에 오퍼를 넣을까" = 리텐션 훅.
- **오퍼 = NPC(가상 클럽/에이전트)가 좋은 카드(제안 카드)를 주는 대신 내 보유 카드를 요구.**
- **오퍼 유형 2종:**
  - **지명 오퍼(Targeted):** NPC가 내 풀에서 **특정 카드를 콕 집어** 요구. "P045(호날두·GOLD)를 넘기면 [레전드 카드]를 주겠다." 받을 카드·줄 카드 확정.
  - **공개 오퍼(Open):** NPC가 **조건만 제시**("총 가치 ≥X, GOLD↑ 2장" 등). 유저가 **자기 카드 조합을 자유 제안** → 조건 충족 시 성사.
- **확률적 확정(가오레 핵심):** 3개 중 일정 확률로 **"확정 오퍼"**(반드시 성사 가능한 고가치 — 상위 버전/LEGEND) 등장. 안 뜨는 날도 있어 기대감.
- **지불 = 보유 카드**(포인트 아님) → 중복·잉여 카드의 배출구. P2P 트레이드 없이 "거래" 재미.

**두 트랙의 역할 분담:** 스카우트 = 물량·확률, 오퍼 = 일일 기대·카드 순환·핀포인트 획득.

### D4. 중복 처리 (3단 배출구)

1. **강화·한계돌파 재료** (동일 versionId 중복 최우선).
2. **오퍼 지불 수단** (지명/공개 오퍼에 내 카드로 지불).
3. **포인트 환급**(초과분) — 뽑기 비용 대비 낮게(인플레 방지).

→ 죽어 있던 `user_players.count`가 세 배출구로 항구 가치를 가짐.

### D5. 덱 연결 (게임플레이 영향)

- **한 덱에 같은 baseId 2버전 동시 편성 금지** 권장(같은 사람은 한 명). `UNIQUE(deck_id, player_id)` → `UNIQUE(deck_id, base_id)`.
- 유저는 "어느 버전의 호날두를 넣을까"(능력·프롬프트 최적) 선택 = 전술 재미.
- ⚠️ **hero 확인 필요**(§4 O1).

### D6. 트레이드 (백로그)

- P2P 카드 교환은 **나중**(C6). 지금은 NPC 오퍼가 대체. 오퍼 시스템이 향후 P2P 트레이드로 확장되는 기반.

## 3. 스키마·모듈 영향 (ERD 델타)

> 상세 DDL은 server-java 웨이브에서 확정. 여기선 방향만.

- **players** (data #84 조율): `base_id TEXT`(선수 identity), `version TEXT`(BASE/SPECIAL/EVENT…), `signature_prompt TEXT?`. v2는 `base_id = id`(1:1)로 시작 → **무마이그레이션 대비(#84에 지금 심기 권장)**.
- **user_players**: `level INTEGER`, `limit_break INTEGER`, `copies_used INTEGER` (강화 상태).
- **신규 `offers`**: `id, user_id, offer_date, kind('targeted'|'open'), reward_version_id, required_json(지명 카드 or 조건), is_guaranteed, status('open'|'accepted'|'expired')`. 일일 생성(결정론 시드).
- **deck_slots**: UNIQUE 제약 `player_id` → `base_id` 승격(D5 확정 시).
- **economy**: 오퍼 생성 확률표·확정 확률·환급률 추가.
- **엔진(`packages/engine`)·시뮬 계약: 무변경.** 카드 시스템은 SelectData의 능력치·프롬프트 입력만 바꾼다.

## 4. 세부 결정 (hero 확정 2026-07-19 — 기본값 락)

- **O1. 덱 규칙:** 같은 baseId 2버전 동시 편성 **금지**. `UNIQUE(deck_id, base_id)`.
- **O2. 버전 시드 범위(PoC):** BASE 전원 + **마퀴 상위 ~10명에 LEGEND/SPECIAL 버전**. (정확 명단은 data #84 판단.)
- **O3. 오퍼 일일 개수:** **3개 고정**(가오레식). 확정 오퍼는 **낮은 확률** 등장(수치는 economy 튜닝).
- **O4. 오퍼 지불 밸런스:** 요구 카드 가치 = **등급 + 강화 반영** 산정.
- **O5. 강화 상한/계수:** **기본 +5 / 돌파 +10**. 스탯 상승폭은 EngineConfig 계수(밸런스는 QA 튜닝).
- **O6. 중복 환급:** **도입**. 뽑기 비용 대비 낮은 환급률(인플레 방지).
- **O7. #84 base_id 지금 심기:** **확정 — v2에 base_id 컬럼 심기**(v3 무마이그레이션).

> 위 수치는 방향 확정값. 정밀 밸런스(확정확률·환급률·계수)는 각 모듈 웨이브에서 economy/config로 튜닝.

## 5. PoC 최소 도입분 (첫 웨이브 스코프)

1. **강화**(D2) — 죽은 count 되살리기, user_players 강화 컬럼 + 서버 강화 API + web 카드 상세.
2. **버전 스키마**(D1) — base_id/version 컬럼 심기. PoC 데이터는 BASE 위주 + 마퀴 소수 SPECIAL.
3. **오퍼 뽑기 MVP**(D3 트랙2) — 일일 3오퍼(지명형 먼저), 카드 지불, 확률적 확정. 공개형·EVENT 배너는 다음 웨이브.
4. 트랙1 스카우트 = 기존 유지.
