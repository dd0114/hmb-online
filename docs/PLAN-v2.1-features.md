## 2. Track α — 엔진 리얼리즘 & 밸런스 (직렬)

### α0 = E3 리얼리즘 갭 분석 (선행 · 리서치)
- **목표**: 현 엔진 게임양상을 실제 축구(`research/football-stats.md`) + 축구게임 엔진(FM/ESMS/open-football)과 대조해 **부족분 목록 + E1/E2 목표치·범위**를 데이터로 확정. 헛튜닝 방지.
- **방법**: `defaultEngineConfig`(리얼) 다수 시드 시뮬 → `tools/qa-match.mjs`/`match-stats.ts` 스탯 산출 → 벤치와 비교표. 정성 관전(독립 QA)도.
- **현 엔진 부족분(초안 — α0에서 확정)**: ①롱볼/스루패스 없음(액션 4종뿐) ②오픈플레이 크로스 없음(코너만) ③패스 성공률 균일(패스타입/압박강도 반영 약함) ④템포/모멘텀 변주 약함 ⑤선수 능력치 영향폭 좁음.
- **산출**: `research/engine-realism-gap.md`(비교표 + 우선순위) → E1/E2 AC 목표치 확정.
- **AC(초안)**: 벤치 대비 편차표 완성 · E1 목표(패스성공률 78–85%) · E2 범위(롱패스 12–15% 비율) 확정 · 나머지 갭은 백로그 우선순위화.

### α1 = E1 패스 정확도 하향 (config 튜닝)
- **현재**: `planPass()`(`decision.ts:129`) `prob = passBase 0.84 − 페널티들 + 속성보정`, clamp(0.05,0.98). 실측 성공률 벤치 상한(85%) 초과 추정.
- **방향**: **config만으로**(하드코딩 금지) 성공률을 벤치(78–85%)로. `passBase`·`passDistancePenalty`·`passPressurePenalty`·`passForwardPenalty` 등 조정. E3 목표치 기준.
- **AC(초안)**: 리얼 config 실측 패스성공률 78–85% · 롱/전진 패스가 숏보다 유의미하게 낮음 · `perceptibility 6/6`·`qa-match` 유지 · 골든 갱신·desync0 · 독립 QA(경기 양상 자연) PASS.

### α2 = E2 롱패스/롱킥 액션 추가 (엔진 피처)
- **현재**: `Action = shoot|pass|dribble|hold`(`decision.ts:20`), 롱 개념 없음. 거리 페널티만.
- **방향**: 롱패스(또는 pass 의 long 변형)를 액션/판정에 추가 — 거리 임계·성공률 곡선·리시버 선택(전진 롱볼)·오픈플레이 롱킥(GK/수비 클리어). config knob 신설(§2-4). MatchEvent detail(long) 로 뷰어가 구분 가능하게(β3 이펙트 연동).
- **AC(초안)**: 롱패스 비율 벤치(12–15%) 근접 · 롱패스 성공률이 숏보다 낮음(현실적) · 결정론 유지(골든·desync0·resume·hygiene) · qa-match·6/6 · 독립 QA PASS.
- **shared 계약**: MatchEvent 에 long 구분 추가 시 `packages/shared` 조율(β와 프리즈).

## 3. Track β — 뷰어 & 인게임 HUD (직렬, 뷰어 전용·골든 무영향)

### β1 = R3 이펙트/자막 영어화 (선행 · i18n)
- **현재**: 자막/티커/토스트/배너 전부 한국어(+이모지). `playback.mjs`(CAUSE/SETPIECE/PAUSE 테이블·buildAnnotations), `index.html`(EV_LABEL·bigCaption·situationCaption).
- **방향**: 표시 텍스트 전부 영어("GOAL!", "SAVE!", "FOUL", "OFFSIDE", "PENALTY!", "CORNER", "THROW-IN", …). 이모지 유지 가능. QA 세션도 영어로 읽음(무리 없음). **글로벌 대상 제품.**
- **AC(초안)**: 캔버스/DOM 표시 텍스트에 한글 0 · e2e 자막 계약(captions.spec 등) 영어로 갱신 green · playwright green.

### β2 = R1 공 궤적 = 소유팀 색
- **현재**: 공 트레일 노랑 고정(`index.html:285`), 선수 잔상만 팀색.
- **방향**: 공 트레일 세그먼트를 **그 구간 소유팀 색**(home 파랑/away 빨강)으로. 소유권은 스냅샷 `ballOwner`/`ownerSide`. 비행 중(패스/슛)은 출발팀 색. 루즈볼은 중립(현 노랑/회색).
- **AC(초안)**: 트레일 색이 소유팀과 일치(실화면 캡처) · 데드볼 컷 구간 처리 유지 · playwright green · 독립 QA PASS.

### β3 = R2 패스성공·가로챔·돌파 이펙트 강화
- **현재**: 토스트("슛!/차단/돌파!")뿐, 링/파티클은 골·유효슛만.
- **방향**: 패스성공(짧은 연결선/펄스), 가로챔(인터셉트 플래시/색 전환), 돌파(스피드 라인/트레일 강조) 등 **재미 이펙트**. 과하지 않게(관전 가독성 6/6 유지). α2 롱패스도 별도 이펙트 검토.
- **AC(초안)**: 이펙트가 이벤트와 정합(실화면) · `perceptibility 6/6` 유지 · playwright green · 독립 QA(재미 + 클러터 아님) PASS.

### β4 = R4 카드 = 받은 선수 표시
- **현재**: `🟨/🟥` 토스트를 파울러 위치에 앵커(#69), 티커는 playerId. **선수 이름/번호 강조 없음.**
- **방향**: 카드 시 받은 선수(번호/이름)를 명확히 — 카드 자막에 선수 식별자 병기 + 해당 마커 하이라이트/카드 아이콘. (선수 이름 데이터는 SelectData 에 있으면 사용, 없으면 번호.)
- **AC(초안)**: 카드 발생 시 받은 선수 번호/이름이 화면에 명확 표시(실화면 캡처, 실제로 좌표 오판 실적 있음 — §2.2) · 티커에도 · playwright green · 독립 QA PASS.

### β5 = F2 상세 경기 로그
- **현재**: `#ticker` 타입별 색, 클릭 점프. 굵기/상세도 없음.
- **방향(FM 코멘터리 참고)**: 시간순 피드, **중요(골/카드/교체/PK)=굵게+아이콘·큰 글씨**, **덜중요(슛/코너/파울/스로인)=작게·흐리게**. 슛/카드/**교체** + 더 디테일한 항목(어시스트·xG·경합 등). 교체는 엔진 이벤트 필요(현재 sub 이벤트 유무 확인 → 없으면 α/shared 조율 또는 뷰어 표시만).
- **AC(초안)**: 로그가 중요도별 타이포(굵기/크기) 구분 · 슛/카드/교체 포함 · 클릭 점프 유지 · playwright(티커 계약) green · 독립 QA PASS.

### β6 = F1 실시간 경기 통계 HUD (최대 규모)
- **현재**: `match-stats.ts` 스탯 다수 있으나 **종료후 일괄·화면 미연결**, 점유율 필드 없음.
- **방향(FM/중계 참고)**: 경기 진행 중 **실시간 갱신** 패널 — 점유율%, 슛(총/유효), xG, 패스성공%, 코너·파울·오프사이드·카드, (선택) 모멘텀/압박 바·진영 점유·공격패턴. `match-stats.ts`를 **현재 틱까지 증분 계산**하도록(또는 뷰어에서 tickSnapshots 누적) + 패널 DOM. 폰/데스크탑 반응형.
- **표시 우선(연구 후 확정)**: 점유율 · 슛(총/유효) · xG · 패스% · 코너/파울/카드 · 모멘텀 바. 나머지(공격패턴 heatmap 등)는 다음 단계.
- **AC(초안)**: 재생 중 통계가 실시간으로 갱신(실화면) · 점유율 등 벤치 정합(qa-match/match-stats 일치) · 결정론 무영향(뷰어) · playwright(패널 계약) green · 독립 QA PASS.
- 참고: F1 은 규모가 커 β6 을 **하위 2단계**(HUD 기본 스탯 → 고급 시각화)로 다시 쪼갤 수 있음(구현 세션 판단).
