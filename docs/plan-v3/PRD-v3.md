## 1. 모듈별 요구 + AC

### A. 로그인/OAuth 목 (server+web)
- **AC-A1**: 로그인 화면에 구글/애플/게스트 3버튼. 구글/애플 클릭 → mock 동의 화면(모사) → 닉네임 입력(최초) → 세션 발급. `users.auth_provider`에 'mock:google' 등 기록.
- **AC-A2**: AuthProvider 인터페이스에 provider 파라미터 — 실 OAuth 구현체를 추가해도 컨트롤러 불변임을 주석+테스트로 증명.

### B. 프리셋 개편 + 전술보드 (web 중심, server API)
- **AC-B1**: 팀 스냅샷 3슬롯 저장/로드/이름변경/복제. 스냅샷 = formation·starters(슬롯 매핑)·bench·선수별 프롬프트·수동 팀 전술.
- **AC-B2**: 브리핑에서 스냅샷 선택 후 **모든 요소 수정 가능**(덱 화면과 동일 편집기 재사용). 킥오프 시 최종 상태가 매치 스냅샷.
- **AC-B3**: **드래그앤드롭 전술보드** — 피치 위 선수 토큰을 끌어 배치(포메이션 슬롯 스냅), 벤치↔선발 드래그 교체. 모바일 터치 지원.
- **AC-B4**: 선수 토큰 탭 → "전술 지시(익숙한 축구 UI: 역할/성향 토글) + 프롬프트(자유 문장)" 2단 구성 — 두 레이어가 구분돼 보임.
- **AC-B5**: 팀 파워 = 선발 11 능력치 합(+컨디션 반영 전 기준) 상시 표시, 상대 팀 파워와 비교 표시(브리핑).

### C. 매치 확장 (server+servants+web)
- **AC-C1 컨디션**: 매치 생성 시 선수별 컨디션(0.0~1.0, 시드 결정론) 롤 → 시계 UI(12시=최고/6시=최저)로 브리핑·라인업에 표시 → SelectData 배율 적용 실효. 같은 매치 재현 시 동일 컨디션.
- **AC-C2 마킹**: "손흥민 막아", "메시랑 음바페 둘 다 마크해" 류 프롬프트 → 해당 선수 markTarget 매핑(복수 지시 = 복수 수비수 배정). E2E로 인풋 반영 증명.
- **AC-C3 지시 카탈로그**: directives/ 디렉토리에 지시 플러그인(마킹·오버랩·침투·롱볼 등 초기 6종+). **1파일 추가/삭제로 지시 증감**이 되는 구조 증명(테스트: 카탈로그에서 1종 제거해도 나머지 동작).
- **AC-C4 관계**: 성격(선수 데이터)·신뢰도(기용/승패/교체로 변동, 규칙 config)·팀 사기(연승/연패) 저장·표시. AI 컨텍스트에 주입 — 신뢰도 낮은 선수는 지시 반응성↓(mentalModifier), 유리멘탈은 질책성 프롬프트에 역효과 등 **성격별 반응 규칙을 프롬프트에 명시**. 방향성 검증(라이브 or stub 계약).
- **AC-C5 AI 예산**: 피처(컨텍스트 블록)당 AI 시간·토큰 증분 측정 하네스(`tools/` 또는 servants 테스트) — 컨디션/관계/지시 카탈로그 각각의 증분 리포트. 상한: 컨텍스트 추가로 **출력 토큰 +10% 초과 금지**(입력은 무관), 하프당 체감 대기는 #82 개선치 유지.

### D. 트레이드 탭 (server+web)
- **AC-D1**: 슬롯 3개, 각 슬롯에 FA 또는 트레이드 오퍼 생성(레어도 가중 랜덤, 시드 저장). 레어도별 대기시간(BRONZE 1h ~ LEGEND 72h, config) 후 오퍼 공개.
- **AC-D2 FA**: 대상 선수 제시 → 유저가 보유 선수+포인트 자유 구성 제안 → 가치 비교 확률(곡선 config)로 성공/실패. 실패해도 제안 자원 소실 없음(재제안 쿨타임 config).
- **AC-D3 트레이드**: 상대가 내 특정 선수 지목+대가 선수 제시 → 수락 시 높은 확률(config, 예 80%) 성공. 거절 → 슬롯 재대기.
- **AC-D4**: 대기시간 **포인트 소모 단축**(잔여시간 비례 비용, config) — 원장 기록·멱등.
- **AC-D5**: 성공/실패/거절 모두 로그 기록, 보유 풀 반영(트레이드 성공 시 내 선수 이탈 포함).

### E. 로그 탭 (server+web)
- **AC-E1**: 경기 기록 리스트(모드·상대·스코어·리그 라운드) + 상세(하프 로그 재생 링크).
- **AC-E2**: 랭킹 — 유저 간 승수/승률 리더보드 + 개인 기록(최다 득점 선수, 연승 등).
- **AC-E3**: 트레이드 이력 포함.

### F. 리그 모드 (server+web+data)
- **AC-F1**: 싱글 진입 시 연습/리그 선택. 리그 시작 → 시즌 생성: 봇 9팀(팀명·성향·로스터는 실선수 풀에서 시드 결정론 구성, 유저 보유와 중복 허용) + 더블 라운드로빈 18R 일정.
- **AC-F2**: 유저 경기 = 기존 풀 매치 플로우(AI+엔진). **봇전 8경기/라운드 = 간이 결과**(팀 능력치+홈어드밴티지 확률 모델, 시드 결정론) — 유저 경기 종료 시 해당 라운드 봇전 일괄 정산.
- **AC-F3**: 순위표(승점 3-1-0, 골득실→다득점→승자승), 일정표, 다음 경기 표시. 시즌 진행 상태 저장(중단 후 이어하기).
- **AC-F4**: 시즌 종료 → 순위별 포인트 보상(config) → 시즌 히스토리 기록 → 새 시즌 시작 가능.
- **AC-F5**: 리그 고증 문서화(참조한 실제 리그 규칙 명시 — 승점제·타이브레이커·홈어웨이).

### G. 모바일/웹 모드 (web)
- **AC-G1**: 전 화면 390px 기준 완성 + ≥1024px 확장 레이아웃(전술보드는 데스크탑에서 사이드 패널형). 가로 오버플로 0.

## 3. 에픽 분할(안)
- **p2-server** (`server-java/**`): A(백엔드)·스냅샷 API·C1/C4 메타·D 트레이드·E 로그/랭킹·F 리그 — Flyway V2.
- **p2-servants** (`packages/server/**`): C2/C3 지시 카탈로그·C4 컨텍스트 주입·C5 예산 하네스 — #82 A+B 구조와 통합 조율.
- **p2-web** (`apps/web/**`): A(화면)·B 전술보드·C 시계/관계 표시·D/E/F 탭·G 반응형.
