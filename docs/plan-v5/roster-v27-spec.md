### 0-2. ⚠️ 라이브 증거 하나는 **혼자서는 결론을 못 낸다**

*"3,260행 중 2★ 이상이 1행"* 은 풀 희석만의 결과가 아니다 — **뽑기를 한 유저가 195명 중 20명뿐**이고(single 6 + ten 50 = 총 56회 = 556장) 지갑 젬 평균 **약 1.1만**으로 **거의 아무도 안 쓰고 있다**. 즉 관측된 "성★ 미작동"은 **확률 구조 + 뽑기 볼륨** 둘의 합이다.
그래서 §1 판정은 **라이브 관측이 아니라 "수입을 전부 뽑기에 쓰는 유저" 시뮬레이션**으로 한다(그게 구조를 재는 자[尺]다). 구조를 고쳐도 볼륨이 안 오르면 체감은 안 바뀐다 — **볼륨은 이 에픽의 스코프 밖**이고, 그 사실을 여기 남긴다.

### 1-2. 왜 이 숫자인가 — 설계 규칙 3줄

1. **골격 = `GK2 / DF4 / MF4 / FW3` (13종)** 을 **모든 등급에 동일하게** 깐다. 이 비율(GK 15.4% · DF 30.8% · MF 30.8% · FW 23.1%)이 **덱 18장 수요**(GK 11.1% · DF 33.3% · MF 30.6% · FW 22.2%)에 가장 가깝다. 등급마다 포지션 골격이 같으면 **어느 티어에서도 같은 포메이션을 짤 수 있다** = 등급 업그레이드가 "포지션 갈아타기"를 강요하지 않는다.
2. **예외는 LEGEND 하나** — 10종(GK2/DF1/MF3/FW4)은 **패러디 로스터가 그대로 결정한다**(hero D3 "패러디는 남기고"). 종수를 골격에 맞추려면 신규 패러디명 + 신규 유닛 아트가 필요한데 둘 다 hero 소재 축이다.
3. **`62 = 10 + 13×4`** — hero D1 "61종 안팎 또는 그 이하" 대비 **+1**이고, 그 +1 은 hero 가 H3 에서 직접 켠 **P178 석신**이다. 골격을 12종(`MF3`)으로 내리면 58종, 14종(`DF5`)으로 올리면 66종이라 **13이 그 부근에서 가장 큰 골격**이다.

## §4. 보상 산식

hero D4 = *"뺏으면 선수당 다이아를 주거나 같은 선수 카드 줘서 강화하게하면돼."* + H6 회신 = **"×3 이상 넉넉하게"**.

### 4-1. 젬 값은 **뽑기 가격에서 역산**한다 (임의 숫자 금지)

카드 1장 단가 = `tenCost / tenCount` = **3,000 / 11 = 272.73젬**.
등급 `g` 카드 1장을 얻는 기대 비용 = `272.73 / P(g)` (등급 롤이 먼저이므로).

| 등급 | P(g) | 272.73 / P(g) | **G(g) (100 단위 반올림)** |
|---|---|---|---|
| BRONZE | 0.45 | 606.1 | **600** |
| SILVER | 0.30 | 909.1 | **900** |
| GOLD | 0.15 | 1,818.2 | **1,800** |
| DIA | 0.08 | 3,409.1 | **3,400** |
| LEGEND | 0.02 | 13,636.4 | **13,600** |

### 4-2. 대체 카드 매핑 `sub(X)` — 결정론

> `sub(X)` = X 와 **같은 (등급, 포지션) 칸의 잔류 카드** 중 **`fit` 최근접**(동률이면 id 오름차순).

- **같은 은퇴 카드는 항상 같은 잔류 카드로 간다** = 유저 간 공평 + 재실행 멱등(우편 ops 를 두 번 돌려도 결과가 같다).
- `fit` 최근접이라 **유저가 잃은 것과 가장 비슷한 카드**를 받는다(등급·포지션·역할 프로필 보존).
- 전량 매핑은 **§3-2 표의 마지막 열**에 있다. **20개 칸 전부에 잔류 카드가 ≥1종** 이므로 이번 개편에서 매핑 실패는 **0건**이다.

### 4-3. 산식 (W2 우편 ops 가 집행)

은퇴 카드 `X`(등급 g, 포지션 p)에 대해, 유저의 `user_players` 행 `(count = n, copies_used = u)`:

```
소실장수 N = n + u            ← 이미 성★ 에 태운 중복(copies_used)도 되돌려 준다
R-1 (기본)  sub(X) ≠ null  →  PlayerGrant(sub(X), N × MULT)      , MULT = 3
R-2 (폴백)  sub(X) = null  →  gems += G(g) × N
```

- **`MULT = 3` 은 hero 결정**(H6 "×3 이상 넉넉하게"). 계량 근거도 같은 방향이다 — **×1 은 475행을 2장에서 멈춰 세운다**(2★ 조건이 **3장**이라 한 장 차이로 목표를 못 넘긴다). ×2 면 2★ 조건 충족이 529행, **×3 이면 607행 + 3★ 92행 + 4★ 17행**까지 열린다(§4-4). 1:1 은 "손실 보전", 그 위는 "회수 보정"이다 — **파생된 값이 아니라 정책 선택**이고, W2 파라미터 1개라 언제든 되돌린다.
- **R-2 는 이번엔 발화하지 않는다**(§4-2). 규칙을 남기는 이유 = 다음 개편에서 칸을 통째로 비우면 필요해진다.
- **왜 젬이 기본이 아닌가**: 젬으로 주면 유저는 그걸 다시 뽑기에 넣어야 하고, 뽑기는 다시 **등급 롤**이라 저등급 강화로 돌아온다는 보장이 없다. 카드로 주면 **그 자리에서 중복 = 성★ 재료**다. 그리고 젬 등가로 봐도 카드가 훨씬 크다 — 특정 SILVER 1장의 기대 비용은 `272.73 / (0.30/13)` = **11,818젬**이고 G(SILVER)=900 의 13배다.

### 4-4. 실측 — 지급 규모와 그 결과 (R1 스냅샷 · 회수 `N` 합계 = 748장 = 보유 746 + `copies_used` 2)

| | ×1 | ×2 | **×3 (채택)** |
|---|---|---|---|
| 지급 카드 총량 | 748장 | 1,496장 | **2,244장** |
| 1인 지급량 (중앙값 / 평균 / 최대) | 2 / 3.8 / 37 | 4 / 7.7 / 74 | **6 / 11.5 / 111** |
| 젬 지급 | 0 (R-2 무발화) | 0 | **0** |
| 지급 후 잔류카드 보유 장수 분포 | `1:2119 · 2:475 · 3:57 · 4:15 · 5:11 · 6+:4` | `1:2041 · 2:111 · 3:419 · 4:41 · 5:33 · 6+:36` | **`1:2041 · 2:33 · 3:79 · 4:418 · 5:18 · 6+:88`** |
| **2★ 조건(3장↑) 충족 행** | 87 | 529 | **607** |
| **3★ 조건(6장↑) 충족 행** | 4 | 36 | **92** |
| **4★ 조건(11장↑) 충족 행** | 0 | 3 | **17** |
| (개편 전 기준선) | 중복 ≥1 보유 **108행** · 3장↑ **11행** · 실제 star>1 **1행** | | |

- **최대 수혜 카드 2종**: `P081 벤 화이트 → P078 얀코 브루센` **657장** · `P092 메이슨 마운트 → P094 알도 티라네` **606장**. 두 카드는 **스타터팩이라 사실상 전 유저가 이미 1장씩** 갖고 있으므로, ×3 이면 **1 + 3 = 4장 = 2★ 충족 + 3★ 진행 중**이 된다. 그게 위 분포에서 `4장: 418행` 이 튀어나온 이유다.
- **개편 당일에 성★ 시스템이 처음으로 작동하는 것을 사실상 전 유저가 본다** — 서비스 시작 이래 2★ 는 라이브 전체에 **1행**뿐이었다.
- **전건을 젬으로 줬다면**(참고): 총 **738,100젬** · 1인 중앙값 약 1,800젬 — 지갑 평균 약 1.1만젬 대비 미미해서 **체감이 없다**. 카드 지급을 고른 두 번째 이유다.

### 4-5. 지급 수단

`MailAttachments(points, gems, List<PlayerGrant>)` 우편 1통 — 한 유저의 전 보상을 **`PlayerGrant(playerId, count)` 로 합산**해 담는다(같은 `sub(X)` 로 모이는 여러 은퇴 카드는 한 항목으로 합친다). 집행은 **W2**.
⚠️ 우편은 **v2.7 배포 후**에 보낸다 — 지급 대상이 잔류 카드라 카탈로그가 먼저 갱신돼 있어야 한다.
