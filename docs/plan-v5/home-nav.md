## 1. 문제 — 홈이 인덱스의 중복이다

hero: *"지금 홈 배치는 PoC 같다. 내비(인덱스)와 홈 화면이 더 확실하게 구분되어야 한다."*

현행 로비는 회색 버튼 4개(`게임 시작`·`덱 구성`·`상점`·`도감`)다. 이 중 **3개가 하단 탭바에 그대로 또 있다**
(덱·상점·도감). 즉 홈이 하는 일이 내비가 하는 일과 같아서, 홈은 "오늘 뭘 할까"에 답하지 못한다.
그리고 게임 모드(연습·리그·원정)는 **[게임 시작] 모달을 열어야만** 존재를 알 수 있다.

### 2.1 육성 + 도감은 신규 화면이 아니라 병합이다 (조사 결과)

`/growth`(육성)과 `/codex`(도감)는 **같은 코드**다 — 둘 다 `codex/CodexPage.module.css` ·
`codex/PlayerCard` · `codex/CardGrowthDetail` 을 쓰고, 차이는 육성이 `owned` 로 거른다는 것과
도감에만 등급 필터가 있다는 것뿐이다. 탭을 두 칸 쓸 이유가 없어 **[보유] / [전체] 세그먼트**로 대체한다.

미보유 카드는 **이미** 회색조 + `잠금` 뱃지로 그려진다. hero 가 말한 "실루엣만"은 신규 표현이라기보다
**더 확실한 실루엣화**(검은 전신 실루엣 + `？？？`)다. 아트는 hero 2R 결정으로 **얼굴 타일 → 전신**으로
바뀐다 — 정책 충돌과 아트 실태는 §3.5 참조.

## 3. 화면별 설계

### 3.1 홈 — 하단탭을 크게 펼친 런처 (hero 4R)

> 3차: *"홈 별도로 빼야지 가장 중요하잖아 … 최대한 간결하게."*
> 4차: *"홈화면을 그냥 밑에 하단탭에 있는거 크게 보여주는 느낌으로 가자. 홈화면때는 하단탭 안보이고."*

**홈 = 내비 그 자체**다. 하단탭의 5칸(게임·덱·선수·영입·내 정보)을 **큰 타일**로 펼치고,
**홈에서는 하단 탭바를 감춘다** — 홈이 내비인데 그 밑에 또 내비를 그릴 이유가 없다.
다른 탭으로 들어가면 그때부터 탭바가 나온다(홈으로 돌아올 길).

구성:
1. **팀 한 줄** — 대표 카드 썸네일 + 팀 이름 · 디비전/순위 · 포메이션/전력 · 레이팅
2. **타일 5개** — **전부 통칸**(hero 5R: *"반칸 나누지 말라"*). 이름·순서는 hero 지정:

   | # | 타일 | 부제(상태) | 이동 |
   |---|---|---|---|
   | 1 | **게임 시작** (더 크고 **색 있음** — 홈의 주인공) | 리그 10/18R · 원정 레이팅 | `[게임]` 탭 |
   | 2 | **덱 구성** | 4-3-3 · 지시 8/11 작성 | `[덱]` |
   | 3 | **영입** | 뽑기 · 트레이드 제안 N건 | `[영입]` |
   | 4 | **내 정보** | 12승 3무 8패 · 리그 4위 · 원정 12위 | `[내 정보]` |
   | 5 | **선수 도감** | 보유 18 / 40 | `[선수]` |

   게임 외 4개는 **회색 명도만** 쓴다(#244 색 규칙 = 의미 있는 색 4개).
3. **알림 한 줄** — 있을 때만

**타일마다 지금 상태를 한 줄** 단다 — 크게 보여주는 자리를 그냥 큰 버튼으로만 쓰면 아깝다.

⚠️ **하단 탭바 라벨은 짧게 유지**한다(홈·게임·덱·선수·영입·내 정보). 6칸에 "선수 도감"·"덱 구성"은
들어가지 않는다. **홈 타일 = 풀 네임 / 탭바 = 축약**이 짝이다.

**홈에 없는 것과 그 행선지** (근거 없이 되돌리면 홈이 다시 대시보드가 된다):

| 한때 홈에 있던 것 | 현재 위치 | 이유 |
|---|---|---|
| 연습/리그/원정 3카드 | **[게임] 탭** | 홈은 내비, 게임은 경기 |
| 내 팀 요약(선발·벤치·지시 작성률) | **[덱] 탭** | 덱이 이미 갖고 있다. 홈엔 한 줄만 |
| 팀 사기 / 컨디션 / 연승 | **[덱] · [내 정보]** | 라인업 짤 때 쓰는 값 |
| "오늘" 할 일 목록 | **타일 부제 + 알림 한 줄** | 목록이면 홈이 대시보드로 회귀 |
| 하단 탭바 | **홈에서는 숨김** | 홈이 곧 내비 — 같은 것을 두 번 그리지 않는다 |

⚠️ 구현 메모: 탭바 숨김은 `Layout`/`AppNav` 의 `nav` 플래그가 아니라 **현재 라우트가 홈인지**로
갈린다. `App.tsx` 가 홈 라우트에만 `nav` 를 끄는 형태가 가장 단순하지만, 그러면
**홈으로 돌아올 경로가 홈 화면 자신에만 존재**하게 되므로 다른 화면의 탭바에 `[홈]` 칸이 반드시
남아 있어야 한다(6칸 유지). 이 둘은 짝이라 한쪽만 바꾸면 홈이 막힌다.

**#245 피원정 팝업**은 트리거를 **[게임] 탭의 원정 카드 클릭**으로 옮긴다.
ack 규약·"행 클릭은 확인이 아니다"는 그대로.

### 3.1a 게임 탭 — 모드 선택만 한다

현행 [게임 시작] **모달이 화면으로 승격**된 자리. 카드 3장이 각자 상태를 단다:

- **리그** — 디비전 뱃지 · **N/18 라운드 진행바** · 현재 순위 · 다음 상대 → 리그 페이지
- **원정** — 레이팅 · 랭킹 · 연승 · 피침공 건수 + **복수 N 리본** → 원정 페이지
- **연습** — hero 확정 Q1: **최하단 · 무채색 · 축소**(리그·원정이 본 게임이고 연습은 시험대라는 뜻이 배치로 읽힌다)

### 3.1b 경기 진행 중 = 홈 전체 잠금 (hero 2R)

> *"홈화면에서 경기중이면 다른것들은 안되게하자. 경기 이어서하거나 포기해야해."*
> *"게임중에는 (강화) 비활성화여야해. 버그가 있을수 있을거같아."*

현행 `MatchLockGate`(#217)는 **누른 뒤에 되돌리는** 방식이다 — 화면은 다 보이고, 이동한 다음에
경기로 튕겨낸다. 그 사이에 **강화·덱 편집이 실제로 들어갈 창**이 있고, 경기 중 강화로 능력치가
바뀌면 진행 중인 시뮬이 쓰는 값과 어긋난다. hero 가 짚은 "버그가 있을 수 있다"가 이 자리다.

| 자리 | 경기 중 |
|---|---|
| 홈 | **잠금 배너만 활성**([이어하기] / [경기 포기]). **타일 5개 전부** 회색·클릭 불가 |
| 하단 탭 (홈 외 화면) | 홈 외 **5칸 전부 잠금**(자물쇠) |
| 게임 탭 | 같은 배너 + 모드 카드 잠금 |
| 덱 | 배치·프롬프트·지시는 **열어 둔다**(하프타임 지시를 써야 한다). **[⚡ 선수 강화] 줄만 잠금** |
| 선수 탭 | 강화 버튼 잠금 |

판정은 계속 **서버**(`GET /api/me/active-match` 의 `locked`/`abandonable`)가 한다 — 규칙을 클라에
복제하지 않는다. ⚠️ `shouldForceResume`(`locked && !abandonable`)을 `locked` 로 "단순화"하지 말 것 —
회수 가능한 사고 매치까지 붙잡으면 탈출구인 [경기 포기]에 영영 못 간다(#217 주석).

### 3.2 리그 페이지
- **상태 A(시즌 없음)**: `리그란?` 설명 + `하는 방법` 3스텝 + 내 디비전/승급강등 컷 + [시즌 시작]
- **상태 B(진행 중)**: 라운드 진행바(`N / 18`) + 다음 경기 카드[경기 시작] + 순위표(승급/강등 구역) +
  **리그 랭킹보드(신규)** + 일정
- 디비전 이름·승급/강등 컷은 **서버 값만** 쓴다(`season.divisionName/promoteRankMax/relegateRankMin`).
  클라가 추측하면 #262 BL-1(화면이 서버와 반대 사실을 말함)이 재발한다.

### 3.3 원정 페이지
`원정이란?` 설명 + 하는 방법 3스텝 → **내 점수**(레이팅·랭킹·연승·주간전적·시즌 종료까지·오늘 남은 횟수)
→ [원정 떠나기](현행 2택 모달 그대로) → **복수 큐 5건(신규)** → **원정 랭킹보드(신규)** → 지난 시즌.

### 3.4 덱 — 지시 레일에 [⚡ 선수 강화] 한 줄

⚠️ **1차 목업은 실제 화면을 안 보고 그려서 틀렸다**(hero 지적). 실물은 `deck/DirectiveRail.tsx` 의
선수 컨텍스트이고 구조가 이렇다 — 캡처 = `before/05c-deck-player-rail-tune.png`:

```
⑥ 선수 6 / MF                                   ✕
┌ 감독의 한마디            [AI가 읽는다] ────────┐
│ (프롬프트 textarea, 0/500)                     │
│           [⇄ 이 자리 선수 바꾸기] [덱에서 제거] │
└────────────────────────────────────────────────┘
[ ⚙ 선수 세부 조정            밸런스 · 지시 없음 ▾ ]   ← 역할 4택 + 세부 지시 칩 6개
[ ⚡ 선수 강화                 ★4/6 · OVR 76 ▸ ]      ← ★ 이 에픽이 더하는 유일한 것
```

전술보드·프롬프트·세부 조정은 **현행(#244) 그대로**. 강화 줄을 누르면 **선수 탭과 같은
`CardGrowthDetail`** 이 열려 hero 가 말한 "싱크"를 문서가 아니라 **컴포넌트 동일성**으로 보장한다.
경기 중에는 이 줄만 비활성(§3.1b).

### 3.5 선수 — 전신 카드 (hero 2R)

[보유 N] / [전체 N] 세그먼트 + 포지션·등급 필터 + 그리드. 보유 카드 탭 → 강화 시트, 미보유 탭 →
**획득 방법 시트**. 경기 중에는 강화 잠금(§3.1b).

**아이콘(얼굴 타일)이 아니라 전신 축소**로 간다 — hero: *"아이콘만 하면 모으는 재미가 떨어질 것 같아."*
미보유는 **전신 실루엣**(검은 실루엣 + `？？？`)이라 "안 가진 것"으로 즉시 읽힌다.

⚠️ **아트 실태를 알고 결정해야 한다**(`data/players/player-chars.v2.json` + 발행 manifest 실측):

| 대상 | 인원 | 아트 |
|---|---|---|
| LEGEND·DIA | **39** | `characters` 축 완성 카드 14종(hue 변형) — 전신으로 바꾸면 **확실히 좋아진다** |
| GOLD·SILVER·BRONZE | **133** | 공용 `default-unit` **하나** — 전원 같은 그림. 전신으로 바꿔도 **나빠지지도 좋아지지도 않는다** |

→ "모으는 재미"의 나머지 절반은 **아트 발행**이다. web 스코프 밖이라 **data/design 에 별도 이슈**로 올린다.
화면은 지금 바꿔 두면 아트가 들어오는 순간 그대로 좋아진다.

⚠️ **이 결정은 기존 정책을 뒤집는다** — `apps/web/CLAUDE.md` "도감은 어느 상태에서도 풀아트가 아니다"
(근거: 잠긴 카드에 원색 전신을 띄우면 잠금 표현과 어긋난다 → **전신 실루엣이 그 근거를 해소한다**) +
계약 `e2e/p3-card-art.spec.ts`(밀집 UI 풀아트 0개). **문서와 계약을 같이 갱신**하는 것이 구현 웨이브에 포함된다.

⚠️ 합성 규칙: `characters` 축 `card-*.png` 는 **프레임이 구워진 완성 카드**라 프레임을 덧씌우지 않는다.
`default-unit` 은 프레임리스라 `frame-<GRADE>.png` 를 **깔고 그 위 아트 창에** 앉힌다 —
프레임 PNG 는 투명 테두리가 아니라 **내부가 불투명한 카드 배경**이라 위에 얹으면 캐릭터가 통째로 가려진다
(목업에서 실제로 그렇게 됐다).

(hero 지적: 튜토리얼에 트레이드 설명 누락). 뽑기 연출(#250)·재화 표기(#232) 규약 전부 유지.

### 3.7 내 정보
프로필(닉네임·디비전·로그인 수단) → **전적**(승률 도넛 · 최근 10경기 폼 · 모드별 전적표) →
**순위 2카드**(리그 / 원정) + 개인 기록 → **기록**(경기 로그 · 트레이드 로그) → 튜토리얼 다시 보기.

## 4. 복수 시스템

hero: *"침공 기록 5개까지 노출 → 누르면 그 상대에게 복수 1회. 이기면 큐에서 빠지고, 지면 2회까지."*

### 4.1 ⚠️ 복수는 일부러 닫아 둔 문을 다시 여는 기능이다

원정은 지금 **상대를 고를 수 없다**. 서버가 2명을 제시하고 그 안에서만 고른다. 이유가 마이그레이션
주석에 남아 있다(`V22__away_season.sql`):

> 클라가 고른 id 를 그대로 믿으면 **지목 원정**이 되고, 그건 부계정을 반복 지목해 레이팅을 무한
> 생성하는 경로다(독립검증 4R MAJ-4 가 막은 그것). 서버가 방금 무엇을 제시했는지 기억하고,
> **그 안에서만** 수락한다.

복수는 정의상 지목 원정이다. 그래서 계약을 이렇게 잠근다:

1. **서버가 "그가 실제로 나를 쳤다"는 원장 행(`away_reports`, `defender_id = 나`)을 가질 때만** 지목이 열린다.
2. 한 기록당 **최대 2회**.
3. 기록은 **최근 5건**만 산다.

→ 부계정으로 무한 지목하려면 **먼저 그 부계정이 나를 쳐야** 하고, 그래도 2판이 끝이다.
이건 밸런스가 아니라 **어뷰징 경로**라 구현 시 이 세 조건을 계약(테스트)으로 박제한다.

### 4.2 한 기록의 일생

```
[남이 나를 침공] → away_reports 행 생성(defender=나)
        │
        ├── 내가 방어 성공(WIN) ──▶ [방어함] 복수 불가 · 버튼 잠김        ← hero 확정 ④
        │
        ▼ 내가 졌거나 비겼다
  복수 가능 2회 ──승리──▶ 완료(소멸: 목록에서 사라진다)
        │      └── 복수 무승부 ──▶ 횟수 그대로(2회 유지)               ← hero 확정 ①
        │ 패배
        ▼
  복수 가능 1회 ──승리──▶ 완료(소멸)
        │      └── 복수 무승부 ──▶ 횟수 그대로(1회 유지)
        │ 패배
        ▼
  소진(회색·비활성) — 목록엔 남지만 못 누른다. 6번째 침공이 들어오면 밀려난다.

※ 어떤 경로든 오늘 남은 원정 횟수를 1회 소모한다(hero 확정 ②).
```

### 4.3 규칙표

| 규칙 | 안 |
|---|---|
| 큐 길이 | 최근 **5건**(슬라이딩). 6번째가 들어오면 가장 오래된 것이 밀려난다. |
| 시도 횟수 | 기록당 **최대 2회**. 1회차 승리면 2회차 없음. |
| 승리 | 기록이 `AVENGED` 로 닫히고 목록에서 사라진다. |
| 패배 | 시도 1 소모. 2회 소진 시 `EXHAUSTED`. |
| **무승부** | **hero 확정 — 횟수를 쓰지 않는다.** 승부가 안 났으니 다시 침공 가능. |
| **판수 소모** | **hero 확정 — 오늘 남은 원정 횟수를 같이 쓴다.** |
| **레이팅** | **hero 확정 — 보너스 없음**(일반 원정과 동일). |
| **방어 성공한 침공** | **hero 확정 — 복수 불가.** 목록엔 `[방어함]` 으로 남고 버튼은 잠긴다. |
| 시간 만료 | 두지 않는다 — 5건 슬라이딩이 자연 만료 역할. |

⚠️ **무승부 규칙의 부작용을 알고 채택한다**: 무승부가 횟수를 안 쓰면 **비기는 한 무한 재도전**이 열린다.
다만 판수 규칙이 일일 원정 횟수를 먹으므로 하루 총 판수는 그대로 묶인다 — 그게 안전장치다.

## 5. 서버 API 계약 초안 (server-java)

> 프리즈 대상 = `docs/plan-v3/api/openapi-v2.yaml`. **구현은 컨펌 후 웨이브**. 마이그레이션 번호는
> merge-ready 시 main 이 배정한다(현재 최신 `V28__league_division.sql`).

| 엔드포인트 | 화면 | 내용 |
|---|---|---|
| `GET /api/away/revenge` | 원정 | 복수 큐 ≤5 + 남은 시도 |
| `POST /api/away/revenge/{reportId}/matches` | 원정 | 지목 복수 경기 생성 |
| `GET /api/away/rankings` | 원정 | 원정 레이팅 랭킹보드 + 내 순위 |
| `GET /api/league/rankings` | 리그 | 디비전 통합 랭킹보드 + 내 순위 |
| `GET /api/me/record` | 내 정보 | 모드별 전적 + 최근 폼 |

```jsonc
// GET /api/away/revenge
{
  "entries": [{
    "reportId": "R1",
    "opponent": { "userId": "u9", "nickname": "FC 한밤중", "rating": 1210 },
    "attackedAt": "2026-07-29T03:12:00Z",
    "theirScore": 3, "myScore": 1,       // 그때 결과(수비자 관점)
    "defenceResult": "LOSS",              // WIN|DRAW|LOSS — 내가 막았나
    "ratingDelta": -10,
    "attemptsUsed": 0, "attemptsMax": 2,
    "state": "AVAILABLE"                  // AVAILABLE | EXHAUSTED | AVENGED

  "remainingToday": 4                     // 원정 일일 한도와 공유(Q3-②)
}

// POST /api/away/revenge/{reportId}/matches → 201 Match
//   403 REVENGE_NOT_OWNED   그 리포트의 defender 가 내가 아니다  ← 지목 어뷰징 차단의 핵심
//   409 MATCH_IN_PROGRESS   기존 규약 그대로(detail.matchId 로 이어가기)
//   410 REVENGE_AVENGED     이미 갚았다
//   429 REVENGE_EXHAUSTED   2회 소진

  "entries": [{ "rank": 1, "userId": "u3", "nickname": "철벽 유나이티드",
                "rating": 1620, "streak": 9, "isMe": false }],

                "division": 1, "divisionName": "다이아 리그",

// GET /api/me/record
{ "overall": { "played": 23, "wins": 12, "draws": 3, "losses": 8, "winRate": 0.52 },
  "byMode": { "practice": {...}, "league": {...}, "away": {...} },
  "recentForm": ["WIN","WIN","LOSS","WIN","DRAW","LOSS","WIN","WIN","LOSS","WIN"],
  "streak": { "current": 1, "best": 4, "awayBest": 4 } }
```

### 이미 있는 것 / 새로 필요한 것

- **있다**: `away_reports`(피침공 원장) · `user_ratings` · `rating_ledger` · `away_streaks` ·
  `away_seasons` · `away_season_results`(V21·V22). `GET /api/rankings`(승수 리더보드 + 개인기록)도 있다.
- **새로 필요**: 복수 **시도 횟수**뿐이다 — `away_reports` 에 `revenge_attempts`/`revenge_state` 를
  얹을지 별도 `away_revenges` 표로 뺄지는 server-java 세션의 구현 판단(여기서 못 박지 않는다).
- 모드별 전적은 `matches.mode` 집계로 가능 — 새 표 불필요.
