## 1. 워크스트림별 요구 + AC

### W1. 게임화면 개편 (web 중심 + engine/dev-viewer 수렴) — P4-D3/D4  ★별도 세션+사람 리뷰게이트
- R: 관전 화면을 **경기장면 고정 메인 + 정보 토글** 구조로 재설계. 지금은 경기장면이 스크롤 안에 있어 번잡 → QA 뷰어식 간결 구조 참고. **다른 게임의 관전/매치 화면 리서치** 후 안 제시.
  - 필수 구성: ① 경기장면 = 상단/중앙 고정(뷰포트 내, 스크롤 무관) ② **후반 사전입력창**(감독시간용, W2 연동) ③ 실시간 통계 on/off ④ 게임 로그 on/off.
  - **뷰어 SoT 수렴(D3)**: 게임화면 렌더 코어를 SoT로, `packages/engine/dev-viewer`(QA)는 그 부분집합을 소비(재발명 제거). 계약 = 렌더 입력(match-log/snapshot)·훅.
- **AC-W1-1**: 경기장면이 화면 고정(모바일 390px·데스크탑 모두 뷰포트 내, 가로 오버플로 0). 통계/로그/사전입력 각각 독립 토글, 기본은 경기장면만.
- **AC-W1-2**: QA 뷰어가 게임화면 렌더 코어의 부분집합을 import해 동작(중복 렌더 구현 0). 기존 E2E 계약(`e2e/*.spec.ts`) 무회귀.
- **AC-W1-3**: 다른 게임 관전 UX 리서치 문서(`docs/plan-v5/research-spectator-ux.md`) + 레이아웃 안 → **사람 리뷰 게이트 PASS** 후 구현.
- 게이트: module-implementer → module-verifier → **hero 리뷰(시각) PASS** → 머지.

### W2. 경기 순서 — 감독시간 단계 분리 (server-java + servants + web) — P4-D2
- R: 현재 "게임장면 나오면 바로 후반 시작 가능" → **전반 → 감독시간(60초 한정) → 후반** 3단계로 분리. 감독시간 = 전반 리뷰 + 프롬프트 재입력(프리셋 활용) 창. 경기 준비 장면은 덱 구성 UI 재사용 가능.
- **AC-W2-1**: 전반 종료 시 후반이 자동 시작되지 않음. 감독시간 상태(HALFTIME) 진입 → 60초 카운트다운. 만료 or 유저 제출 시 후반 시뮬 트리거.
- **AC-W2-2**: 감독시간에 프롬프트 재입력(선수별/팀) + 프리셋 로드 → 후반 `TacticalInput`에 반영(라이브 AI 재호출, §7 하프타임 개입 지점). 미제출 만료 = 전반 프롬프트 자동 승계.
- **AC-W2-3**: 상태 전이(FIRST_HALF→HALFTIME→SECOND_HALF→FINISHED) 서버 권위·멱등·재현. 결정론 불변(엔진 resume=통짜 동일성 유지).

### W3. 서버 권위 시계 — 클라 독립 진행 (server-java + servants + web) — P4-D1
- R: 현재 매치가 **클라 재생에 묶여** 화면 안 보면 진행 안 됨 → **서버 시계 기준**으로. 킥오프 시각 기록, 재생 위치 = f(now−kickoff), 압축비 config(전반 90분→~4분).
- **AC-W3-1**: 킥오프 후 접속 지연 시, 뷰어가 (경과 실시간 × 압축비)에 해당하는 매치 틱부터 재생(앞서가기 금지, 뒤는 자유 스크럽). 두 클라가 같은 시각 열면 같은 지점.
- **AC-W3-2**: 압축비·전반 실시간 길이·감독시간(60s)·seek 정책 전부 config(하드코딩 0). 전반 종료 시각 = kickoff + halfRealMs → 이후 HALFTIME(W2).
- **AC-W3-3**: 서버가 매치 시각의 SoT(=매치 상태에 kickoffAt·phase·phaseStartAt 저장). 결정론 시뮬 결과(match-log)는 불변, 시계는 재생 게이트일 뿐.
- **비고**: W2와 깊게 결합(감독시간 = 시계상 전반 종료 후 60초). W2+W3는 한 에픽에서 조율 구현.

### W4. 배포 버전기록 정책 (infra + docs + CLAUDE) — P4-D5  ★epic-flow
- R: 배포마다 **어느 커밋·어느 모듈 버전**이 나갔는지 `docs/deploy-log.md`(append-only, git 추적)에 남긴다. AI가 나중에 "언제 뭐 배포됐나" 조회 가능. version-manifest.sh(#164) 산출을 이 로그에 자동 append. 정책을 CLAUDE.md에 규칙으로 박제.
- **AC-W4-1**: 배포 실행(`infra/deploy-pages.sh` 등) 시 `docs/deploy-log.md`에 항목 append: 배포시각·git SHA/브랜치·모듈별 버전(engine/server-java/web/servants)·이미지 다이제스트·tunnel/URL·배포자·결과(GO/이슈). 커밋됨.
- **AC-W4-2**: 과거 배포 조회 재현 가능(항목 축적, 시간순). 현 배포(hmb-online.pages.dev, 8adfaab 계열)를 **백필**로 첫 항목 기입.
- **AC-W4-3**: 정책이 CLAUDE.md에 명시(§ 배포 규칙) + `.claude/` 또는 문서에 "배포기록 질문 시 deploy-log.md 참조" 가이드. #164(버전 매니페스트)를 이 정책으로 승계·종결.
